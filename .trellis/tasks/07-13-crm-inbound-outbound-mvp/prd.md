# CRM 入库与出货 MVP

## Goal

建立一个可追溯的 CRM MVP，使业务人员能够登记来料入库和成品出货，并查询每种物料的当前可用库存。

## Confirmed Facts

- 当前仓库只有模板级 `Item` CRUD；未发现已实现的 CRM、来料、库存、客户或出货业务模块。
- CRM 必须使用完全独立的新领域模型、API 和前端模块；不得复用、扩展、映射或迁移现有 `Item` 示例实体。现有项目仅可提供技术组织模式参考。
- 前端已安装并全局配置 Ant Design 6；项目策略允许在 `features/*` 等复杂业务界面使用 Ant Design，同时要求共享组件层保持领域无关。
- MVP 将来料库存和成品库存建模为两套独立台账；不自动将来料转换为成品。
- 所有库存余额字段由已确认的台账记录自动计算并只读展示；用户只录入本次业务数量，不能直接编辑余额。
- 首版不提供日常库存调整页面，但库存变动模型预留“变动类型”和“原因”扩展点。
- MVP 面向单人使用，不引入草稿、确认、撤销或审批状态机；入库/出库单据保存即生效并更新对应库存。
- 历史入库/出库单据允许编辑和软删除；库存余额由对应台账中所有未软删除记录全量重算，任何变更不得使余额为负。
- MVP 纳入“坯布退走”：它是从指定加工单位退走的正式坯布出库变动，保存即扣减该加工单位的来料库存；不属于库存调整单，也不把“某加工单位退走”建立为独立加工单位。
- 实际业务链路为“坯布入库 → 投产 → 工艺卡 → 成品入库 → 成品出货”。一匹坯布对应一张工艺卡；工艺卡用于记录客户要求的工艺、目标颜色并跟踪至成品产出。
- 首版只预留工艺卡和成品入库与台账的衔接点，不实现工艺卡生产流程、坯布投产扣减或坯布到成品的自动转换；成品入库也暂不提供日常单据页面。
- 首版不提供工艺卡创建或查询页面；仅保留其未来与坯布匹数、客户、工艺要求、目标颜色和成品入库的关联边界。
- 已只读分析 `hongxia/2026年坯布入库明细.xlsx`（20 个工作表、776 条含品名或品号的数据行）和 `hongxia/2026年成品进出明细.xlsx`（41 个工作表、3,177 条含品名或颜色的数据行）。两份工作簿均按加工单位拆表，且库存列没有 Excel 公式；当前余额是静态填写值，不能作为新系统的计算来源。
- 来料库存项目使用“加工单位 + 品名 + 品号 + 含毛量”识别。同一加工单位、相同含毛量下，源数据中既存在相同品号对应不同品名（20 组），也存在相同品名对应不同品号（48 组），因此品名与品号都不能从识别维度中省略；日期、单号、备注不是库存项目维度。
- 成品库存项目使用“加工单位 + 品名 + 含毛量 + 颜色/色号 + 缸号”识别。源数据中有 90 组记录在前四项相同而缸号不同，故缸号不能省略；收货单位、出库单号、日期、备注不是库存项目维度。缸号为空时，系统须以显式的“未分缸”值作为该维度的归并值，不能以空值隐式混淆库存项。
- 源历史数据存在缺项：来料有 53 条缺品号、56 条缺含毛量（其中三泰页没有含毛量列）；成品有 337 条缺含毛量、2,165 条缺缸号。首次受控导入时需确定这些记录的迁移策略；新建业务记录应完整填写其库存识别维度。
- 坯布工作簿另有 8 条负数“入库”记录；其加工单位填写为“天双退走”“禧云庄退走”“缪秀忠退走”，而工作表仍归属于原加工单位。这说明“退走”是坯布从加工单位退回的库存变动方向，不是新的加工单位；新系统不能把“天双退走”等字符串建立为独立加工单位。
- 首次上线时，根据两份历史 Excel 执行一次受控导入，逐条保留其中的历史入库、退走、成品入库和成品出库明细，以建立可出货的初始库存；每条导入记录须保留来源工作簿、工作表和行号以便追溯。不提供用户可重复操作的 Excel 导入功能，也不提供单独的期初库存录入页面。后续重复导入、历史重导和数据清洗均不属于首版日常功能。
- 原工作簿的“库存 / 库存匹数 / 库存米数”均为静态填写值、没有公式。新系统以导入后的历史变动重新计算余额；这些原始库存值仅作为导入对账快照保存，不能覆盖或直接编辑系统计算的余额。
- 为完整迁移历史明细，缺品号、含毛量或缸号的源行分别使用“未填写品号”“未填写含毛量”“未分缸”等明确遗留占位值导入，并标记“历史待清洗”；新建单据不得使用这些占位值，必须完整填写库存识别维度。
- 成品源数据中，同一出库单号可包含多条不同品名、颜色和缸号的明细（例如新力的 `0005117`）。因此来料入库、坯布退走和成品出货均应采用“单据头 + 多条明细”形式；库存变动按明细行计算，编辑或软删除单据时影响其全部明细行。
- 成品源数据中，1,711 条出库明细同时有匹数和米数，仅 2 条只有匹数、没有只有米数的记录；另有 399 条历史行同时包含入库和出库数量。首次导入必须保留同一来源行的定位和关联，即使它被转换为多条库存变动记录。
- 按“结存行作为期初 + 历史变动逐条重算”复核源数据后，坯布出现 3 次负库存、成品出现 427 次负库存。这表明源工作簿不是完整可回放流水，且其库存列为手工快照；若既要逐条保留历史又要保持非负库存，首次导入需要受控的迁移对账期初记录。
- 首次导入允许在每个首次会导致负库存的库存项前插入系统生成的“迁移对账期初”记录，使余额补至零；该记录必须带有明确来源和原因，不可作为日常调整、不可由业务页面编辑或删除。
- 新建成品出货明细必须同时填写出库匹数和出库米数：匹数为正整数，米数为可含小数的正数。两者共同扣减成品库存；首次导入仅保留源表中两条只有匹数的异常记录并标记“历史待清洗”。
- 新建来料入库、坯布退走和成品出货单据的单号均由用户手工填写，且在各自单据类型内唯一；首次导入保留原有空单号或重复单号，并标记为历史数据。
- 首版只维护“加工单位”和“收货单位”两类主数据，并在单据中选择；品名、品号、含毛量、颜色/色号、缸号不建立独立主数据页面，直接在明细中录入，并从已导入和已保存的明细值提供联想选择。
- 首版页面范围固定为四组：加工单位管理与收货单位管理；坯布台账（来料入库、坯布退走两个页签，均含单据列表、筛选、新建、编辑、软删除）；成品出货（单据列表、筛选、新建、编辑、软删除）；来料库存与成品库存（余额汇总、筛选、关联明细）。不提供首页仪表盘、工艺卡、成品入库、导入页面或跨台账报表。
- 来料入库与坯布退走均以“匹”为数量单位；用户录入的每条数量必须为正整数，来料库存余额按整匹自动计算。
- 本任务处于规划阶段；未经后续设计审阅和用户批准不得开始实现。

## Requirements

- R1：支持记录来料入库，字段为：日期、加工单位、单号、品名、品号、含毛量、入库、库存、备注。
- R1.1：支持记录坯布退走，使用与来料入库相同的库存识别字段和业务日期、单号、备注；加工单位填写实际加工单位，数量以正数录入，并作为来料库存的出库扣减。变动类型固定为“退走”。
- R2：支持记录成品出货，字段为：日期、加工单位、收货单位、出库单号、品名、含毛量、颜色+色号、缸号、入库匹数、入库米数、出库匹数、出库米数、库存匹数、库存米数、备注。
- R3：来料入库操作后更新来料库存；成品出货操作后更新成品库存。两套库存均必须可追溯且不能出现负库存。
- R3.1：来料库存、成品库存匹数和成品库存米数均由系统自动计算并只读展示；新建成品出货明细只录入本次出库匹数和出库米数，入库与出库历史汇总由系统展示，不允许直接编辑余额。
- R3.2：软删除的历史单据不参与库存计算，但必须保留以便恢复和追溯。
- R3.3：来料入库、坯布退走和成品出货均支持一个单据头下录入多条明细；单号在各自单据类型内用于标识单据，库存按明细行变动。
- R4：提供加工单位、收货单位两类主数据及其管理界面/接口；单据中必须从有效的加工单位或收货单位中选择。
- R4.1：来料库存按“加工单位 + 品名 + 品号 + 含毛量”汇总；成品库存按“加工单位 + 品名 + 含毛量 + 颜色/色号 + 缸号（或未分缸）”分别汇总。单号、出库单号和收货单位仅作为单据追溯字段，不参与库存余额归并。
- R4.2：为后续工艺卡及成品入库保留可关联的扩展边界：工艺卡将关联一匹坯布、客户、工艺要求和目标颜色；未来成品入库将可关联工艺卡。首版不得据此自动转换两套库存或开放成品入库页面。
- R4.3：物料规格字段采用明细直接录入加已有值联想，不创建独立物料、颜色或缸号主数据管理页面。
- R4.4：实现已确认的四组页面范围；单据列表同时承担历史查询入口，库存汇总可查看关联明细。
- R4.5：来料入库和坯布退走明细的数量单位固定为匹，且只接受正整数；保存、编辑、恢复或删除后的来料余额按匹自动重算。
- R4.6：新建成品出货明细必须同时填写正整数的出库匹数和正数的出库米数；保存、编辑、恢复或删除后，成品库存匹数和米数分别自动重算。历史导入的仅匹数异常行必须显式标记“历史待清洗”。
- R4.7：新建来料入库、坯布退走和成品出货单据的单号必须手工填写，并在对应单据类型内唯一；历史导入例外可保留空单号或重复单号，且必须标记为历史数据。
- R5：首次部署提供一次受控的 Excel 数据导入流程，逐条使用用户提供的坯布与成品工作簿建立历史台账和初始可用库存；每条导入记录保留工作簿、工作表、行号和原库存快照。该流程不是运行时页面或通用导入功能，系统余额必须由导入后的变动重算，并在导入后按库存识别维度与确认后的 Excel 口径核对。
- R5.1：首次导入遇到首次会导致负库存的库存项时，必须在该历史变动前创建不可由业务页面修改的“迁移对账期初”记录，仅补足至零；该记录保留来源、原因和关联库存识别维度，不得作为日常库存调整使用。

## Acceptance Criteria

- [ ] 用户可创建并查询来料入库记录。
- [ ] 用户可创建、编辑、软删除并查询坯布退走记录；保存或恢复时只影响对应加工单位的来料库存，且库存不足时被拒绝。
- [ ] 用户可创建并查询成品出货记录。
- [ ] 每笔保存的入库/出货都能反映在对应库存余额中；任一台账库存不足时，对应操作被拒绝。
- [ ] 同一库存识别维度的多张单据被汇总为一个余额；任一库存识别维度不同的记录不得被错误合并。
- [ ] 首次受控导入完整保留两份 Excel 的每条业务明细及其来源定位；来料和成品的各库存识别维度余额均可与确认后的 Excel 导入口径核对一致。
- [ ] 历史缺项记录以明确遗留占位值和“历史待清洗”标记导入；新建单据不能保存缺少库存识别字段的明细。
- [ ] 用户可在一张来料入库、坯布退走或成品出货单中维护多条明细，单据编辑或软删除后所有相关库存余额均正确重算。
- [ ] 用户可维护加工单位和收货单位；单据明细可录入物料规格并获得已有值联想，不出现独立物料规格主数据页面。
- [ ] 页面范围限于已确认的四组；不存在首页仪表盘、工艺卡、成品入库、导入页面或跨台账报表入口。
- [ ] 来料入库与坯布退走拒绝零、负数和非整数的录入数量，并按匹正确计算库存余额。
- [ ] 成品出货拒绝缺少匹数或米数、非整数匹数、零或负数米数的明细；匹数和米数库存均正确扣减。
- [ ] 新建单据拒绝空单号及同类型重复单号；历史导入的空单号或重复单号可保留且带有历史数据标记。
- [ ] 首次导入在不丢失任何 Excel 业务明细的前提下，不产生负库存；所有迁移对账期初记录均可追溯且不出现在日常编辑、删除操作中。
- [ ] PRD、技术设计和实施计划经用户审阅后方可进入实现阶段。

## Likely Out Of Scope

- 用户可重复操作的 Excel 导入、期初库存录入页面、工艺卡生产流程、坯布投产扣减、来料加工为成品的转换/损耗、成品入库单据页面、采购、销售订单、财务对账、批次质检、复杂仓位/库区、多仓调拨和条码/PDA 流程，除非后续明确纳入 MVP。

## Follow-up Backlog

- 库存调整单：支持盘盈、盘亏、报损、历史录入纠正和期初建账；通过独立台账变动而非直接编辑库存余额来调整库存。
