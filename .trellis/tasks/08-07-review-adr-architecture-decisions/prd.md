# 审查并修复 ADR 架构决策文档

## Goal

对 `docs/adr/` 中所有现行 ADR 做软件工程审查，并根据审查结论修复文档漂移、决策可追溯性和 AI 退役迁移的回归验证缺口。

## Background

- 当前目录包含 ADR-0001 至 ADR-0012。
- 该仓库已启用 CodeGraph；涉及实现一致性的判断必须以当前代码、测试、配置和相邻规范为证据，而非仅凭 ADR 文本。
- 审查阶段已完成；用户随后授权根据 Findings 更新 ADR 并修复验证缺口。
- 当前日志规范和实现已经采用受限的 Celery 失败异常记录；本任务将把该后续决策显式记录为替代 ADR，不改变日志运行行为。

## Requirements

1. 逐篇检查 ADR 的问题陈述、决定、后果、状态和替代方案是否满足可追溯、可执行的架构决策记录要求。
2. 核对每项仍有效的决策与当前仓库实现、运行配置和相关规范之间是否一致。
3. 识别事实错误、过期陈述、决策边界不清、重复/冲突决策、缺失状态演进或缺失关键约束。
4. 输出按严重度排序、带文件与行号证据的审查结论，并为每篇 ADR 给出保留、修订、取代或废弃的建议。
5. 修订 ADR-0001、ADR-0004 至 ADR-0009、ADR-0011 和 ADR-0012，使状态、现行边界、相关决策和历史范围与实现一致。
6. 保留 ADR-0010 的任务上下文与清理规则，仅将异常详情禁止项交由新增 ADR-0013 替代，并记录当前受限的任务失败异常日志决策及其安全边界。
7. 为 ADR-0008 的退役补充数据处置治理前提，并添加隔离数据库的 `predecessor -> head -> predecessor -> head` Alembic 迁移测试。
8. 为 ADR 目录提供一个按状态和替代关系导航的索引。

## Acceptance Criteria

- [x] 覆盖 `docs/adr/` 下的全部 12 篇 ADR。
- [x] 每个结论均说明依据，并在需要时引用当前实现或规范的文件与行号。
- [x] 发现项按严重度排列，明确区分事实错误、设计风险与文档改进建议。
- [x] 审查结论按严重度排序，明确区分事实漂移、设计风险和文档改进，并保留实现/规范证据。
- [x] 所有仍适用的 ADR 都有统一的状态和可追溯的相关决策链接。
- [x] ADR-0005、ADR-0010 和 ADR-0012 不再把已淘汰的实现描述为当前事实。
- [x] ADR-0008 包含未来不可逆数据处置的治理前提，且 AI 迁移往返链在临时隔离测试数据库上得到覆盖。
- [x] 新增 ADR 明确限定 Celery 失败异常记录的来源、允许内容、禁止内容和运维边界。

## Out of Scope

- 修改 FastAPI、前端 API、Celery 任务逻辑、日志渲染逻辑或 Redis 配置。
- 生成前端客户端或变更公开 API。
- 对生产运行环境或生产数据库做验证或变更。
- 对生产运行环境做验证或变更。

## Open Questions

无。用户已要求从软件工程角度评估完整 ADR 目录；采用仓库现有代码和规范作为一致性基线。
