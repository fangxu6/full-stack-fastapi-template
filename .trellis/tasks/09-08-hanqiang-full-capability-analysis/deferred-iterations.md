# Hanqiang 能力 Deferred Iterations

## 当前边界

本任务只生成全量证据、能力矩阵和生产级设计文档，不实现运行时能力。未来任何候选能力都必须建立独立 Trellis 任务后再开发。

## Deferred Items

| ID | 范围 | 暂缓原因 | 前置条件 |
| --- | --- | --- | --- |
| D-001 | 事件回调运行时与最小 Webhook | 需要真实领域事件和消费者 | 稳定事件内核、SSRF 策略、幂等/审计方案 |
| D-002 | 外部集成中心 | 需要固定外部契约和 D-001 的事件/投递基础 | 入站/出站契约、密钥治理、版本与重试 |
| D-003 | 通用审批流 | 需要真实多级/可配置审批业务 | D-001 事件出口、首个业务适配器、并发状态矩阵 |
| D-004 | WeCom 通知 Adapter | 需要明确组织渠道和收件人策略 | 密钥轮换、Token 生命周期、通知 Outbox |
| D-005 | 服务通信管理 | 需要第二个独立服务 | 端点身份、调用链、跨服务审计 |
| D-006 | 文件监控与远程抓取 | 需要明确文件来源和长期处理需求 | 路径/SSRF/ReDoS 防护、对象存储策略、资源授权 |

## 规则

- Deferred 项不计入当前任务的实现验收，也不通过占位控件或宽松 fallback 暴露。
- 每个 Deferred 项必须新建自己的 PRD、design、implement 和适用的 E2E 计划。
- 依赖顺序是 D-001 → D-002，D-001 → D-003；D-004、D-005、D-006 只有其自身事实需求出现时启动。
