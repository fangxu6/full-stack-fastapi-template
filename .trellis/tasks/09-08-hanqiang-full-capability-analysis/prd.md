# Hanqiang 全量提交能力分析与 prod 文档扩充

## Goal

逐个复核 `docs/hanqiang-core-contributions/` 下的全部提交级文档，识别当前模板值得引入、复用、暂缓或明确不引入的平台能力，并把可落地能力沉淀为后续开发可直接使用的生产级（prod）文档。

用户价值：后续实施某项能力时，开发者能够从一份文档获得范围、边界、接口/数据契约、安全要求、可观测性、迁移、验证、发布和回滚要求，不必重新通读全部历史提交。

## Confirmed Facts

- 目录当前有 105 个 Markdown 文件：98 个提交级文件（后端 59、前端 39）和 7 个汇总/复用指南。
- 总索引当前声明 94 条提交，但存在未被索引的提交级文件；本任务必须以文件清单为事实源并修正索引覆盖数。
- 当前模板已有 IAM、审计、EmailOutbox、Celery、Scheduler、导入/库存调整等基础能力；历史项目的业务字段、目录和任意 Python 调用能力不能直接复制。
- 本任务只产出分析和文档，不实现审批、Webhook、外部集成或其它运行时代码。

## Requirements

### R1. 全量逐文件证据

对每个提交级 Markdown 文件记录：文件名、提交/SHA（若文档提供）、原始主题、能力归属、可复用结论、风险/缺口、引入决策（引入/复用现有/暂缓/不引入）和对应 prod 文档。无法从文档确认的内容必须标为待核实，不得补猜。

### R2. 能力归类与模板差距

按后端、前端和跨层边界归并重复提交，区分“平台能力”和“单一业务实现”。对每类能力对照当前模板事实，说明已有能力如何复用、缺什么、为什么现在引入或暂缓，以及依赖顺序。

### R3. 生产级 prod 文档

对确认值得保留的能力，逐能力生成独立 Markdown 文档，统一包含：目标与非目标、适用条件、边界/所有权、数据与状态契约、API/事件契约（适用时）、权限与多租户、安全威胁、幂等/并发/失败恢复、审计与可观测性、配置与密钥、迁移、测试验收、发布/回滚、运维检查和明确的后续拆分。

对暂缓能力也要保留轻量 prod 入口，写明启动门槛、依赖和禁止提前建设的范围，避免未来重复分析。

### R4. 总报告与索引同步

更新 `docs/hanqiang-platform-capability-assessment.md`，加入全量覆盖情况、新增能力、分期路线和 prod 文档导航；更新 `docs/hanqiang-core-contributions.md` 的文件统计、遗漏链接和能力导航。

### R5. 文档质量与可追溯性

所有新增结论必须能回链到提交级文档；相同能力的多个提交要保留来源清单。Markdown 相对链接可解析，文档不复制业务敏感值，不把历史实现缺陷误写成生产建议。

## Out of Scope

- 不修改 `backend/`、`frontend/` 或运行时配置，不新增数据库迁移、依赖、API 和前端页面。
- 不把 98 个提交逐一复制成第二套重复指南；提交级文档仍作为证据源，prod 文档只承载归并后的可执行要求。
- 不在没有真实消费者、外部契约或组织渠道时实现 WeCom、服务通信、文件监控和完整集成编排。

## Open Questions

- 无阻塞问题。prod 文档数量由全量分析后的能力边界决定；同一能力只保留一份主 prod 文档，必要时用附录或专题文档承载差异。
