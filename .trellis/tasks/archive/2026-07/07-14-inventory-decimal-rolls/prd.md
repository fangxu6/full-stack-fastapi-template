# 匹数小数精度修正

## Goal

将库存领域的匹数从正整数改为正数、最多两位小数，完整保留并正确计算实际存在的 `0.5` 匹业务记录，恢复成品出货页面的可用性。

## Confirmed Facts

- 当前 `quantity_rolls` 与 `rolls_delta` 均为整数；写入 DTO 也只接受整数。
- 成品出货列表序列化历史 `quantity_rolls=0` 记录时，因读取 DTO 继承写入 DTO 的 `gt=0` 约束而返回 500。
- 当前历史导入批次没有任何日常新单据。三泰工作表第 532、538 行的出库匹数均为 `0.5`，导入器的 `int(rolls)` 将其截断为 `0`。
- 两条记录均有同源迁移对账期初，当前最终库存余额为零。

## Requirements

- 所有匹数类日常业务统一接受大于零、最多两位小数的数值；超过两位小数必须被拒绝，不自动舍入。
- 来料入库、坯布退走、成品出货、单据明细、库存台账和余额聚合全部使用 `Decimal(18,2)`。
- 历史读取 DTO 必须允许零匹数，以兼容受控导入的历史例外；写入 DTO 继续拒绝零和负数。
- 受控导入必须保留原始两位小数匹数，禁止整数截断。
- 使用定向数据迁移修正当前批次中所有可从来源 JSON 识别的小数匹数历史行；同步修正其单据明细、台账变动和同源迁移对账期初，且不得造成负库存。
- 重新生成 OpenAPI 客户端。前端匹数输入支持 0.01 步长和两位精度，列表、余额及台账正确显示小数匹数。

## Acceptance Criteria

- [ ] 以 `0.50` 匹创建、更新、删除和恢复来料入库、坯布退走及成品出货时，余额与库存不足校验均准确。
- [ ] `0`、负数和超过两位小数的匹数请求返回 422；米数规则保持不变。
- [ ] 当前历史数据库中单号 `0005290`、`0005348` 的匹数及对应台账变动为 `0.50`，匹数与米数余额均不为负。
- [ ] `/api/v1/inventory/documents?document_type=FINISHED_SHIPMENT&include_deleted=true` 返回 200，`/inventory/shipments` 可加载历史列表。
- [ ] 导入器回归测试证明 `0.50` 匹不被截断，并正确建立必要的迁移对账期初。
- [ ] 后端测试、lint/type check、客户端生成、前端 lint/build 通过。

## Constraints

- 不删除或重导当前历史批次，不修改 `hongxia` 工作簿。
- 降级不得静默截断小数匹数；存在非整匹数据时必须明确失败，回滚依赖迁移前数据库备份。
- 历史缺项的 `requires_cleanup` 语义保持不变；小数匹数本身不是待清洗原因。
