# Design: Remove Confirmed Unused Repository Artifacts

## Boundaries

This is a deletion and dependency-cleanup task with no API or runtime behavior
change. Work is limited to artifacts already proven to have no current consumer.

### Root artifacts

- Delete the five dated architecture review HTML snapshots.
- Delete the tracked root `openapi.json` snapshot. Keep
  `frontend/openapi.json` ignored and generated by `scripts/generate-client.sh`.

### Backend

- Delete the empty `backend/app/core/logging.py` shim. Runtime logging remains
  owned by `backend/app/core/observability.py`.
- Keep `backend/app/backend_pre_start.py` as the single readiness implementation.
- Change `backend/scripts/tests-start.sh` to invoke that implementation and
  delete the duplicate module and duplicate test.

### Frontend

- Remove only the five direct dependencies with no non-lockfile reference.
- Regenerate the workspace lockfile with the existing Bun toolchain.
- Do not touch the generated client or the retained vendor-style UI primitives.

## Compatibility

- No HTTP/API, schema, database, cache, PM2, or application logging behavior
  changes.
- The test startup shell script continues to wait for PostgreSQL using the same
  implementation as the normal backend prestart path.
- Existing archived Trellis documents may mention the removed root OpenAPI
  snapshot as historical context; they are not active runtime consumers.

## Rollback

The changes are recoverable through the Git diff. Restore deleted tracked files
and revert the package/lockfile change if any focused validation exposes an
external consumer.
