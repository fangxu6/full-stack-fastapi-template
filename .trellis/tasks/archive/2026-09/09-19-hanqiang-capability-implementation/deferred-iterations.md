# Hanqiang 事件能力 Deferred Iterations

## Purpose

本任务先交付不依赖具体业务的事件回调内核。具体业务事件、出站 Webhook 和其它执行器必须在真实消费者与外部契约明确后单独立项。

## Traceability Rules

- 延期项目不计入当前内核的验收标准。
- 每个延期项目必须新建独立 Trellis 任务，并提供自己的 PRD、design、implement 和适用的 E2E 计划。
- 不通过占位 API、动态配置 UI、宽松 fallback 或假业务数据提前暴露延期流程。
- 原历史评估的“真实消费者才启动”对本任务已由用户确认的内核先行范围调整；对本清单的适配器仍然适用。

## Deferred Items

| ID | Deferred Scope | Reason | Dependencies | Future Deliverables |
|---|---|---|---|---|
| D-001 | 具体业务事件适配器 | 当前没有确认的领域事件和业务所有者 | 事件信封与发布协议稳定 | 业务事件契约、快照、权限、幂等、数据保留/容量、执行超时和集成验收 |
| D-002 | 最小出站 Webhook | 需要真实外部消费者、URL/Secret 策略和接收方幂等契约 | D-001、事件投递内核 | Webhook Adapter、SSRF 防护、签名、重试、投递查询和人工重放 |
| D-003 | 动态回调配置与管理 UI | 没有多个消费者和稳定字段目录时会形成猜测性平台 | D-001、至少两个真实消费者 | 版本化订阅、白名单条件、权限菜单、生成 client 和 UI 验收 |
| D-004 | 内部/级联执行器 | 需要明确跨模块副作用和循环控制需求 | D-001、事件执行协议 | 白名单执行器、级联深度/堆栈限制和跨模块审计 |

## Suggested Iteration Order

D-001 -> D-002；D-001 -> D-003；D-001 -> D-004。D-002、D-003、D-004 之间没有强制依赖。

## Carry-Forward Acceptance Notes

- D-001 在启用首个真实消费者前确认 payload 的数据分类、脱敏、保留周期、容量与清理策略；不能无限沿用本期“无自动清理”作为生产容量承诺。
- 消费者必须定义副作用幂等和执行超时。lease/token 只能限制内核结果提交，不能取消旧进程或保证业务只执行一次。
- 本期无顺序保证、历史补投或人工重放。新增 handler 不消费历史，重复 publish 也不补投；若未来需要，应明确授权、版本、唯一性和审计语义。
- 本期 FAILED 是保留的终态，不可直接改为 PENDING；D-002 的重放须保存原有事实与审计。其它适配器若先需要运维恢复，先独立立项该能力，不要求为了重放必须引入 Webhook。
- 现有 AuditEvent 会清理严格超过 365 天的记录；未来若要更长的投递尝试历史，另行定义，不把 AuditEvent 当永久历史表。
- 未来滚动部署须先部署支持新事件版本/handler 的 Worker，再启用业务发布；handler 缺失或不兼容在当前内核是明确终态。
- 停用适配器/应用回滚保留事件、投递与审计；数据迁移/清除是单独动作，不隐含在代码回滚中。

## Remaining Work In Current Scope

事件信封、事务内登记、投递状态、处理协议、派发/执行双租约、幂等、有限重试/恢复、审计与隔离测试假处理器仍属于当前任务。并发、Broker/Worker 故障、异常脱敏和真实运行时验证不能因延期 Adapter 而省略。当前 AC 以 [prd.md](prd.md) 为准。
