Problem

The new correction page bypasses the existing app module, repeats the raw query key, and skips its 30-second UI freshness and error-classification contract.

Solution

Route the page through the existing permission access module and add one regression check that keeps future callers on that seam.

Wins

  • locality: one permission read policy
  • leverage: one query contract, all callers
  • tests hit the module interface

Deletion test: deleting the page-local query concentrates the behavior in the existing app module; no new abstraction is required.

Problem

The service carries master units, document commands, ledger effects, balance reads, exports, and suggestions; importer and correction flows cross that broad implementation.

Solution

Concentrate document/ledger mutation and its negative-balance invariant in one deep module, while leaving master-unit and read/export concerns local to their callers.

Wins

  • locality: ledger bugs stay together
  • leverage: import and correction share invariants
  • tests target one mutation surface

ADR fit: this follows ADR-0002 and ADR-0006 only if the request-scoped transaction owner remains unchanged. The scope must not become a full inventory rewrite.

Problem

Definition validation, job CRUD, run creation, lease dispatch, execution, alert persistence, cleanup, and bootstrap span two broad files and cross a durable state seam.

Solution

Group definition/configuration, run lifecycle, and runtime dispatch behind narrower module entry points while keeping PostgreSQL authoritative and Celery transport-only.

Wins

  • locality: state transitions have one home
  • leverage: runtime tests cover one lifecycle
  • seam: broker failure stays at the adapter

ADR fit: preserve the scheduler runtime contract from ADR-0005 and the durable lease rules. This candidate is riskier because moving the seam can alter at-least-once behavior.

Top recommendation

Candidate 1: permission access module

It has the clearest current friction, the smallest credible scope, and the strongest leverage: one new caller is already bypassing a module that the prior review deliberately made deep.
