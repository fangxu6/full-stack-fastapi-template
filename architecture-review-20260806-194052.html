Candidate 01

Concentrate inventory document/ledger invariants

Strong in-process

Files

  • backend/app/modules/inventory/service.py:247-671, 674-975
  • backend/app/modules/inventory/importer.py:74-206, 505-805
  • backend/app/modules/inventory/correction_service.py:30, 541-555, 791-930
  • backend/app/modules/inventory/router.py:101-136, 322-381

Problem

The 975-line inventory implementation mixes master-unit writes, document mutation, ledger effects, balance reads, exports, and suggestions. Import and correction paths depend on its mutation details, so the interface is nearly as wide as the implementation and locality is weak.

Solution

Deepen one document/ledger module around line creation, ledger effects, delete/restore, correction application, and negative-balance checks. Keep master-unit and read/export modules separate only where their callers justify it. Preserve the existing request-scoped transaction owner.

Wins

  • locality: invariants co-locate
  • leverage: import and correction share one seam
  • tests hit one interface
  • implementation absorbs read noise
Deletion test: deleting the document/ledger module would force balance and ledger rules into importer, correction, and route callers. Consolidation concentrates complexity.
ADR fit: aligns with ADR-0002 and ADR-0006. No new transaction owner, schema, or external adapter is implied.

Candidate 02

Split workbook adapters from import orchestration

Worth exploring adapter

Files

  • backend/app/modules/inventory/importer.py:74-210
  • backend/app/modules/inventory/importer.py:375-487, 505-805
  • backend/app/modules/inventory/router.py:101-136
  • backend/tests/modules/inventory/test_importer.py:22-345

Problem

One implementation handles the modern document template, two legacy workbook formats, cell normalization, validation aggregation, idempotency fingerprints, import-batch persistence, audit attribution, and explicit commit/rollback. The interface changes shape between HTTP imports and the CLI-style import_workbooks() path.

Solution

Give the modern template and legacy workbook family separate adapters for reading and normalization. Keep one import orchestration module responsible for issue aggregation, batch identity, persistence, and the caller-owned transaction. Two adapters make the seam real; no new external dependency is needed.

Wins

  • locality: format rules stay local
  • leverage: new format reuses orchestration
  • parser tests avoid database setup
  • transaction policy stays explicit
Constraint: import_workbooks() is outside HTTP and may keep explicit commit/rollback. The deepening must not move that ownership into an adapter or into WriteSessionDep.

Candidate 03

Preserve NDJSON across the PM2 display adapter

Strong adapter

Files

  • scripts/pm2-json-prefix.cjs:23, 61-63
  • scripts/pm2-json-prefix.test.cjs:8
  • ecosystem.config.js
  • .trellis/spec/backend/logging-guidelines.md:135

Problem

The PM2 adapter is presentation-only by contract, but the implementation rewrites a child JSON line into a human-readable string and drops the original JSON suffix. Operators get a readable prefix while collectors lose the machine-readable interface required by the logging specification.

Solution

Make the adapter preserve the exact child NDJSON line and prepend only the approved display fields. Keep JSON parsing limited to deciding whether a prefix is safe; the original line remains the durable payload. Delete unused application logging code only after a usage check.

Wins

  • locality: presentation stays outside logging
  • leverage: backend and Celery share the contract
  • tests assert payload preservation
  • adapter seam is deterministic
Contract drift: the active logging guideline requires the original JSON after the display prefix. This candidate is a correctness repair with architectural leverage across collectors and operator diagnosis.
