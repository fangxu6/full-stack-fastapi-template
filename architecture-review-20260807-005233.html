Problem

Normal document writes use _add_lines_and_ledgers and _reject_negative_balances; legacy import constructs InventoryLedgerEntry and maintains a separate balance map.

Solution

Deepen an Inventory Ledger module that owns movement effects and balance validation; keep import-specific opening and reconciliation metadata beside the import workflow.

Wins

  • locality: balance rule in one module
  • leverage: imports and writes share it
  • tests hit one interface
  • deletion test: remove duplicate bookkeeping

Problem

correction_attempts reaches private request, work-item, timestamp, and audit helpers in correction_service. The module also mixes policy, projections, permissions, and persistence transitions.

Solution

Deepen the Correction workflow module around request and work-item state transitions. Make the scheduled executor an adapter that uses the module's owned transition surface.

Wins

  • locality: invariants near transitions
  • no private helper leakage
  • executor tests isolate orchestration
  • leverage: one policy, two entrypoints

Problem

tasks.py still owns multiple transaction snapshots, broker dispatch, actor binding, execution handoff, alert decisions, and cleanup around the already-deepened lifecycle module.

Solution

Deepen the scheduler orchestration module around the Celery-to-run flow while preserving lifecycle persistence in run_lifecycle and side-effect-free execution in execution.

ADR-0012 is compatible: this does not merge Beat and Worker or create a generic state-machine framework.

Wins

  • locality: Celery glue in one module
  • leverage: thinner task entrypoints
  • tests exercise one call graph
  • ADR-0012 remains intact

Problem

The 600-line page module owns five queries, three mutations, permission-driven tabs, table definitions, the document editor, and the detail drawer. Browser coverage checks routing, not the local workflow policy.

Solution

Deepen a feature-local correction workspace module for query keys, actions, tab policy, and view data; leave the page module as a UI adapter.

Wins

  • locality: workflow policy leaves JSX
  • leverage: one cache policy
  • tests hit one interface
  • AI navigation follows the domain

Top recommendation

Concentrate Inventory Ledger effects

It has the clearest leverage: two recently changed workflows construct the same Inventory Ledger effects with different bookkeeping, so one deep module can improve locality without reopening the repository's modular-monolith or scheduler decisions.
