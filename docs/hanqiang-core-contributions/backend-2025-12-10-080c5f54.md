## 原始变更范围

| 能力 | 提交行为 | 复用意义 |
| --- | --- | --- |
| 撤回 | 上传撤回删除远端文件；下载撤回删除本地文件。 | 删除目标取决于传输方向，不能统一写成“删远端”。 |
| 创建校验 | 上传要求本地源文件存在；下载允许目标文件不存在，但先创建父目录。 | 上传和下载的本地路径语义相反。 |
| 重复策略 | 下载目标已存在时支持 `skip`、`fail`、`overwrite`。 | 策略必须在创建、执行、重试和统计中保持一致。 |
| 下载执行 | 调用 `download_with_resume`；本地 `FileNotFoundError` 时创建目录/touch 后重试一次，二次失败转为远端路径错误。 | 首次下载和远端不存在的错误要可区分，不能无限重试。 |
| 重试 | retry payload 携带 `duplicate_strategy`；策略型 `BusinessException` 不再重试；retry task 使用原始策略。 | 延迟任务不能丢失用户选择，也不能重试确定性业务错误。 |
| 统计 | `skip` 状态写入 `Progress=100` 和 `TransferredBytes`。 | 跳过是终态，进度和字节统计仍需可解释。 |

## 当前 CodeGraph 链路

```text
process_transfer_task(transfer_id, file_ids, duplicate_strategy)
  -> FTPTransferService.process_transfer_batch_by_id()
  -> _execute_transfer_batch()
  -> 单文件重复策略预处理
       download + 已存在 + skip  -> skipped / 100% / 本地字节数
       download + 已存在 + fail  -> BusinessException / 失败终态
       download + 已存在 + overwrite -> 删除旧文件
       download + 不存在 -> 创建父目录并准备目标文件
  -> download_with_resume()
       -> transfer_runner.execute_file()
       -> 进度回调、offset、resume mode、哈希
  -> 成功写回文件状态和统计
  -> 异常 -> _handle_transfer_failure(..., duplicate_strategy)
       -> BusinessException 不安排 retry
       -> 可恢复错误按退避写 retry payload
       -> process_retry_task() 用原始 duplicate_strategy 重试
```

任务入口位于 `app/tasks/ftp_tasks.py::process_transfer_task`，短名和全名别名都接收 `transfer_id`、文件 ID 列表和重复策略。前端 `src/services/ftpTransferService.ts` 主要查询传输列表、详情、进度、统计、撤回和取消；下载本身由后端传输任务完成，不应在页面另造一套下载状态机。

## 重复策略契约

| 策略 | 目标已存在 | 任务状态 | 是否传输 | 统计规则 |
| --- | --- | --- | --- | --- |
| `skip` | 保留现有文件 | `skipped` | 否 | `Progress=100`；`TransferredBytes` 取本地文件大小（未知时才使用记录大小）。 |
| `fail` | 不修改目标 | 失败，错误可读 | 否 | 记为策略错误；不进入网络重试。 |
| `overwrite` | 删除后重新下载 | 按正常传输 | 是 | 从 offset 0 开始；旧文件删除失败不能被静默忽略。 |

新项目若支持 `version` 等额外策略，必须把它加入 API Schema、数据库快照、Celery payload、重试队列、审计和测试；不能只在首次请求解析一次。

### 幂等与状态更新

- 重复策略应在 worker 领取文件后再次判断，避免创建任务到执行任务之间目标文件状态发生变化。
- `skip` 必须是可重复执行的终态；重复消息不能把它重新标成处理中。
- `fail`、本地路径无效、远端明确不存在等 `BusinessException` 属于策略/输入错误，不应消耗网络重试次数。
- 状态、进度、已传字节数、哈希、开始/结束时间和错误码应在同一事务边界更新；进度回调失败不能覆盖已完成状态。

## 断点续传与文件完整性

`download_with_resume` 当前把已有 offset、总大小、进度回调和 resume mode 交给 `transfer_runner.execute_file`。可复用实现至少应明确：

1. 目标文件是临时文件还是最终文件；断点重试只能打开属于当前传输 ID 的临时文件。
2. offset 来自已确认写入的字节数，而不是最后一次 UI 进度；远端大小变化时必须重新开始或失败。
3. 下载完成后校验远端/记录中的哈希、大小和协议 EOF，再用原子 rename 发布最终文件。
4. 进程崩溃、磁盘满、连接断开和 worker 重启后能从状态机恢复，不能把半文件当作成功文件。
5. `FileNotFoundError` 的“本地目标未准备好”和“远端路径不存在”要有不同错误码、日志字段和重试策略。

## 撤回与路径安全

提交后的撤回逻辑按方向选择删除目标：上传删 `RemotePath`，下载删 `LocalPath`。这是高风险操作，复用时必须增加以下边界：

- 将本地路径 `resolve()` 后限制在配置允许的下载根目录，并确认文件记录属于当前传输；不能信任数据库中曾经写入的任意路径。
- 对符号链接、路径大小写、Windows 盘符和共享挂载做归属检查，避免 `unlink()` 越界。
- 删除失败时文件状态应为“撤回请求失败/待人工处理”或记录明确告警；不能只把业务状态改成 `revoked` 就隐藏失败。
- 上传远端删除也要按配置/租户前缀限制路径，凭据从配置服务解密，日志中不得输出密码、私钥和完整远端路径中的敏感片段。

## 不能原样复制的历史行为

| 历史行为 | 风险 | 新项目要求 |
| --- | --- | --- |
| `overwrite` 先 `unlink`，失败时宽泛 `pass` | 删除失败后仍可能续传到旧文件，造成混合内容。 | 删除失败立即失败；使用传输专属临时文件并原子替换。 |
| 目标不存在时 `touch` 空文件 | 空文件可能被当作可续传文件；并发任务可能互相看到。 | 使用 `.part` 文件和租约，完成后 rename。 |
| `FileNotFoundError` 重试一次后统一报远端不存在 | 可能掩盖权限、挂载或本地路径问题。 | 区分本地 IO、远端 404、协议错误和权限错误。 |
| 仅按 `BusinessException` 判断不重试 | 业务异常分类若过宽会漏掉可恢复错误，过窄又会重复策略错误。 | 定义可枚举错误码和重试矩阵，而不是依赖文案。 |
| 撤回直接删除 `LocalPath` | 任意路径写入数据库后可能获得删除能力。 | 根目录、租户、传输 ID 三重归属校验。 |

## 推荐模块拆分

| 组件 | 职责 |
| --- | --- |
| `TransferPlanner` | 校验方向、路径根、大小限制和重复策略，生成不可变任务快照。 |
| `TransferExecutor` | 调用 FTP/SFTP adapter 执行上传或下载，支持 offset、超时和校验。 |
| `FileMaterializer` | 管理 `.part` 文件、原子 rename、断点恢复和清理。 |
| `TransferStateMachine` | 统一 pending/running/skipped/success/failed/revoked 状态及统计。 |
| `RetryPolicy` | 依据错误码、attempt 和 deadline 计算退避；策略错误直接终止。 |
| `RevokeService` | 按传输方向和允许根目录撤回文件，并记录删除结果。 |
| `CredentialProvider` | 解密 FTP 凭据，向 adapter 提供最小连接配置；禁止进入日志和任务 payload。 |

## 复用验收清单

- [ ] 上传、下载、撤回都验证远端路径/本地路径的方向语义和允许根目录。
- [ ] `skip/fail/overwrite` 从创建到执行、重试、统计和审计保持一致；重复消息不会重复传输。
- [ ] `skip` 的进度为 100% 且字节数可信；`fail` 不消耗网络重试；策略错误不会被 Celery 自动重放。
- [ ] 下载目标使用临时文件和原子 rename；断点 offset 来自已确认字节，远端大小/哈希变化会重新开始或失败。
- [ ] 首次下载自动创建目录，但目录不可写、磁盘满和路径越界会明确失败。
- [ ] 远端不存在、本地 IO、认证失败、超时和限流具有不同错误码与重试矩阵。
- [ ] 撤回删除失败可查询且不会伪装成成功；符号链接和跨租户路径不能被删除。
- [ ] FTP 密码、私钥、Token 和完整敏感路径不出现在 INFO/WARN/ERROR 或任务 payload。
- [ ] 至少用真实 FTP/SFTP 或协议适配器测试并发重复、断点续传、worker 重启、远端断链和撤回。
