## 端到端链路

```text
上传/配置 API
  -> ImportConfigService 读取启用配置、格式、解析器、目标表和重复策略
  -> ImportRecordService 创建原始文件记录
  -> datafile.import_file_task(record_id, stored_file_ref, format, config snapshot, operator)
  -> worker 重新建立 AsyncSession
  -> 专用文档服务（FT/CP/PN）或 ImportProcessor
       -> 物化本地/MinIO 引用
       -> BaseImportParser / CSV / XLSX / XLS / DOCX
       -> 行校验、映射、主键去重、写入目标表
       -> 更新 processed/success/failed/skipped/versioned 统计和 error_details
  -> CallbackService 记录回调配置/日志、重试或事件重发
  -> 列表/详情 API 返回记录与业务结果
```

`ImportRecord` 是导入状态事实源；解析错误、数据库写入错误和外部业务回调结果应分开保存，页面不能只根据一条 `error_message` 猜测业务状态。

## 通用分页契约

后端 `app/schemas/pagination.py::PaginatedResponse[T]` 的正式形状是：

```json
{
  "total": 120,
  "page": 2,
  "page_size": 20,
  "items": []
}
```

`page >= 1`、`page_size >= 1`，总数和当前页必须由服务端在同一筛选/权限范围内计算。当前后端已有多个列表调用者：admin users、departments、email、features、FTP、positions、training 等。

复用时应一次确定以下规则：

- 查询参数只保留 `page/page_size`，在边界层将旧 `skip/limit` 转换并设置删除期限；不要让每个 route 自己换算。
- 响应列表字段只保留 `items`（或在统一 API adapter 中映射到前端 `records`），不能同时让页面猜 `items/records/data`。
- 排序字段、默认排序、最大 page size、软删除过滤、租户/组织范围和权限条件由服务端统一。
- 空页、页码超过总页数、总数变化和筛选变更都要有确定语义；不要用客户端数组长度代替 `total`。

这是该提交最重要的跨模块风险：当前后端使用 `items`，DataFile 前端类型/服务部分使用 `records`，服务层有兼容解包；新项目应尽快消除双事实源。

## 导入配置、记录与回调模型

### `ImportConfig`

配置至少包含：配置 ID/编码/名称、文档类型、支持格式、解析器类型/类、解析器配置、目标表、主键字段、重复策略、预校验开关、校验规则、启用/删除状态和审计人。当前 `ImportConfigService` 还负责：

- 支持格式的编码/解码，兼容历史单值并统一输出数组。
- 默认目标表与自定义目标表校验；自定义目标表字段映射通过 `destination_mapping_service` 验证和替换。
- 创建/更新前验证文档类型与解析器配置，逻辑删除时同时禁用配置。
- 返回 snake_case `ImportConfigRead`，把数据库 PascalCase/UUID bytes 转换到 API DTO。

配置读取应只返回元数据；解析密钥、连接凭据或内部表结构若属于敏感信息，必须从读模型剔除。

### `ImportRecord`

记录保存原始文件名、大小、格式、配置/文档类型、重复策略、操作人、trace ID、存储引用和哈希，并维护 pending/processing/completed/failed/cancelled 等状态、行数统计、错误明细、开始/结束时间和处理耗时。状态更新要有条件写入或版本号，避免重试任务覆盖已完成记录。

### Callback 配置与日志

当前实现中的 `CallbackService`（`app/services/datafile/legacy_callback_service.py`，历史入口为 `app/services/datafile/callback.py`）负责回调配置/日志 CRUD、状态更新、失败重试和事件重发。回调是外部副作用，必须：

- 以稳定的 `record_id/event_id` 建立幂等键；网络超时不能直接判定“未发送”。
- 保存请求/响应摘要、attempt、下次重试时间和最终状态，敏感请求体按字段脱敏。
- 回调配置删除/禁用不影响历史日志读取，但不能让新任务继续使用已禁用配置。

## 解析器与 `ImportProcessor`

`app/utils/import_processor.py::ImportProcessor` 是当前通用处理器，支持本地路径、MinIO URL/对象引用物化，并处理 CSV、XLSX、XLS、DOCX、字段映射、主键/组合主键去重及 `skip/overwrite/version/fail` 策略。它被 `import_record_service.py`、PN 导入服务、PN 预订单解析服务和 `datafile_tasks.py` 多处调用，是高 blast-radius 组件。

`BaseImportParser` 的最小接口是：

```text
parse(file_path, primary_fields, validation_rules) -> {total_count, rows, errors}
validate_row(row, validation_rules) -> (is_valid, message)
add_parse_error(...) / clear_parse_errors()
```

当前解析器包括 `CSVImportParser`、`XLSXImportParser`、`DOCXImportParser` 和新增的 `XLSImportParser`。XLS/XLSX 解析支持：

- 编码 fallback、表头行识别、空行跳过和 footer/合计行停止。
- sheet 名/索引选择、anchor 单元格、master/detail 行布局。
- 单元格引用、字段映射、值转换、合并行和每行校验。
- 返回结构化解析错误，继续处理有效行；文件级错误返回空结果和错误明细。

解析器不应直接写业务表或发送回调；处理器/领域服务负责事务、去重策略、状态统计和外部副作用。大文件场景应使用流式解析或队列分片，不能默认一次性读入内存。

## 异步任务与幂等

`app/tasks/datafile_tasks.py::import_file_task` 接收稳定的记录 ID、存储引用、格式、主键字段、重复策略、文档类型、解析配置、校验规则和操作人 ID。任务中重新创建数据库 session，并根据专用文档类型选择专用解析服务，否则调用 `ImportProcessor`。

推荐保持以下顺序：

1. 任务领取时以 `record_id + version` 条件把 pending 改为 processing；已 completed/failed 的重复消息直接返回当前状态。
2. 物化文件并校验大小/哈希；对象不存在、格式不支持和配置禁用进入明确失败状态。
3. 解析与写库使用可回滚事务，记录每行错误和去重结果；不要把部分成功伪装为全成功。
4. 提交后再投递回调/业务事件，回调失败写回日志并按错误分类重试。
5. worker 崩溃、软超时和数据库断连由恢复任务重新领取过期 processing 记录。

## 不能原样复制的历史行为

| 历史行为 | 风险 | 新项目要求 |
| --- | --- | --- |
| 一个提交同时迁移几十个列表 API | 难以判断分页契约是否完整，回归范围过大。 | 先定义统一分页 Schema/adapter，再按模块迁移并保留契约测试。 |
| 后端 `items`、前端 `records` 并存 | 空表、总数错误和字段兼容逻辑散落页面。 | 选择单一外部契约，兼容只放在一个边界层。 |
| `skip/limit` 与 `page/page_size` 同时作为长期 API | 调用方永远无法收敛，排序和页码换算容易不一致。 | 设置弃用窗口、观测旧参数命中量并移除。 |
| 解析器/专用服务直接复用数据库对象 | Celery 重试和事务边界不清，可能重复写入。 | 任务传稳定 ID 与不可变配置快照，服务层负责幂等。 |
| `v-html`/原始错误明细交给前端渲染 | 导入内容可能成为 XSS 或敏感数据泄露入口。 | API 返回结构化字段，前端安全转义/白名单渲染。 |
| 提交中的 coverage、上传样例和项目配置一起迁移 | 把环境产物或业务数据误当平台依赖。 | 只迁移源代码、Schema、迁移脚本和最小测试夹具。 |

## 推荐模块拆分

| 层次 | 推荐职责 |
| --- | --- |
| `datafile/contracts` | 配置、记录、回调、分页和错误码的稳定 DTO。 |
| `datafile/storage` | 本地/对象存储 adapter、引用物化、哈希和生命周期。 |
| `datafile/parsers` | 统一 parser 接口及 CSV/XLS/XLSX/DOCX 实现，只负责读取和校验。 |
| `datafile/import_service` | 任务领取、去重策略、事务写入、状态统计和错误明细。 |
| `datafile/callback_service` | 事件投递、幂等、重试、脱敏和回调日志。 |
| `api/v1/datafile` | 参数验证、权限、响应壳和分页转换，不承载解析逻辑。 |
| `tasks/datafile` | 只编排稳定 ID 和配置快照，重新创建 worker session。 |

## 复用验收清单

- [ ] 配置 CRUD、上传、记录详情、原始文件下载、导入数据查询和回调日志都有明确 API/权限契约。
- [ ] 分页统一使用 `page/page_size/items`（或在单一 adapter 中转换），最大页大小、排序、软删除和范围过滤由服务端执行。
- [ ] 配置读写 DTO 分离；目标表、字段映射、支持格式、解析器配置和重复策略在边界校验。
- [ ] 本地/MinIO 引用在 API 与 worker 间可读；文件大小、格式、SHA256 和生命周期有明确策略。
- [ ] 重复任务、worker 崩溃、数据库重试和对象不存在不会重复写入或把终态改回处理中。
- [ ] CSV/XLS/XLSX/DOCX 的空文件、编码、表头、footer、master/detail、校验错误和大文件行为有测试。
- [ ] `skip/overwrite/version/fail` 的统计和错误明细可审计；部分成功与业务回调结果分开。
- [ ] 回调使用幂等键、attempt 和错误分类重试；敏感请求/响应字段脱敏。
- [ ] 前端或其他消费者不使用 `v-html` 直接展示导入数据；权限由后端强制，页面隐藏只改善体验。
- [ ] 迁移清单排除 coverage、样例文件和项目专属 RBAC/配置产物。
