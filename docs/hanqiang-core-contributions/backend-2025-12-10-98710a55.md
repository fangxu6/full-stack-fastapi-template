## 原始链路

```text
POST /v1/datafile/import/process
  -> upload_and_process_import()
  -> 创建 app/uploads/datafile/YYYY-MM-DD/
  -> 以 file.filename 写入本地文件
  -> 创建 ImportRecord(file_path)
  -> Celery datafile.import_file_task(record_id, file_path, ...)
  -> worker 读取文件并执行导入
```

原始版本的目标路径是：

```text
backend/JSECommon/app/uploads/datafile/YYYY-MM-DD/<上传文件名>
```

日期应由部署约定的时区生成。跨时区部署若直接使用机器本地时间，会让同一批文件落入不同日期目录；可复用实现应统一使用应用时区并在记录中保存 UTC 创建时间。

## 当前 CodeGraph 链路

当前 `upload_and_process_import` 已不再把原始文件名作为最终存储名：

```text
upload_and_process_import()
  -> 读取文件并识别 CSV/XLSX/XLS/DOCX
  -> 校验配置、文档类型、客户/制造类型和上传权限
  -> 计算 SHA256（CP 工单额外计算 MD5）
  -> _upload_datafile_to_minio()（启用 MinIO）
       -> import/{document_type}/YYYY/MM/DD/{trace_id}{suffix}
     或 save_datafile_upload_to_local()（未启用 MinIO）
       -> app/uploads/datafile/YYYY-MM-DD/{trace_id}{suffix}
  -> ImportRecordService.create_record()
  -> datafile.import_file_task(record_id, stored_file_ref, ...)
  -> ImportProcessor / 专用文档解析服务
```

当前本地实现位于 `app/services/datafile/local_upload_storage.py`：

- 根目录由模块路径推导为 `app/uploads/datafile`，不依赖当前工作目录。
- 日期目录由 `YYYY-MM-DD` 组成。
- 文件名使用 `trace_id`，只从上传文件名提取小写后缀；没有后缀时使用 `.bin`。
- `ImportProcessor` 能把本地路径、MinIO URL 或对象引用物化为 worker 可读的临时文件。

因此，记录中的 `stored_file_ref` 是跨进程的文件引用，不能假定一定是本机路径；下载源文件、清理和重试都应先按引用类型分派。

## 可复用契约

### 存储引用与异步边界

1. API 只负责接收、校验和持久化原始文件；Celery payload 传 `record_id`、`stored_file_ref`、格式和配置快照，不传 `UploadFile`、数据库对象或文件内容。
2. worker 必须能访问同一对象存储或共享卷。多副本部署不能把 API 容器的临时目录当作共享存储。
3. 记录同时保存 `file_name`（展示用）、`stored_file_ref`（读取用）、大小、格式、哈希和 trace ID；显示名称不能被当作路径。
4. MinIO 与本地 fallback 的读取接口应一致，迁移存储时只改变 adapter，不改变导入任务协议。

### 路径与文件安全

- 原始提交直接拼接 `file.filename`，存在 `../`、反斜杠、绝对路径和同名覆盖风险；新实现必须使用服务端生成的 ID/trace 名称，后缀采用白名单。
- 所有本地读取、删除、下载都要 `resolve()` 后校验位于允许根目录；禁止让记录中的任意路径成为删除权限。
- 写入应使用临时文件、大小限制和原子 rename，避免 worker 读到半个文件；成功落库前确认文件已完整写入并可读。
- 文件名、trace ID、对象 key 和日志字段都要限制长度并拒绝控制字符；日志不应记录文件内容。

### 生命周期与运维

`.gitignore` 只能防止误提交，不能替代生命周期策略。应明确：

- 上传失败、导入成功、导入失败和撤销记录各自的保留期；清理任务按数据库记录和对象元数据执行。
- 本地目录权限、容器挂载、MinIO bucket policy、加密和备份恢复方式。
- 本地 fallback 是否只允许开发环境；生产禁用对象存储时应有显式告警，而不是静默丢失高价值文件。
- 哈希校验、对象不存在、磁盘满、权限不足和 worker 重启后的可恢复状态。

## 不能原样复制的历史行为

| 历史行为 | 问题 | 新项目要求 |
| --- | --- | --- |
| 使用 `file.filename` 作为落盘文件名 | 路径遍历、同名覆盖和跨平台路径语义不一致。 | 服务端生成 trace/id 文件名，只保留受限后缀。 |
| 只把路径转成字符串后投递 Celery | 字符串可序列化，但 worker 可能不挂载同一目录。 | 使用共享对象存储或共享卷，并在任务启动时验证引用可读。 |
| 目录按 API 机器本地日期创建 | 时区不一致导致检索和清理边界漂移。 | 统一应用时区，记录 UTC，按对象元数据做清理。 |
| 直接 `write_bytes`/覆盖目标文件 | 进程中断会留下半文件，重试可能读到坏数据。 | 临时文件 + fsync（按需要）+ 原子 rename + 哈希校验。 |
| 依赖 `.gitignore` 清理上传物 | 磁盘和对象存储会无限增长。 | 独立生命周期任务、配额和保留期监控。 |

## 推荐模块拆分

| 组件 | 职责 |
| --- | --- |
| `FileReference` | 统一表达 `local`、`object`、`temporary` 引用及大小、哈希、版本。 |
| `UploadStorage` | `put/read/delete/presign`；实现本地和 MinIO adapter，隐藏路径细节。 |
| `UploadValidator` | 大小、扩展名、实际文件格式、恶意内容和业务配置校验。 |
| `ImportRecordService` | 保存上传上下文、状态、统计和错误明细；不直接拼接文件路径。 |
| `ImportWorker` | 依据稳定记录 ID 领取任务，物化引用、解析、更新状态并处理幂等。 |
| `RetentionJob` | 按记录终态和保留期清理本地文件/对象，并保留审计摘要。 |

## 复用验收清单

- [ ] 相同文件名并发上传不会覆盖；`../x`、绝对路径、反斜杠和超长文件名不能改变存储根。
- [ ] API 与 Celery 使用同一 `stored_file_ref` 契约；worker 在不同容器/主机上仍能读取文件。
- [ ] MinIO 开关、共享卷不可用、磁盘满和对象不存在时，记录进入明确失败状态，不返回伪成功。
- [ ] 本地和对象存储两种实现都保存并校验大小、SHA256；需要去重时使用哈希而不是展示文件名。
- [ ] 导入 worker 只读取已完成写入的对象；中断、重试和重复消息不会解析半文件或重复落库。
- [ ] 下载/撤销/清理操作验证路径归属和记录所有权；普通用户不能删除任意本地路径。
- [ ] 上传目录、bucket、密钥、保留期和时区均由配置管理，运行时目录不会进入 Git。
- [ ] 至少覆盖成功、格式错误、超限、并发同名、worker 不共享磁盘、对象存储故障和清理任务的集成测试。
