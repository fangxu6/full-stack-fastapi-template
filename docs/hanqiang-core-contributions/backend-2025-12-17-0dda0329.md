## 原始调用链

```text
GET /api/fileMonitor/parse-history/{parse_id}/download-file
  -> FileMonitorParseHistoryService.build_download_response()
  -> 从 ParseDetail 提取 localPath/minioPath/objectName/path
  -> 本地绝对路径存在时调用 PathValidator.validate()
  -> resolve + '..' 检查 + allowed_base_dirs 子路径检查
  -> 通过后按 1MB 分块 StreamingResponse
  -> 失败写安全日志并抛 BusinessException
```

提交只保护本地文件分支。MinIO object key、归档 URL 和其他下载来源仍需要各自的 bucket/URL 校验。

## 当前 helper 契约与兼容风险

当前工作树的 `validate_file_path(file_path, base_dir=None)` 行为是：

- 空路径返回 `(False, "文件路径不能为空")`。
- `os.path.normpath` 后拒绝 `Path.parts` 中的 `..`。
- 绝对路径必须位于默认 `backend/JSECommon` 基准目录下；相对路径按 `download/exports/attachments/temp` 首段白名单判断。
- 返回 `(True, "ok")` 或 `(False, reason)`，不会返回规范化 `Path`，也不会抛出 `BusinessException`。

当前 `EventEmailNotificationService` 按 tuple 解包，契合这个版本；`FileMonitorParseHistoryService` 则把返回值赋给 `validated_path` 后传给 `open()`，契约不一致。复用前应选择一种明确接口，例如：

```python
safe_path = path_policy.resolve_for_read(file_path)  # 失败抛 PathPolicyError
with safe_path.open("rb") as stream:
    ...
```

或统一返回 `ValidationResult(path, reason)`，不要让调用方自行猜 tuple/Path/异常三种语义。

## 路径安全边界

### 规范化与归属

- 先对用户输入做 Unicode/分隔符规范化，再 `resolve(strict=False)`；同时检查原始输入中的 `..`、NUL、控制字符和过长路径。
- 使用 `Path.relative_to(allowed_root)` 判断归属，不能用字符串前缀；`/download2` 不应被视为 `/download` 的子目录。
- 允许根目录从配置注入，并按租户/资源类型分开；不要把整个项目根或系统临时目录列入白名单。
- 文件名来自用户时只作展示，真实文件 ID/对象 key 由服务端生成。

### 符号链接与 TOCTOU

`resolve()` 可以发现已有符号链接，但“校验后再 open”仍存在替换窗口。高风险目录应使用 `openat`/目录句柄、禁止跟随符号链接或在打开后再次确认 `realpath`/inode；下载目录权限也必须禁止低权限用户写入可被高权限服务读取的目录。

### 多种来源

| 来源 | 必要检查 |
| --- | --- |
| 本地路径 | 允许根、规范化路径、符号链接、文件类型、大小和读取权限。 |
| MinIO object key | bucket allowlist、租户前缀、禁止 `..`/绝对 key、对象大小和内容类型。 |
| 归档 HTTP URL | 使用统一 SSRF 策略、超时、重定向和最大响应大小。 |
| `Content-Disposition` 文件名 | 只作展示；移除控制字符/路径分隔符，不能影响服务器读取路径。 |

## 不能原样复制的历史行为

| 历史行为 | 风险 | 新项目要求 |
| --- | --- | --- |
| 只在“绝对路径且文件存在”分支校验 | 不存在文件、相对路径、MinIO 和 URL 分支可能绕过同一安全策略。 | 每种来源有明确 resolver，任何读取前都完成归属校验。 |
| `..` 字符串检查 + 白名单 | 对符号链接、编码分隔符、TOCTOU 和其他 API 不够。 | 使用规范化 Path、目录句柄/无符号链接打开和资源级授权。 |
| 默认允许整个 `download/exports/attachments/temp` 首级目录 | 目录内可能混有不同租户、敏感导出或临时凭据。 | 按资源/租户划分根目录，最小化服务账户读权限。 |
| tuple 返回值与 `Path` 返回值并存 | 调用点可能把 tuple 传给 `open()`，导致下载失败或错误处理失效。 | 一个明确的 resolver/result 类型，契约测试锁定。 |
| 记录中的 `localPath` 可决定下载目标 | 数据库污染或越权写入后可能读取任意文件。 | 通过 `parse_id -> 资源记录 -> 服务器生成路径` 映射，不信任客户端路径。 |

## 推荐模块拆分

| 组件 | 职责 |
| --- | --- |
| `FileReferenceResolver` | 识别 local/object/url 引用，拒绝混合或歧义来源。 |
| `PathPolicy` | 配置允许根、规范化、符号链接策略、租户前缀和文件类型限制。 |
| `ObjectPolicy` | 校验 bucket/object key、大小、版本和内容类型。 |
| `SafeFileReader` | 在校验后的句柄上流式读取，限制大小、超时和并发。 |
| `DownloadAuthorization` | 根据 parse/record/tenant/permission 决定是否可读；UI 权限不是边界。 |
| `DownloadAudit` | 记录资源 ID、来源类型、策略版本、结果和失败原因，不记录秘密内容。 |

## 复用验收清单

- [ ] 本地、MinIO、归档 URL 和附件文件名各自有 resolver，所有读取都在最终打开前完成校验。
- [ ] `../`、反斜杠、绝对路径、NUL、Unicode 分隔符、符号链接和大小写绕过均被拒绝或规范化后安全处理。
- [ ] 允许根目录按租户/资源隔离，服务账户无法读取源码、配置、数据库凭据和其他用户导出。
- [ ] 校验返回类型统一；解析历史、事件邮件、导入处理器和路由均有契约测试，避免 tuple/Path 漂移。
- [ ] 校验和 open 之间的 TOCTOU 有目录句柄、无符号链接打开或受控目录权限保护。
- [ ] 下载响应有大小上限、流式读取、正确 Content-Disposition 脱敏和断点/超时策略。
- [ ] 记录 ID、权限范围和服务器生成路径建立绑定，篡改 ParseDetail 不能扩大可读范围。
- [ ] 路径拒绝事件可审计；错误响应不回显服务器绝对路径或内部目录结构。
