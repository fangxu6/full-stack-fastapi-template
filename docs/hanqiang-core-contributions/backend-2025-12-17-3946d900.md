## 原始调用链

```text
文件监控配置创建/更新
  -> FileMonitorConfigService._validate_target_api_url()
  -> url_validator.validate_url(require_https=False)
  -> 配置持久化

邮件附件处理
  -> FileMonitorApiCaller.call_target_api()
  -> url_validator.validate_url(require_https=False)
  -> 验证失败：写 ParseHistory(ParseType=2, IsSuccess=0)
  -> 验证通过：构建请求并按 4xx/5xx/网络错误策略调用目标 API
```

## 当前 CodeGraph 影响范围

当前 `url_validator` 已被多个外部请求路径共享：

```text
FileMonitorConfigService / ConfigValidator

FileMonitorApiCaller.call_target_api
  -> _validate_target_url
  -> validate_url（HTTP 请求前）
  -> _record_security_error -> ParseHistory

EventEmailNotificationService._download_from_archive_url
  -> validate_url（下载邮件附件）

  -> validate_url（事件回调 HTTP 请求）
```

因此，调整黑名单、白名单或异常类型会影响文件监控、事件回调和事件邮件附件，不应只回归 `api_caller.py`。

## 当前校验规则与限制

`URLValidator.validate_url(url, require_https=False)` 当前执行：

| 检查 | 当前行为 | 复用风险 |
| --- | --- | --- |
| 空值/解析 | 拒绝空 URL；使用 `urlparse`。 | `urlparse` 不等于完整 URL 安全解析，需要显式拒绝 userinfo、控制字符和异常端口。 |
| 协议 | 只允许 HTTP/HTTPS；`require_https=True` 时要求 HTTPS。 | 文件监控调用点目前显式允许 HTTP，敏感数据可能明文传输。 |
| 域名 | `ALLOWED_DOMAINS=["*"]` 时允许所有域名；非通配符支持精确/子域匹配。 | 任意外部域名、攻击者域名和 DNS rebinding 仍可能进入出口。 |
| 直接 IP | 拦截 `127.0.0.0/8`、`169.254.0.0/16`、`::1/128`。 | 未覆盖 `0.0.0.0`、IPv4-mapped IPv6、RFC1918、保留地址和其他云元数据别名。 |
| DNS | `socket.gethostbyname` 解析一个 IPv4 地址后再做同样黑名单检查。 | 只看一个 A 记录，存在 IPv6、多地址、解析 TOCTOU 和代理绕过问题。 |
| 端口 | 当前不限制端口。 | 数据库、Redis、管理面板等端口可能被 HTTP 客户端探测。 |
| 重定向 | 校验目标 URL 本身，未在每次重定向后重新校验。 | 外部域名可 302 到内网地址。应关闭自动重定向或逐跳校验。 |

## 安全审计和日志契约

验证失败返回 `ApiCallResult(success=False, attempts=0)`，并写入 API 调用解析历史。复用时保持：

- 安全拒绝必须在建立连接前发生，不能“请求失败后再判断是否 SSRF”。
- `config_id`、任务 ID、触发来源、规则版本、拒绝原因和目标主机应可审计。
- URL 可能含用户名、密码、查询 Token 或签名；日志和 `ParseDetail` 只能保存规范化后的 scheme/host/port 或脱敏 URL，不能保存完整凭据。
- 4xx 不应自动重试，5xx/网络异常的重试也不能绕过每次请求前的 URL 校验。
- 失败结果必须与业务 API 失败区分，便于告警和安全事件统计；不要把拒绝伪装成“目标服务不可用”。

## 不能原样复制的历史行为

| 历史行为 | 风险 | 新项目要求 |
| --- | --- | --- |
| 通配符允许所有域名 | SSRF 的主要攻击面仍然开放。 | 默认 deny；按租户/环境配置显式 host、端口和协议白名单。 |
| 只检查 `gethostbyname` 返回的 IPv4 | 多 A/AAAA、DNS rebinding 或代理链可绕过。 | 解析全部地址，连接时绑定已验证地址，禁止重定向到未验证目标。 |
| 允许 HTTP | 内网凭据和文件内容可能被窃听或篡改。 | 默认 HTTPS；HTTP 仅对明确的本地开发/隔离网段开启并审计。 |
| 端口检查被注释掉 | 可探测数据库、缓存和控制面。 | 白名单端口，拒绝非 HTTP 服务常用端口。 |
| 把原始 URL 写入错误日志 | URL userinfo/query 可能含秘密。 | 结构化日志字段脱敏，只记录 host、port、规则版本和 trace。 |
| 校验失败后只返回 `success=False` | 调用方可能把安全拒绝当作普通可重试错误。 | 使用稳定的 `SECURITY_VALIDATION_FAILED` 错误码和不可重试标记。 |

## 推荐的可复用设计

| 组件 | 职责 |
| --- | --- |
| `URLPolicy` | 按环境/租户声明 scheme、host、端口、IP 网段、重定向和最大响应大小；默认拒绝。 |
| `URLParser` | 规范化并拒绝 userinfo、控制字符、异常编码、空主机和非标准端口。 |
| `DNSGuard` | 解析所有 A/AAAA，拦截 loopback/link-local/private/reserved/metadata 范围，并处理 TTL/TOCTOU。 |
| `SafeHttpClient` | 禁止或逐跳校验重定向，限制连接/读取/响应大小，绑定出口代理和超时。 |
| `SecurityAudit` | 记录拒绝原因、规则版本、配置/任务 ID 和结果；敏感字段脱敏。 |
| `ConfigValidator` | 保存配置时做快速校验；不能取代运行时复验。 |

应用层校验之外，生产网络还应使用 egress firewall、云元数据保护、代理 allowlist 和容器网络策略。代码校验不是网络隔离的替代品。

## 复用验收清单

- [ ] 未配置白名单时默认拒绝外部目标；每个业务租户/环境的允许 host、端口和 scheme 可审计。
- [ ] 创建、更新、任务执行、事件回调和邮件附件下载都使用同一策略对象并在实际连接前复验。
- [ ] 拒绝 loopback、link-local、RFC1918、IPv6 ULA、未指定/保留地址、云元数据地址和 IPv4-mapped IPv6。
- [ ] DNS 解析覆盖所有 A/AAAA；解析后的地址与实际连接绑定，处理 DNS rebinding 和代理解析差异。
- [ ] HTTP 重定向被禁用或逐跳重新执行完整校验；响应大小、连接超时和读取超时有限制。
- [ ] URL 中的 userinfo、Token、签名和查询秘密不出现在日志、错误响应或 ParseDetail。
- [ ] 安全拒绝有稳定错误码，明确不可重试，并能按配置/任务/规则版本查询审计记录。
- [ ] 使用真实 DNS、HTTP 重定向、IPv4/IPv6、代理和云网络演练 SSRF 测试，而不只测字符串黑名单。
