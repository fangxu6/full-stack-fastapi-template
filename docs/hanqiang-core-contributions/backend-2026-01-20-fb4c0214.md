## 3. CodeGraph 关系与真实流程

CodeGraph 当前索引显示的主调用链：

```text
POST /approve/process-nodes/{id}/handle
  -> ApprovalService.handle_approval()
     -> 条件 UPDATE Approve_Process_Detail(ApproveStatus=1)
     -> ProcessService.advance_process()
        -> NodeAssignmentService.assign_next_stage()
     -> 提交后 trigger_event()
```

关键关系：`process_service -> node_assignment_service`，`approval_service -> process_service`，审批事件再进入通用 `event_dispatcher.publish()`。CodeGraph 未发现 `node_assignment_service` 的独立覆盖测试，迁移时不能只依赖路由冒烟。

## 4. 可复用行为契约

### 4.1 NodeLevel 与 BIT 兼容

- `NodeLevel` 必须匹配 `正整数.正整数`，例如 `1.2`；空值、`0.1`、`1.0` 和非数字直接拒绝。
- 排序使用 `(stage, order)` 数值元组，不能使用字符串排序。
- MySQL `BIT(1)` 可能返回 `bytes`、`memoryview` 或 `{data: ...}`，统一转换后再判断 `IsSingleApproval`。
- `IsSingleApproval=1` 覆盖 `ParallelPolicy`，强制按串行节点处理。

### 4.2 OR 并行

- `ParallelPolicy=3` 且未被 `IsSingleApproval` 覆盖时，同阶段连续 OR 节点一起分配。
- 任一 OR 节点同意：其余同组待办置为 `ApproveStatus=5`（失效），流程进入下一节点/阶段。
- OR 节点退回：直接拒绝，避免“部分退回”造成组状态不确定。
- OR 节点否决：只有同组没有任何 `ApproveStatus=1` 待办时，流程才变为 `ProcessStatus=4`；仍有待办则流程保持进行中。

### 4.3 重新提交与回调状态

- 可重新提交状态由 `(4=否决, 5=退回)` 扩展为 `(4, 5, 6=取消)`。
- 否决/取消：从首节点全量重审；退回：复制已通过节点，从退回节点继续。
- 新流程 `CallbackStatus=0`；发起事件匹配到回调后回写 `1=执行中`，事件失败由事件桥接回写 `3=失败`。
- `CallbackStatus` 字典：`0 无、1 执行中、2 成功、3 失败`。

### 4.4 事件模板

`append` 模板支持 `${Field}`、`${$.path}`、`${value}` 以及 `${NOW}`、`${NOW_YYYY}`、`${NOW_MM}`、`${NOW_DD}`、`${NOW_HH}`、`${NOW_MI}`、`${NOW_SS}`、`${NOW_YYYYMMDD}`、`${NOW_YYYYMMDDHHMMSS}`。迁移时应保留未知占位符的显式错误，不要静默替换为空。

## 5. 事务与并发边界

- 审批节点使用 `UPDATE ... WHERE ApproveStatus=1` 抢单，重复点击或并发审批只能成功一次。
- `advance_process()` 只修改当前事务，不自行 `commit`；人工审批、超时任务和重放任务必须调用同一个推进器。
- OR 组失效其他节点和流程终态更新必须在同一事务内完成。
- 回调发布发生在主业务提交后；回调失败不能回滚已落库的审批结果，依靠 `CallbackStatus`、事件日志和补偿任务追踪。
- 节点记录不再写 `CreatorID/CreateTime/UpdaterID/UpdateTime`，目标项目若保留这些列，应明确由 ORM 默认值或审计中间件负责。

## 6. 复用风险与验收

- [ ] 串行、AND、OR、`IsSingleApproval` 覆盖规则均有单元/集成测试。
- [ ] OR 同意会失效同组待办；OR 否决在“仍有待办/全部否决”两种情况下分别验证。
- [ ] 人工审批与超时审批并发时不会双重推进。
- [ ] 取消流程可重新提交，且 `ParentProcessID`、轮次和回调状态正确。
- [ ] 回调匹配成功、无匹配、发布异常分别得到 1/0/3 的可追踪状态。
- [ ] 数据库迁移不会把旧流程的 `CallbackStatus=1` 误解为失败或待触发。
- [ ] 时间模板在统一时区下渲染，未知 key 和非法 `NodeLevel` 有明确错误。
