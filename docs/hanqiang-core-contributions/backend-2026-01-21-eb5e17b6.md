## 4. 角色与授权契约

### 4.1 RoleType

本提交明确两类用途：`1=审批人角色`、`2=流程管理员角色`。当前模型还兼容动态角色 `3=部门负责人`、`4=部门审批人列表`、`5=发起人自选审批人`；迁移时将它们作为策略类型处理，不要把所有角色都视为静态成员列表。

- 工作流节点的 `RoleID` 必须存在、启用且 `RoleType=1`（动态角色按既有策略解析）。
- `FlowAdminRoleID` 必须存在、启用且 `RoleType=2`。
- 列表接口支持 `role_type` 过滤，角色详情和审批人查询使用独立读权限。
- 流程管理员权限按“系统管理员”或“工作流绑定的管理员角色成员”判断；不能只判断前端按钮。

### 4.2 监控数据范围

`list_process_monitoring()` 对管理员返回全量流程；普通用户只返回其作为工作流管理员的 `WorkflowID`。响应同时返回 `items/total/page/page_size/total_pages` 和 `status_summary`，后者按全量可见范围统计 1~7 状态，不受当前分页和筛选影响。

## 5. 弃审配置矩阵

仅 `ProcessStatus=3`（已通过）允许进入检测。检测同时评估：

| 完成回调 | 弃审回调 | 结果 |
| --- | --- | --- |
| 有 | 无 | `Blocked=true`，禁止弃审，避免完成后无法撤销外部业务 |
| 有 | 有 | 允许弃审，并执行 `approval_process_abandon` |
| 无 | 有 | 允许更新状态，但不执行撤销回调 |
| 无 | 无 | 允许更新状态，不触发回调 |

`AbandonConfigCheckResponse` 还可返回 `CallbackStatus`、匹配到的动作/目标服务等调试信息（后续 `7c805e02` 进一步扩充）。本提交的弃审动作只把流程置为 `ProcessStatus=7`；“弃审后重建待确认流程”是 `7c805e02` 的后续行为，不能倒归因到本提交。

## 6. 操作日志模型

`Approve_Process_OperationLog` 的最小字段：

- `ProcessID`、`ActionType`、`OperatorID/Name`、`OperateTime`；
- `Content`、`ExtendData(JSON)` 保存原因和扩展上下文；
- `NotifyStatus`：`0 无需通知、1 待发送、2 发送中、3 成功、4 失败`；
- `WXSendLogID`、`NotifyErrorMessage` 关联企业微信发送结果；
- `ProcessID + ActionType + OperateTime`、操作人、通知日志等索引。

`create()` 在当前事务写入并返回日志 ID；`safe_create()` 负责“日志失败不阻塞业务”的场景。迁移时应保留审计日志的不可变语义，更新只用于通知状态同步。

## 7. 事件配置筛选

`Sys_Event_Config` 新增：

- `TransactionType`：事件的业务事务语义，空值表示不限制；
- `TargetObjectType`：当前审批约定 `APPROVAL_FLOW`；其他类型保守不匹配；
- `TargetObjectID`：绑定具体 `WorkflowID`，空值表示该对象类型的全局配置。

事件发布前依次执行事务类型、目标工作流和 `ScenarioConditions` 条件评估；配置 CRUD 在输入和过滤时把 UUID 字符串转换为 `BINARY(16)`。这样同一事件码可以区分“某工作流专属回调”和“全局回调”。后续 `7c805e02` 增加“专属配置有日志则不再触发全局兜底”的优先级。

## 8. 复用风险与验收

- [ ] 服务层拒绝把 `RoleType=2` 绑定到审批节点，拒绝把普通角色作为流程管理员。
- [ ] 监控列表只返回当前管理员可见的工作流，状态摘要与总范围一致。
- [ ] 四种弃审回调组合符合矩阵，且非已通过流程不能弃审。
- [ ] 操作日志写入失败不影响流程状态，但通知状态可后续同步。
- [ ] `TargetObjectID` 的非法 UUID 返回 400，不进入数据库查询。
- [ ] 事务类型/目标对象/场景条件任一不匹配时不创建回调日志。
- [ ] 权限码变更有兼容策略；`6cc930bc` 后的读权限命名以新提交为准。
