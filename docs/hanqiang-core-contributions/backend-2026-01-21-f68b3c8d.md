## 4. 事件载荷契约

### 4.1 通用元数据

载荷从 `Approve_Process_Master`、`Approve_Workflow_Master/Detail`、`Approve_Role_UserDetail` 和 `CommonUser` 组装：

- 流程：`ProcessID`、`ProcessCode`、`BusinessCode`、`ProcessName`、`WorkflowID`；
- 节点：`ProcessNodeID`、`NodeName`、`NodeLevel`；
- 人员：`InitiatorName`、`ApproverName`、`FinalApproverName`；
- 时间：`StartTime`、`ApproveTime`、`EndTime`、`TotalDuration`；
- 链接：`ApprovalURL`、`DetailURL`、`EditURL`、`ResubmitURL`；
- 通知收件人：`RecipientWXUserIDs`。

流程名为空时回退到工作流名；时间统一格式 `YYYY-MM-DD HH:mm:ss`；收件人去重并过滤空企业微信账号。

### 4.2 事件类型

| 事件码 | 触发点 | 典型收件人/字段 |
| --- | --- | --- |
| `approval_process_started` | 流程真正开始（启动或确认） | 流程管理员；流程详情链接 |
| `approval_node_assigned` | 首节点、下一节点、重新提交或超时推进后分配 | 直接审批人优先，否则角色成员；审批链接 |
| `approval_node_approved` | 人工或超时通过节点 | 发起人；审批人、批注、下一节点名 |
| `approval_process_returned` | 节点退回 | 发起人；编辑/重提链接 |
| `approval_process_rejected` | 流程否决 | 发起人；重提链接 |
| `approval_process_completed` | 流程完成 | 发起人；最终审批人、总耗时 |

节点分配事件同时提供 `processNodeId` 和 `processId`，前端可据此打开审批弹窗或详情抽屉。

## 5. 事件桥接与失败语义

`trigger_event()` 透传通用 `event_dispatcher.publish()`：

1. 成功返回 `matched/scheduled/trace_id`；
2. 没有匹配配置时返回 `matched=0`，不把流程标成失败；
3. 发布异常先回滚会话，再尝试将对应流程 `CallbackStatus` 更新为 3；
4. `trigger_notify_event()` 只记录异常，不修改审批主表回调状态，适合纯通知。

审批流程启动后，`ProcessService` 根据 `matched>0` 将 `CallbackStatus` 从 0 改为 1；因此“无回调”和“回调执行中”可区分。事件日志由通用平台负责持久化，主业务提交与回调执行不是一个原子事务。

## 6. 企业微信账号与链接

- `CommonUser.WXUserID` 在创建、更新、列表和审计数据中贯通；空字符串归一化为 `NULL`。
- 角色成员收件人只取启用、未删除且有 `WXUserID` 的用户；若节点已有直接 `ApproverID`，优先直接收件人。
- 前端地址来自配置的公开基址，不能硬编码开发机地址；迁移时增加生产环境校验。
- 模板字段应允许多余字段，避免历史模板因新增元数据失败；必填字段仍由模板解析器显式校验。

## 7. 与超时/并行的组合规则

- 超时自动审批调用同一个 `advance_process()`，并把 `ApproverID` 设为 SYSTEM 用户、`IsTimeout=true`。
- `advance_process()` 返回刚创建的下一节点集合，随后逐节点发送 `approval_node_assigned`；没有下一节点才发送完成事件。
- OR/AND 并行组的节点事件必须与节点状态更新处于同一推进结果之后，避免通知尚未真正激活的节点。
- 事件发送失败不重试主审批事务；通过回调日志、状态字段和补偿任务重放。

## 8. 复用风险与验收

- [ ] 启动、确认、通过、退回、否决、完成、超时各生成正确事件码和字段。
- [ ] 直接审批人、角色成员、流程管理员三类收件人解析均有覆盖。
- [ ] `WXUserID` 为空时不生成空收件人；用户禁用/删除后不再通知。
- [ ] `ApprovalURL/DetailURL` 使用可配置公开地址，URL 参数正确编码。
- [ ] 事件无匹配、发布异常、通知发布异常分别验证 `CallbackStatus` 行为。
- [ ] 节点分配事件只在节点真正创建后发送，重提和超时场景不重复发送旧节点。
- [ ] `process_id/process_node_id` 过滤不能绕过待审批权限范围。
