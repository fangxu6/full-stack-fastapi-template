## 4. 审批运维能力

### 4.1 监控与状态摘要

`list_process_monitoring()` 在当前用户可见的工作流范围内统计 1~7 状态：`pending_confirm/in_progress/completed/rejected/returned/cancelled/abandoned`。状态摘要不受 `status`、`keyword` 和分页影响，适合前端筛选标签；普通用户只能查看其流程管理员角色所绑定的工作流。

### 4.2 催办

- 仅进行中的流程（`ProcessStatus=2`）可催办；系统管理员或对应流程管理员可操作。
- 选择最早分配的待办节点；并行组可一次选择同阶段的多个待办。
- 收件人优先使用节点直接 `ApproverID`，否则使用角色成员；过滤禁用/删除用户和空 `WXUserID`，按用户去重。
- 默认消息为“请尽快处理此审批任务”；载荷兼容 `ApprovalURL/approve_url/approveUrl` 等历史模板字段。
- 同一流程 1 小时冷却；`get_urge_meta()` 返回当前审批人、上次催办、下次时间和剩余秒数。
- 先写 `Approve_Process_OperationLog(NotifyStatus=1)`，企微发送成功后关联 `WXSendLogID`；发送失败写状态 4 和错误信息。

### 4.3 弃审后重建

`abandon_process()` 在通过流程置为 `ProcessStatus=7` 后，检查同一 `BusinessCode` 无活跃流程，再创建一个新的 `ProcessStatus=1` 待确认实例：

- 新实例 `ParentProcessID` 指向旧流程，复制业务快照、工作流和发起人；
- 旧流程的弃审日志保留回调配置、首个 `CallbackID` 和 `IsRebuild=true`；
- 只有“完成回调存在 + 弃审回调存在”才发布撤销事件；
- 返回旧流程与重建流程的 ID/编码，供前端继续确认。

### 4.4 流程创建时版本快照

工作流更新会软删除旧节点并插入新节点。`get_by_workflow_for_process()` 通过流程最早分配节点的 `AssignTime` 找到对应 `Workflow_Detail.CreateTime`，再按同一版本加载节点（包含已软删除节点），确保旧流程不被新配置“穿越修改”。同时，配置更新/删除前应拒绝仍有 `ProcessStatus=2` 实例的工作流。

## 5. 事件与通知基础设施

### 5.1 专属配置优先

对于 `TargetObjectType=APPROVAL_FLOW` 且绑定具体 `TargetObjectID=WorkflowID` 的配置，事件分发先尝试专属配置；只有专属配置没有创建任何回调日志时，才回退到同事件码的全局配置。这样可以避免全局回调和工作流专属回调重复执行。

### 5.2 企业微信默认配置与 URL 兜底

- 发送 `config_code=default` 且数据库不存在时，从 `config.yaml` 的 `wxwork.agent_id/secret` 懒创建配置；Secret 使用 Fernet 等加密存储，并以数据库唯一冲突回读应对并发。
- `template_card` 发送前递归补齐空 `url` 字段和 `card_action.url`，回退地址来自动态载荷中的审批/详情 URL。
- 发送 Celery 任务完成或失败后，根据 `WXSendLogID` 同步 `Approve_Process_OperationLog.NotifyStatus`。

### 5.3 重复错误告警（可选）

Loguru ERROR sink 将日志指纹交给 Redis：默认 5 分钟窗口累计 10 次触发一次，触发后冷却 30 分钟，再由 Celery 发布 `log_error_repeated` 事件。sink 必须永不抛异常并支持 `skip_log_error_alert/skip_error_alert/skip_alert` 标记，避免告警链路反过来污染业务日志。

## 6. 复用风险与验收

- [ ] 工作流有进行中实例时，更新/删除被拒绝或进入明确的版本化策略。
- [ ] 监控数据范围与状态摘要都按权限过滤，不能通过分页参数绕过。
- [ ] 催办在串行、AND、OR、直接审批人和角色成员场景下均正确去重，并严格执行冷却。
- [ ] 企微发送失败能回写操作日志错误，发送任务重试不会重复生成催办日志。
- [ ] 弃审会阻止活跃业务重复创建，并返回可确认的重建实例。
- [ ] 旧流程在工作流更新后仍读取原节点版本，退回/重提不混用新旧配置。
- [ ] 专属回调有日志时不会再触发全局回调；专属无匹配时能兜底全局。
- [ ] 默认企微配置不覆盖人工配置，密钥不明文落库；模板卡片缺 URL 时有可解释兜底。
- [ ] 重复错误告警在 Redis 不可用时只跳过告警，不影响业务日志和审批事务。
