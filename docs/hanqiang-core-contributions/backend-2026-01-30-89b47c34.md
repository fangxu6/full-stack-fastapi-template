该提交在两个 FastAPI 应用入口统一配置 `CORSMiddleware.expose_headers=["Content-Disposition"]`，使跨域浏览器代码能够读取后端返回的下载文件名。提交同时整理了两个入口的格式和少量生命周期代码；可迁移的核心行为只有 CORS 响应头暴露。

## 2. 涉及文件与调用边界

| 文件 | 作用 | 复用建议 |
| --- | --- | --- |
| `app/main.py` | 轻量 FastAPI 应用入口，配置 `settings.frontend.origins`、凭证、方法、请求头和暴露响应头 | 迁移到实际生产入口；不要只修改未被部署的示例入口 |
| `app/main_refactored.py` | 带异常处理、启动任务和自定义 OpenAPI 的生产入口 | 与 `main.py` 保持同一 CORS 契约，避免不同启动命令行为不一致 |

CodeGraph 显示应用入口的 `CORSMiddleware` 是配置边界，而 `getFilenameFromContentDisposition()` 被 50 余个下载/导出服务复用。也就是说，后端只暴露响应头并不足够：前端请求必须读取该 header，下载工具还要兼容 UTF-8 文件名和安全清理。

## 3. 可复用配置契约

```python
app.add_middleware(
    CORSMiddleware,
    allow_origins=settings.frontend.origins,
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
    expose_headers=["Content-Disposition"],
)
```

- `expose_headers` 只控制浏览器脚本可读的响应头，不会改变实际 HTTP 响应，也不会授予跨域访问权限。
- `allow_origins` 应来自显式配置；当 `allow_credentials=True` 时不要使用通配来源 `*`。
- 仅暴露确有需要的响应头。若项目还需要前端读取性能指标，可单独加入 `Server-Timing`，不要无差别暴露全部 headers。
- `main.py` 与 `main_refactored.py` 必须同时更新，或通过共享应用工厂生成唯一 CORS 配置，防止部署入口漂移。

## 4. 下载文件名端到端流程

```text
下载/导出 API
  -> Response headers: Content-Disposition
     attachment; filename="report.xlsx"; filename*=UTF-8''报告.xlsx
  -> CORSMiddleware 暴露 Content-Disposition
  -> Axios/fetch blob 响应读取 headers
  -> getFilenameFromContentDisposition()
  -> sanitizeFilename()
  -> <a download="..."> 保存文件
```

当前前端工具优先解析 `filename*`，支持 UTF-8 百分号编码；若编码非法则回退到 `filename=`，最终再移除控制字符、路径分隔符和空文件名。迁移时应保留这一顺序，避免中文文件名在 Chrome/Edge 与代理环境中退化为默认名称。

## 5. 安全与兼容性边界

- 文件名来自外部输入时，后端应移除 CR/LF，防止响应头注入；同时提供 ASCII fallback 和 RFC 5987 UTF-8 值。
- 前端保存前应移除 `..`、路径分隔符、控制字符，并在空值时使用固定 fallback；不能把 header 原值直接写入 `link.download`。
- 代理/CDN 必须透传 `Content-Disposition`；若签名 URL 使用 `response-content-disposition`，要确认最终响应仍返回该 header。
- CORS 预检请求仍需通过 `allow_methods/allow_headers` 和来源校验；`expose_headers` 不影响预检授权。
- `Content-Disposition` 同时可能用于 inline 预览和 attachment 下载，前端不要强制覆盖后端 disposition 语义。
