## PMS 查询与模板契约

### 范围和计划筛选

1. `all_devices`：查询 `IsDeleted=0 AND IsActive=1`，若制造类型非空再按 `ManufactureTypeCode IN (...)`。
2. `specified_devices`：按配置关系加载设备；不存在/删除/停用设备不阻断整批任务，而是生成 `skipped` 明细。
3. 查询 Active 计划且 `StartDate <= today + max(0, advance_remind_days)`；按日期、设备编号、设备名、模板名稳定排序。
4. 计划日期早于今天标记 `is_overdue=true`，统计 `overdue_plan_count` 和 `upcoming_plan_count`。

### `mtplan` 双渲染

`build_mtplan()` 返回 `TemplateRenderValue`：

- `text`：制表符分隔的标题/数据行，适合纯文本邮件。
- `html`：已对单元格内容 `escape()` 的表格，带最小内联样式。
- `allow_raw_html=True` 仅针对该系统生成的表格；用户变量默认仍转义。

变量存储前通过 `serialize_variables_for_storage()` 把 `TemplateRenderValue` 转为带 marker 的 JSON；读取历史邮件时用 `restore_stored_variables()` 还原，避免 JSON 列丢失 HTML/text 语义。

## 执行状态、重试和 Trace

- `dispatch_scheduled_task` 在已有 `TaskTraceID` 时不再用 Celery task id 覆盖它，保证手动执行/重试链路稳定。
- `list_traces` 先把陈旧 pending（默认 10 分钟）标为 timeout，再按 Trace 分组；没有 Trace 的旧记录退化为自身 ExecutionID。
- Trace `overall_status` 取最新步骤状态，`latest_execution_id` 指向最新记录；步骤保留完整主日志摘要。
- 重试只允许 `failed`/`timeout`；不修改原记录，创建新记录并复制 Trace。目标任务仍需启用且在有效期内，且同一任务不能有活动执行。
- 前端/调用方必须关闭这两个写请求的网络自动重试，否则一次点击可能产生两条执行记录。

## 邮件提交与错误边界

`EmailSendService` 的提交包装器在 commit 异常时先 rollback，再记录错误并抛出；发送历史中的 variables 始终是可 JSON 化结构。PMS Worker 在邮件异常时：

1. 非 skipped 明细写入 failed、耗时和错误；
2. 主记录更新失败/跳过计数和 `ExecutionSummaryJSON`；
3. 提交后重新抛出，使 Celery 监控可见；外层兜底再次回填主/明细状态。

不要把“邮件发送失败”当作成功任务；如果 SMTP 提交具有副作用，重试前必须提供幂等键或人工确认。

## 数据库迁移注意事项

迁移文件 `202605071000_add_scheduled_task_tables.py` 对已存在的 PMS 配置增加列时包含：

```sql
UPDATE PMS_Scheduled_Task_Config_Detail
SET EquipmentScopeMode = 'specified_devices'
WHERE EquipmentScopeMode IS NULL
   OR EquipmentScopeMode = ''
   OR EquipmentScopeMode = 'all_devices';
```

这会把原有“全部设备”数据映射成“指定设备”，与默认值语义相反；跨项目迁移前必须改为按历史设备关系决定映射（有有效关系才指定，否则全部），并为旧数据写一次性校正脚本和审计记录。`ManufactureTypeCodes` 空值应统一为 JSON 空数组。

## 复用步骤

1. 先落地首版 6 张表和执行日志状态，再加入范围模式；不要让 `equipment_ids=[]` 同时代表“全部”和“未选择”。
2. 把 `PmsTaskQueryService` 抽成领域适配器，返回通用的 `MatchedItem/SkippedItem`，通知层只消费结果。
3. 将模板变量分为用户变量和系统变量；系统变量通过显式注册表提供，HTML 输出只允许可信生成器。
4. 为执行主表建立 `(TaskTraceID, QueuedTime)`、`(ScheduledTaskID, Status)` 索引，状态迁移使用条件更新或版本号。
5. 重试入口返回新 `execution_id`，在 UI 和 API 客户端关闭自动重试，增加审计字段 `source_execution_id`。
6. 使用 outbox 或 Beat 补偿扫描解决“任务提交成功但调度同步失败”；不要仅依赖 warning 日志。
