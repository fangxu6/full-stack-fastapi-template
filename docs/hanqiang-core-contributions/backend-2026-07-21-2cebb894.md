## 变更目标

Socket 寿命预警从“黄/红两个阈值”简化为“一个红色触发阈值”。有效规则是：

```text
remaining_life / total_life * 100 <= life_warning_percent_red
    -> matched_items，warning_level = "warning"
否则
    -> 不发送该对象
```

`life_warning_percent_yellow` 不再是创建/更新的必填项，也不再参与匹配；服务层创建时将其持久化为 `NULL`，更新时保留已有值以兼容历史数据。`total_life` 或 `remaining_life` 缺失/非法的对象仍会进入候选并写入 skipped 明细，避免数据库预过滤改变审计结果。

## Tooling 候选 API

新增受 `scheduled_task:read:list` 保护的接口：

```text
GET /api/scheduled-tasks/tooling-options
  ?warning_type=socket_life|sample_tube_expiry|sample_tube_bin1_safety_stock
  &page=1&page_size=50&keyword=<code/name/group>&tooling_ids=<uuid1,uuid2>
```

行为约定：

- `warning_type` 必填，并映射到唯一 Tooling 类型：`socket_life -> Socket`，两个样管预警 -> `SampleTube`；未知类型返回 400。
- 只查询 `IsDeleted=0`；关键字匹配 `ToolingCode`、`ToolingName` 或 `GroupCode`，按 `ToolingCode` 升序稳定分页。
- `tooling_ids` 按逗号拆分、去重并校验 UUID；与关键字同时存在时使用 OR，确保已选对象不会因当前搜索词消失。
- 默认 `page_size=50`，接口上限 200；成功响应外层沿用 `{code, message, data}`，`data` 统一为 `{items, total, page, page_size}`，每项包含 `tooling_id/tooling_code/tooling_name/tooling_type/group_code`。

该查询只返回轻量选项，不把寿命快照或执行明细塞入表单接口；详情/执行查询继续走原有服务。

## 查询与索引优化

`ToolingTaskQueryService._load_candidates()` 对 `all_toolings` 的 Socket 扫描在数据库阶段追加候选条件：寿命字段缺失、总寿命无效，或剩余寿命已低于红阈值。这样先排除寿命正常对象，再由 Python 计算百分比，同时保留需要写 skipped 的异常对象。指定 Tooling 模式仍按 ID 读取并报告缺失对象。

新增迁移 `202607211530_add_tooling_warning_query_indexes`，并在模型中声明同名索引：

- `Tooling(ToolingType, Status, IsDeleted, GroupCode, ToolingCode)`：覆盖活动 Tooling 预警候选过滤和排序；
- `Tooling_Group(IsDeleted, ToolingType, GroupCode)`：覆盖当前类型有效组别选项查询。

迁移升级/降级先检查索引是否存在，支持重复执行；迁移前需确认 `down_revision=202607200931_backfill_socket_used_count` 在目标项目可达。

## CodeGraph 调用链证据

```text
GET /api/scheduled-tasks/tooling-options
  -> list_tooling_warning_options
  -> ScheduledTaskService.list_tooling_options
  -> warning_type -> expected_tooling_type
  -> count + ordered option query

Tooling warning execution
  -> ScheduledTaskService.create/update_tooling_task
  -> _validate_tooling_payload (red threshold/type/scope)
  -> ToolingTaskQueryService.collect_warning_items
  -> _load_candidates (DB prefilter)
  -> matched_items / skipped_items
```

CodeGraph 还显示 `_validate_tooling_payload()` 同时由创建和更新路径调用，故阈值、组别类型和指定 ID 校验应集中在该服务边界，不能只在新增 API 或前端表单中实现。

## 跨项目复用步骤

1. 将预警类型定义为受控枚举，并建立“预警类型 -> Tooling 类型”的单一映射；未知值在 API 边界返回 400。
2. 提供轻量候选分页接口，关键字和已选 ID 使用 OR，分页上限由后端强制，响应不携带执行快照。
3. Socket 预警只要求一个红阈值；历史黄阈值字段可保留为兼容列，但不要继续参与匹配或作为新请求必填。
4. 在执行查询中先按类型、状态、删除标记、组别和寿命条件预过滤，再对异常数据生成 skipped 明细，确保性能优化不丢审计事实。
5. 为候选过滤建立覆盖索引并使用可重复迁移；确认 ORM 模型索引、迁移索引名和降级顺序一致。
6. 同时测试 API 参数校验、选项排序/去重、红阈值边界、异常寿命 skipped 以及索引声明；前端黄/红展示需另行对齐，不能假定本提交已覆盖。
