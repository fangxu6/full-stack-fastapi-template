## 最小运行闭环

```text
业务事务 -> enqueue_outbox_event
         -> Owner Worker 租约领取 -> POST /internal/service-communication/events
         -> 目标 receive_event 写 Inbox 并返回 202
         -> 目标 Worker 异步调用已注册 handler
         -> 必要时在目标事务写回执 Outbox
```

- `OwnerServiceCode` 是数据和 Worker 的硬边界；主服务聚合层需要远端记录时，使用 `RemoteOwnerRecordClient` 转发，不能跨服务数据库写入。
- 同一 `EventID` + 相同 `PayloadHash` 幂等返回；摘要冲突返回 409；未知版本/事件是永久错误。
- 每个处理轮次为首次执行加最多 2 次自动重试；人工重试只允许 `dead`，新建轮次并保留旧 Attempt/Audit。
- 暂停服务会暂停发送 Outbox 与处理 Inbox，但不消耗尚未产生真实副作用的次数；目标地址和配置版本在首次投递时冻结。
- `/internal/**` 使用真实 socket IP + 登记 CIDR + requester service code，不接收用户 JWT，且不发布到 OpenAPI。

## 跨项目复用步骤

1. 先迁移六张表和索引，再实现 `contracts.py`；用 Python/Rust 相同 golden fixture 固定中文、嵌套对象、数组顺序和键顺序。
2. 在业务事务里写本服务 Owner 的 Outbox；Worker 只领取本 Owner 的记录，并把 handler 注册表作为明确扩展点。
3. 目标服务先写 Inbox 再返回 202；业务副作用只在 Inbox Worker 事务执行，失败按错误类别区分重试/死信。
4. 接入服务注册、CIDR、能力验证、权限和审计；公网反代对 `/internal/**` 返回 404。
5. 先执行迁移，再运行现有测试中的重放、摘要冲突、Owner 转发、人工轮次、暂停和 Worker 租约用例。
