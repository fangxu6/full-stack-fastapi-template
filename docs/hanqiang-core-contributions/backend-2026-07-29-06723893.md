## 聚合算法

1. 对 Outbox 和 Inbox 做同字段只读 `UNION ALL` 投影；不复制载荷，也不改变 Worker 状态。
2. `CorrelationID` 非空时分组为 `correlation:<UUID>`；否则按 `event:<EventID>` 单事件分组。
3. 链路状态取记录状态的最高失败优先级：`dead > paused > processing > delivered > processed > ignored > cancelled`，避免 Outbox 已送达掩盖目标 Inbox 死信。
4. 列表先在 SQL 聚合分页，再批量读取当前页记录；详情按严格解析后的 `chain_key` 返回轻量记录。
5. 默认排除归档；`include_archived=true` 才显示逻辑归档事实。非法状态或 chain key 返回明确业务错误。

## API 契约

| 方法 | 路径 | 关键参数 | 权限 |
| --- | --- | --- | --- |
| GET | `/api/service-communication/chains` | `chain_key`、Owner/来源/目标、事件/聚合/业务键、`trace_id`、`statuses[]`、时间范围、分页 | `service_communication:record:read` |
| GET | `/api/service-communication/chains/{chain_key}` | `include_archived` | `service_communication:record:detail` |

返回摘要包含 `record_count/outbox_count/inbox_count`、首个发生时间、最近活动时间、错误摘要、状态计数和服务/事件去重集合；详情额外包含按发生时间排序的 `records`。

## 跨项目复用步骤

1. 目标项目先保证 Outbox/Inbox 具备同名关联字段和 `IsArchived/IsDeleted/UpdateTime`，再复制只读投影；没有这些字段时不要伪造链路状态。
2. 将 `_RAW_STATUS_RANK` 和对外 `ChainStatus` 保持为一个事实源；前端只消费摘要，不重复实现优先级。
3. 为 `correlation:<UUID>` 与 `event:<UUID>` 建复合索引；索引迁移必须可重复执行，且不回填历史关联 ID。
4. 先分页摘要，再批量拉取当前页记录，避免每条链路一次 SQL；详情路径严格校验前缀和 UUID。
5. 测试至少覆盖无 correlation 的回退分组、死信优先级、归档可见性、非法状态/键和重复筛选参数。
