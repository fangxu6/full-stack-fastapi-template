## 核心契约

### 管理面与运行面分离

管理 API 使用 `external_integration:manage` 权限，负责配置/回调 CRUD、Key 轮换/退休、脱敏预览、可选网络测试、审计日志/网络尝试查询和认证拒绝统计。运行 API 位于 `/api/pms/integrations/*`，只接受代码固定的契约：

- `pms.equipment-status.query.v1`：入站按 `equipment_code`、`asset_code` 或 `serial_number` 查询；出站返回设备编码与 MES 状态映射；
- `pms.equipment-status.sync.v1`：入站批量写入 `equipment_code + mes_state`，批量最多 200 项；
- 请求体上限 64 KiB，严格 JSON 拒绝重复键、非法常量和非 UTF-8；响应统一包含 `code`、`message`、`trace_id`。

### 安全、幂等与审计

- 入站先按 Key、启用状态、方向和来源 CIDR 认证，再按固定 contract/callback 路由；认证拒绝和不可用配置都写入审计日志。
- `Idempotency-Key` 使用严格 JSON 的规范化哈希；同 Key 不同 payload 返回冲突，同 Key 处理中返回 409，处理租期默认 60 秒，过期记录在行锁内收敛为失败。
- 入站/出站请求、响应和错误统一结构化脱敏，密钥、Authorization、敏感 Header/Body 不进入日志；所有日志关联 TraceID，网络尝试单独记录。
- 配置和回调写操作使用 `ConfigVersion/CallbackVersion + expected_version` 乐观锁；变更前后快照脱敏保存，退休立即失效入站 Key。

### 出站 Profile 与设备上下文

出站 URL、方法、超时、Header、Body 模板、响应 JSONPath、结果映射和事件字段映射均来自受限 Profile。服务端校验协议/Host/Port/CIDR 白名单，禁止任意 URL、脚本、SQL、目标表和回调 ID；设备数据通过固定服务查询并按模板变量渲染。

### 事务与错误边界

主业务状态和外部网络尝试分开记录；不可用、配置歧义、合同错误、网络错误、超时和业务错误使用固定错误分类。网络层不自动重试不可重放的管理/入站事实；补偿依赖日志状态、租期和显式重试策略。

## 历史边界

- 本提交新增外部集成协议、数据库表、管理/运行 API 和审计模型；后续 `a4193e5e` 只拆分服务文件，不改变公开服务契约。

- 网络测试属于管理操作，不能作为生产事件投递器；正式投递仍应由事件/任务执行路径负责。
