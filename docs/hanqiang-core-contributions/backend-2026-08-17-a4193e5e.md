## 拆分契约

原 3,600 行单体服务拆为多个 Mixin，但公开入口保持稳定：

```python
ExternalIntegrationService(
    ExternalIntegrationManagementMixin,
    ExternalIntegrationPreviewMixin,
    ExternalIntegrationInboundMixin,
    ExternalIntegrationOutboundMixin,
    ExternalIntegrationSharedMixin,
    ExternalIntegrationEventService,
)
```

- 路由继续导入 `external_integration_service`；调用方不需要知道 Mixin 文件。
- Mixin 只能依赖 `common/shared` 或明确的同层依赖，不得反向导入稳定入口，避免循环依赖。
- `parse_inbound_json()` 在稳定入口保留静态转发，固定入站路由继续使用同一严格 JSON 实现。
- 原 `tests/services/test_external_integration_service.py` 删除，按 common/inbound/management/outbound/profile 分拆，并新增路由测试；测试边界与生产 Mixin 一一对应。

## CodeGraph 调用链证据

```text
external_integrations.py
  -> external_integration_service (singleton)
     -> ExternalIntegrationService MRO
        -> management / preview / inbound / outbound / shared / event
           -> common policy + models + equipment adapters
```

稳定入口只负责组合和兼容导出；业务规则仍在对应 Mixin。迁移时可先保持同名 facade，再按“通用基础 → 共享 → 领域 Mixin → facade”顺序移动代码，避免一次性改动所有路由。

## 跨项目复用步骤

1. 先锁定原服务公开 import 路径和 singleton，再创建 facade；迁移期间路由和调用方保持不变。
2. 把无状态工具/常量放入 common，把跨领域查询和模板渲染放入 shared，再按管理、入站、出站、预览拆分。
3. 明确 Mixin MRO 和依赖方向，禁止子模块导入 facade；公共错误类型和严格解析器只能有一个事实源。
4. 按生产职责移动测试并增加路由级回归；每个拆分模块应有独立测试入口。
5. 拆分完成后再考虑将 Mixin 替换为组合服务；若没有第二个实现，保持当前最小 facade 即可。

## 历史边界

- 本提交是内部结构重构，不改变管理/运行 API、数据库模型、错误分类、幂等、审计或网络策略。
- 文件拆分不会自动解决跨进程一致性、事务边界或网络重试问题；这些仍由原契约约束。
- 删除旧单体测试文件是测试重组，迁移时必须确认新测试覆盖与旧测试等价，而非仅依赖文件数量。
