## 条件契约

### 归一化输入

登记字段固定为：

| 条件键 | 设备事实键 |
| --- | --- |
| `equipment_code` | `EquipmentCode` |
| `equipment_name` | `EquipmentName` |
| `asset_code` | `AssetCode` |
| `serial_number` | `SerialNumber` |
| `manufacture_type_code` | `ManufactureTypeCode` |
| `equipment_type_code` | `EquipmentTypeCode` |
| `equipment_type_name` | `TypeName` |

每个字段接受以下三种形状：

```json
{
  "equipment_code": {"$in": ["FT-A", "FT-B"]},
  "equipment_name": {"$ne": "已停用设备"},
  "manufacture_type_code": "FT"
}
```

- 对象表达式必须只有一个运算符；标量兼容为 `$eq`；数组兼容为 `$in`。
- 运算符只能是 `$eq`、`$ne`、`$gt`、`$gte`、`$lt`、`$lte`、`$in`、`$nin`、`$exists`。
- `$in/$nin` 必须是字符串、数字、布尔值或 null 组成的标量数组；`$exists` 必须是布尔值；其他运算符只能接收标量或 null。
- 未登记字段、未知运算符、多运算符对象和非法值在保存边界抛出 `BusinessException`，不能静默忽略。
- 出站查询和出站事件保存规范化后的对象；空对象持久化为 `None`，表示不限设备。

### 共享求值语义

`condition_evaluator.evaluate()` 对所有字段做 AND；字段路径支持点号读取。`$in/$nin` 对标量做成员判断，对数组实际值采用任一元素命中；比较运算符异常时返回 false；`$exists` 按“实际值不是 `None`”判断存在。因此缺失字段和明确 null 对 `$exists` 都视为不存在，目标项目若需区分两者应先扩展共享求值器并补测试。

## 事件事实与可观察性

- `_enrich_equipment_context` 在同一查询中关联设备、类型、型号、`Common_Area` 和快照，新增/编辑事件把 `AreaName` 放入对外 `data`。
- `pms.equipment.created.v1`、`pms.equipment.updated.v1` 的映射字段包含 `AreaName`；`pms.equipment.scrapped.v1` 仍只允许 `EquipmentCode`，删除场景不扩散主数据。
- 主数据和状态事件的 TraceID 格式改为包含设备编码（如 `pms-equipment-status:<EquipmentCode>:<EventID>`），避免仅凭 UUID 排查时无法快速定位。
- 事件映射仍由 `eventMappings` 白名单控制；本提交只是补充 AreaName 到白名单，不改变“映射只改外部报文”的边界。

## 跨项目迁移步骤

1. 在后端建立稳定的条件字段到领域事实字段映射；前端字段目录必须来自同一契约。
2. 先在保存入口归一化旧标量/数组，再把规范对象交给执行层；空条件统一为 `None`。
3. 将运算符白名单和值类型校验集中在一个策略函数，未知输入直接返回可审计错误。
4. 所有匹配路径调用共享条件评估器，禁止查询路由和事件路由各自实现比较逻辑。
5. 事件事实查询一次性补齐区域等关联字段；对新增/编辑与报废定义不同的对外数据集。
6. TraceID 优先包含稳定业务键（设备编码）并保留事件 ID；审计/网络尝试沿用同一 TraceID。
7. 以单元测试覆盖每个运算符、旧格式兼容、非法输入、AreaName 白名单和报废最小载荷。
