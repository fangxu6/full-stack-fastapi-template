## 前端端到端链路

```text
AppSidebar
  -> router/index.ts
       /datafile/configs
       /datafile/records
       /datafile/callback-configs
       /datafile/callback-logs
  -> 页面状态、筛选、表单和上传控件
  -> services/datafile/* service adapter
  -> apiClient（统一 baseURL、认证和错误）
  -> backend /v1/datafile/*

```

菜单和路由 feature key 包括 `module:datafile`、`menu:datafile:config`、`menu:datafile:record`、`menu:datafile:callback`、`menu:datafile:log`。按钮权限还包括：

```text

pn_pre_order_import:record:detail

pn_pre_order_import:upload:create
```

这些 key 只控制菜单、按钮和后续请求；后端必须再次验证读取范围、上传、详情、下载和专用业务结果权限。

## 服务 adapter 契约

### `import.service.ts`

`datafileImportService` 集中处理：

- `uploadFile(file, configId, options)`：multipart 上传，支持文档类型、客户代码、制造类型、量产标记、重复策略和预校验；对 413 翻译为用户可读错误。
- `getRecords(page, pageSize, filters)`、`getRecordById(recordId)`：导入记录分页、详情和源文件下载。
- FT 工单记录/详情/外部业务结果查询。
- PN 预订单上传/详情/外部结果，PN 配置查询和通用 PN 上传/导入数据查询。
- 统一解包 `response.data?.data ?? response.data`，并把后端 `items` 兼容映射到页面使用的 `records`。

页面只应接收领域 DTO；不要在四个页面中重复判断 `data/items/records`、403、413 和网络错误。

### 配置、回调和导入数据 service

| service | 当前契约 | 复用注意 |
| --- | --- | --- |
| `config.service.ts` | 配置列表仍接受 `skip/limit`；CRUD、目标表校验/映射、文档类型查询。 | 与后端 `page/page_size` 方向未完全收敛，迁移时应在 adapter 一次转换。 |
| `callback.service.ts` | 回调配置 CRUD、启停和分页/详情调用。 | 回调状态是外部副作用结果，不能仅靠 HTTP 2xx 推断最终成功。 |
| `callbackLog.service.ts` | 回调日志列表、详情、状态和重试相关调用。 | 重试应以服务端幂等键和 attempt 为准，禁止浏览器无条件重放。 |
| `importData.service.ts` | 主表/主从表/从表查询，snake_case -> camelCase，详情扁平化。 | 扁平化只是展示模型；不要把它写回 API 或丢失主从 ID。 |

`importData.service.ts` 当前通用数据查询仍可把 `page/pageSize` 换算为 `skip/limit`，而 PN 数据接口使用 `page/page_size`。这说明页面之外仍有历史 API，不能只改一个分页组件。

## 页面与数据模型

### 配置管理 `ConfigManagement.vue`

配置页支持列表过滤、创建、编辑、复制、删除、支持格式选择、解析器配置、自定义目标表/字段映射和工单模板生成。支持格式交互约束为 CSV/DOCX 单选组、Excel 可多选。写入模型应与读模型分离，避免把服务端生成字段或敏感配置通过 `Partial<ImportConfig>` 回传。

### 导入记录 `ImportRecords.vue`

记录页支持状态/文档类型/配置/日期筛选、分页、详情、源文件下载以及 FT、CP、PN、通用 PN 上传入口。详情区同时展示：

- 导入状态、业务状态、总行数/成功/失败/跳过/覆盖/升版统计。
- 文件路径、trace、文件摘要、MinIO 对象和错误明细。
- FT/CP 外部业务结果、请求响应、业务摘要和未匹配行。
- PN 导入数据和主从表详情。

列表响应没有外部业务结果；当前页面只对当前页、已完成的工单记录发起后续查询，并用 request version 丢弃过期响应，避免 N+1 扩散。新项目应把这种“列表摘要 + 详情/业务结果按需加载”写成明确接口契约。

### `ImportRecordDataTable.vue`

组件支持动态列、主表/明细表、JSON 结果、错误明细、搜索、分页、虚拟滚动、加载/空/错状态。它还被 Tooling、PC 管理和文件监控解析历史页面复用，已经是跨业务通用组件。

首版使用 `v-html` 展示部分动态单元格内容；导入文件内容、错误消息和外部回调结果都属于不可信输入。复用时必须改为安全文本/白名单 HTML 渲染，并限制链接、样式和脚本注入。

## 分页与响应壳风险

后端通用 `PaginatedResponse[T]` 使用 `total/page/page_size/items`，前端 `src/types/datafile.ts` 的导入记录列表使用 `records`。当前服务层兼容 `payload.records ?? payload.items ?? []`，这只能作为过渡。

推荐的前端边界是：

1. `apiClient` 统一处理认证、错误壳和 trace；DataFile service 统一解包 `data`。
2. adapter 内把所有后端列表转换为 `{ total, page, pageSize, items }`，页面不再读取 `items/records/data`。
3. query 只保留一个公共类型，服务层负责 `page/page_size`，旧 `skip/limit` 只在有期限的兼容函数中出现。
4. 服务端返回的 `total`、排序和权限范围是唯一事实源；页面不能用当前数组长度替代总数。

## 权限、下载与可靠性边界

- 前端 `hasPermission()` 只负责显示；API 必须对列表、详情、源文件下载、导入数据、回调管理和专用业务结果分别授权。
- 源文件下载使用 `responseType: 'blob'` 和 `Content-Disposition` 文件名解析；下载按钮应处理 loading、超时、错误和未知结果，不能把 blob 错误当成功文件。
- 上传提交要防重复点击，保留服务端返回的 `record_id`；202/“已受理”不等于导入或外部业务成功。
- 详情里的错误明细、客户代码、文件路径、哈希、外部响应和业务行可能含敏感数据，默认最小展示并按权限脱敏。
- 前端网络超时后不能自动重发上传、回调重试或外部业务操作；应使用稳定 ID 查询状态。

## 不能原样复制的历史行为

| 首版行为 | 风险 | 新项目要求 |
| --- | --- | --- |
| 页面同时处理 `items/records/data` | 响应升级后容易出现空表或总数错误。 | 单一 API adapter 统一响应和错误。 |
| 配置页使用 `skip/limit`，记录页使用 `page/page_size` | 分页语义、页码换算和服务端契约不一致。 | 统一 page contract，旧参数限时兼容。 |
| `v-html` 渲染导入内容 | XSS、恶意链接和样式注入。 | 默认文本转义，必要 HTML 采用 sanitizer + allowlist。 |
| 隐藏菜单/按钮作为权限控制 | 可绕过 UI 直接调用 API 或下载源文件。 | 后端按动作、资源范围和敏感字段授权。 |
| 列表后逐条请求外部业务结果 | 页大小增大时产生 N+1 和竞态。 | 服务端提供批量摘要或详情按需/批量接口。 |
| 上传后直接显示“成功” | 202 只代表受理，异步导入/回调可能失败。 | 展示 pending/processing/终态，按 `record_id` 查询。 |
| `importData` 在前端扁平化主从行 | 展示形状与领域数据混淆，可能丢失关系。 | 明确展示 DTO 与写入 DTO，保留 master/detail ID。 |

## 推荐模块拆分

| 层次 | 推荐职责 |
| --- | --- |
| `types/datafile.ts` | 读 DTO、创建/更新 DTO、上传选项、分页、错误和状态联合类型。 |
| `services/datafile/api.ts` | 响应壳、分页、snake/camel 转换、错误码和下载文件名归一。 |
| `pages/datafile/ConfigManagement.vue` | 配置元数据、解析器/目标表编辑和表单状态。 |
| `pages/datafile/ImportRecords.vue` | 记录筛选、上传、详情抽屉、按需加载外部结果和源文件下载。 |
| `components/datafile/ImportRecordDataTable.vue` | 只负责安全展示动态字段、分页、加载/错/空态；不直接拼 API。 |
| `pages/datafile/Callback*.vue` | 回调配置、日志、attempt、重试和脱敏审计。 |
| `useDatafilePermissions()` | 将列表、详情、上传、下载、回调管理等动作映射到 UI；不替代服务端授权。 |

## 复用验收清单

- [ ] 四条路由、菜单 feature key、页面权限和后端动作权限一一对应；直接请求 API 无权必拒绝。
- [ ] 所有 DataFile 列表都经过一个 adapter，统一响应壳、`total`、页码、排序、筛选和错误翻译。
- [ ] `page/page_size` 是唯一新契约；旧 `skip/limit` 有观测、兼容窗口和删除计划。
- [ ] 配置读写 DTO 分离，目标表/映射/解析器配置和文件格式在客户端只做提示，后端做最终校验。
- [ ] 上传防重复提交并保存 `record_id`；202、超时、刷新和网络恢复不会重复创建导入记录。
- [ ] 记录详情区分导入状态、解析错误、业务回调状态和外部结果；列表不会产生无界 N+1 请求。
- [ ] 源文件下载、错误明细、文件路径、客户/业务数据按权限和字段规则脱敏。
- [ ] 动态单元格不使用不受控 `v-html`；HTML、URL、文件名和外部响应均按不可信输入处理。
- [ ] 主从数据展示保留关联 ID，snake/camel 转换和扁平化有单元测试。
- [ ] 页面、service、表格组件和后端契约测试覆盖空/错/加载态、分页边界、403/413、异步终态和重试条件。
