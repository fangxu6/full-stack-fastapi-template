## 3. 权限树组件契约

### 3.1 输入数据

组件接收 treeData、modelValue 和 cascade：

~~~typescript
type FeatureTreeNode = {
  FeatureID: string
  FeatureType: 'module' | 'menu' | 'button' | string
  FeatureKey?: string
  FeatureCode?: string
  FeatureName: string
  children?: FeatureTreeNode[]
}

type PermissionTreeProps = {
  treeData: FeatureTreeNode[]
  modelValue?: string[]
  cascade?: boolean
}
~~~

实际项目还可能带 ParentID、Path、Icon、IsSystem、IsEnabled 等字段。权限树逻辑只应依赖稳定 ID、类型、权限键、名称和 children，避免绑定业务页面字段。

组件通过 update:modelValue 输出选中的 FeatureID 列表。JsePermissionTreeEl.vue 当前只声明这一输出；PermissionTree.vue 另外输出 change，并带上半选节点。

### 3.2 组件内部的三份状态

1. 原始树：保留按钮节点，用于查找按钮权限和父子关系。
2. 展示树：processTreeData() 去掉按钮子节点，让菜单/模块保持清晰的树形结构。
3. 节点索引：nodeMap 保存 FeatureID 到节点的映射，parentMap 保存 FeatureID 到父节点 ID 的映射。

按钮并没有从权限模型删除，只是从树的可展开分支中平铺显示。迁移时不能只传展示树，否则无法判断按钮的父菜单、查询按钮和手工按钮权限。

## 4. e3f8464f 的核心修复

### 4.1 避免 Element Plus 级联误勾选

新增 getEffectiveCheckedKeysForTree(checkedKeys, nodeMap, parentMap)，算法如下：

1. 从外部权限 ID 中过滤未知节点和 button 节点；
2. 保留 module/menu 节点的去重集合；
3. 对每个已选节点沿 parentMap 向上收集祖先；
4. 从结果中移除“同时也是其它已选节点祖先”的节点；
5. 如果只有父节点被选中，则保留父节点本身。

伪代码：

~~~text
selected = checkedKeys 中存在且非 button 的节点
ancestors = selected 中每个节点的所有父节点
return selected - ancestors
~~~

背景是后端角色权限接口会为了可导航性向上补全模块/菜单。若直接把补全后的 ID 传给 Element Plus 的级联树，树展开时可能把未授权的子菜单一起勾上。初始化时只传“最小集合”，可以保留真实授权边界。

这个函数是纯函数，时间复杂度为 O(N * H)，N 为选中节点数，H 为树深度；返回顺序沿用输入顺序。它假设 parentMap 来自无环树，跨项目应在服务端或索引构建阶段校验重复 ID 和父子环。

### 4.2 图标显示策略

新增 shouldShowPermissionTreeNodeIcon(node)，提交 e3f8464f 的基线规则是：

- 非 module 节点显示图标；
- 特定 module FeatureKey 隐藏图标，使权限树与现有侧边栏视觉保持一致；
- FeatureKey 比较大小写不敏感。

当前工作树中该策略已经被后续提交扩展为菜单节点也可隐藏，并继续维护一组项目专属 module key，例如后台用户管理、人事管理、系统设置、邮件服务、文件监控和事件回调。不要把这些 key 当成通用常量，应改成项目配置或由节点元数据决定。

### 4.3 接入 JsePermissionTreeEl.vue

组件在 defaultCheckedKeys 上使用 getEffectiveCheckedKeysForTree，在节点模板上使用 shouldShowPermissionTreeNodeIcon。原有交互仍包括：

- FeatureName + FeatureCode 搜索；
- 展开全部；
- 级联选择开关；
- module/menu/button 类型标签和图标；
- 按钮子节点平铺显示；
- 菜单选中后自动纳入基础查询按钮；
- 非查询按钮允许在父菜单选中时手工选择；
- 父菜单未选中时禁用按钮；
- 从外部 modelValue 变化重新同步树的勾选状态。

其中 nextTick() 配合 Element Plus 的 getCheckedKeys()/setCheckedKeys() 是组件时序的一部分。换用其他树组件时，应把“初始化勾选”和“用户变更回写”分开，不要照搬对 Element Plus store.nodesMap 的访问。

## 5. 当前工具文件的后续扩展

CodeGraph 当前读取到的 permissionTree.ts 还包含 isReadPermissionButton()。该函数来自 e3f8464f 之后的权限树提交链，不应误标为 e3f8464f 的新增内容，但它已经成为 JsePermissionTreeEl.vue 的当前依赖：

- 中文名称包含 查询、列表、详情、查看，或权限键分段为 read/list/detail/view 时，视为基础读取按钮；
- 名称或键分段包含 导出、export、download 时排除；
- view_all 视为数据范围权限，必须单独授权，不自动勾选。

这是兼容现有权限命名的启发式，不是安全授权规则。跨项目迁移时优先让后端返回 capability（例如 is_read_action、is_scope_action），前端只消费能力字段；若暂时保留启发式，必须覆盖多语言名称、复合权限键、导出详情和数据范围权限测试。

## 7. 跨项目迁移步骤

1. **先定义节点契约**：统一 FeatureID 类型、FeatureType 枚举、children 字段和权限键命名；不要同时接受多套大小写字段而不做边界归一化。
2. **复制纯工具**：迁移 getEffectiveCheckedKeysForTree 和 shouldShowPermissionTreeNodeIcon，先替换项目专属图标 key。
3. **建立索引**：在树数据变化时重建 nodeMap/parentMap，检测重复 ID、缺失父节点和环。
4. **接入树组件**：展示树可以隐藏/平铺按钮，但原始树必须可查；初始化勾选使用最小集合，保存时输出完整权限集合。
5. **明确按钮策略**：查询按钮自动授权还是独立授权必须由后端契约决定，不能只由中文名称推断。
6. **补齐测试**：纯函数测试先覆盖祖先过滤、按钮过滤、仅父节点、空输入和图标策略，再补组件测试覆盖搜索、级联、按钮禁用和外部值同步。
7. **最后迁移样式**：页面样式作为独立变更接入，并用目标项目的权限键和字段替换培训业务示例。

## 8. 复用风险与边界

- **不是安全边界**：权限树只负责编辑和展示，后端 RBAC/API 仍必须校验每次操作。
- **父级补全语义必须一致**：如果后端不再补全父级，最小集合算法的输入/保存策略需要重新定义。
- **按钮语义不能硬编码**：中文名称、read/list 字符串和导出例外都属于历史兼容规则。
- **展示树与原始树不能混淆**：过滤按钮后若丢失原始 children，会导致按钮状态和父级判断错误。
- **级联模式要有明确开关**：非级联模式下只修改当前节点，不能继续沿用父子自动更新。
- **递归和深度**：超深权限树会触发递归栈或频繁重建，必要时改为迭代遍历或限制树深度。
- **组件类型检查**：当前 JsePermissionTreeEl.vue 含有 ts-nocheck，迁移时应逐步移除，至少为 props、emit 和树实例补类型。
- **全局 CSS 风险**：jse-page-system.css 变更量大，不能把业务页面样式当作权限组件依赖。
