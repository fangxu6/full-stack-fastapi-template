## 4. 可复用组件与契约

### 4.1 ApprovalDialog

组件输入：`visible`、`data: PendingApprovalItem | null`、`componentPath`、可选 `mode`；输出：`update:visible`、`success`。

- `full` 模式展示流程信息和业务数据；`commentOnly` 只加载审批意见，减少列表场景的业务数据请求。
- `RETURN` 仅在 `NodePosition=2/3` 时可用；首节点/唯一节点禁用退回，提交函数再次校验，不能只依赖按钮禁用。
- `APPROVE` 可不填意见；`RETURN/REJECT` 必须填意见。
- 使用 `approve:mvp:process-node:handle` 权限码；弹层 z-index 高于详情抽屉，避免嵌套弹窗被遮挡。
- 并发冲突只进入短暂冷却提示，不自动代替用户重试；错误由 API 响应明确告知。

### 4.2 监控与催办服务

```ts
listProcesses({ page, page_size, status?, keyword? })
checkAbandon(processId)
getUrgeMeta(processId)
urgeProcess(processId, { UrgeMessage? })
abandonProcess(processId, { AbandonReason })
```

`UrgeMetaResponse` 至少包含当前审批人、上次催办、是否可催办、下次催办时间和剩余冷却秒数；`CurrentApprovers` 应包含节点/角色信息，供 AND/OR 并行阶段完整展示。页面对状态汇总同时兼容 `1..6` 数字键和 `pending_confirm/in_progress/...` 英文键。

### 4.3 工作流节点配置

`WorkflowNodeConfig.vue` 在前端维护工作副本：按 `NodeLevel` 解析阶段，拖拽后把阶段内顺序重新编号为 `stage.1..n`，并把 `ParallelPolicy` 规范化为 `1/2/3`。这只是编辑器约束，后端仍须校验节点级别、角色类型、并行规则和运行中流程保护。

### 4.4 业务数据与密码编辑

- 重提业务数据编辑器允许 literal/JSON 值，空对象与显式 `null` 语义必须和后端约定一致。
- 用户编辑页默认不展示密码输入；只有勾选“修改密码”才渲染并提交密码，防止浏览器密码管理器误覆盖。
- 工作流编辑列表项缺少管理员角色等详情字段时，先打开对话框再异步拉详情补齐，不能用空值覆盖后端。

## 5. 测试与迁移验收

`ProcessMonitoring.spec.ts` 覆盖：

1. 快捷筛选点击会向 API 传递 `status=2`；
2. 催办弹窗展示并行阶段所有待处理节点的用户、部门、角色和节点信息。

其他项目迁移至少补齐：

- 同意/退回/拒绝的按钮权限、意见必填和 NodePosition 边界；
- 催办冷却、重复收件人去重、空部门/空姓名显示；
- 状态汇总英文键/数字键兼容及分页筛选行为；
- 工作流拖拽后 `NodeLevel` 连续编号、阶段策略同步和保存失败回滚；
- 用户编辑不修改密码时不会提交 Password；
- 事件预置文档与实际 `RecipientWXUserIDs` 收件人一致。

## 6. 复用风险

- `ProcessMonitoring.vue` 的前端状态号只是展示映射，不能代替后端 `CanAbandon/CanUrge` 和权限判断。
- 页面默认使用 `page/page_size`，若目标 API 仍是 `skip/limit`，应在 service 层做一次适配，避免组件到处分叉。
- 企微收件人、审批链接和回调状态属于后端事件载荷；前端类型允许可选字段，但不能静默伪造默认值。
- `WorkflowNodeConfig` 使用连续节点推断并行组；目标系统有显式并行组时应改用后端组 ID。
