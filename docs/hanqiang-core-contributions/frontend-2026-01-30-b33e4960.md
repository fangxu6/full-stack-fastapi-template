## 4. `getFilenameFromContentDisposition` 契约

### 4.1 输入和默认值

```typescript
getFilenameFromContentDisposition(
  contentDisposition: string | null | undefined,
  fallbackName = 'download'
): string
```

- `null`、`undefined` 或空响应头直接返回 `fallbackName`。
- 解析失败、编码不支持、文件名为空时也返回 fallback（或在已找到 `filename=` 时使用其清理结果）。
- 解析函数只返回字符串，不创建 URL、不操作 DOM，适合放在服务层或纯函数测试中。

### 4.2 解析优先级

1. **优先 `filename*=`**：按 RFC 5987/RFC 8187 形式解析 `charset'language'percent-encoded-name`。
   - 支持空 charset、`utf-8`、`utf8`；
   - 将 `+` 转成 `%20` 后调用 `decodeURIComponent`；
   - URI 解码异常时继续尝试普通 `filename=`。
2. **回退 `filename=`**：支持带双引号和不带引号的 token，去除外层引号，并解除 `\\x` 形式的转义。
3. 两种参数都不存在时返回 fallback。

示例：

| `Content-Disposition` | 结果（fallback=`download`） |
| --- | --- |
| `attachment; filename*=UTF-8''%E4%B8%AD%E6%96%87.xlsx` | `中文.xlsx` |
| `attachment; filename="report.csv"` | `report.csv` |
| `attachment; filename=report.csv` | `report.csv` |
| `attachment; filename*=UTF-8''bad%ZZ; filename=report.csv` | `report.csv` |
| `attachment` | `download` |

### 4.3 文件名清理

内部 `sanitizeFilename(name, fallbackName)`：

- 以 `/`、`\\` 分割，只保留最后一个路径片段，避免把服务端路径直接作为下载名；
- 删除 `U+0000`–`U+001F` 和 `U+007F` 控制字符；
- 去除首尾空白，结果为空时返回 fallback；
- 再将残留路径分隔符替换为 `_`。

该清理降低路径穿越和控制字符风险，但不是完整的操作系统文件名策略。目标项目若需兼容 Windows 保留名、冒号、通配符、长度上限或 Unicode 规范化，应在同一边界扩展并补测试，不要让业务页面各自清理。

## 5. `downloadBlob` 契约

提交新增的函数：

```typescript
export function downloadBlob(blob: Blob, filename: string): void {
  const url = window.URL.createObjectURL(blob)
  const link = document.createElement('a')
  link.href = url
  link.download = filename
  link.rel = 'noopener'
  document.body.appendChild(link)
  link.click()
  link.remove()
  window.URL.revokeObjectURL(url)
}
```

它负责一次性的浏览器下载生命周期：创建 Object URL、构造隐藏锚点、触发点击、移除锚点并释放 URL。函数不负责请求、权限、MIME 类型或文件名解析；调用方应先取得 Blob 和可信文件名。

当前工作树还出现了后续新增的 `openBlobInNewTab(blob)`，该函数不属于 `b33e4960`，且会延迟 60 秒释放 URL。迁移时不要把它误认为本提交的下载契约。

## 6. 事件日志导出接入

### 6.1 服务层变化

提交前，`eventLogService.ts` 使用：

```typescript
const match = /filename=([^;]+)/i.exec(contentDisposition)
```

它无法处理 `filename*=`、百分号编码、引号转义和路径清理。提交后 `exportExecutionLogs()` 改为：

```typescript
const response = await apiClient.get(`${BASE}/execution-logs/export`, {
  params,
  responseType: 'blob'
})
const filename = getFilenameFromContentDisposition(
  response.headers?.['content-disposition'],
  'event_logs.csv'
)
return { blob: response.data as Blob, filename }
```

服务层因此把“响应头解析 + fallback”统一起来，并把文件名作为返回契约的一部分交给页面。

### 6.2 当前页面的注意点

CodeGraph 和源码复核显示，`EventLogQuery.vue` 当前仍然这样调用：

```typescript
const { blob } = await exportExecutionLogs(params)
// 随后自行按 Trace/Log 数量拼接 a.download
```

也就是说，页面丢弃了服务返回的 `filename`；后端响应头中的动态文件名在该页面不会真正生效。跨项目接入时应二选一：

- 接收 `{ blob, filename }` 并调用 `downloadBlob(blob, filename)`，让服务端文件名生效；
- 明确产品要求由页面覆盖文件名，并把服务返回的 filename 仅作为其他调用方的通用能力。

不要同时解析响应头、页面拼接和组件默认名三套事实源，否则不同入口会下载出不同名称。

## 7. 跨层依赖：CORS 暴露响应头

浏览器跨域请求时，前端只有在后端 CORS 响应包含以下配置时才能读取 `Content-Disposition`：

```python
CORSMiddleware(
    ...,
    expose_headers=['Content-Disposition'],
)
```

本仓库对应的后端配套提交是 [`backend-2026-01-30-89b47c34.md`](backend-2026-01-30-89b47c34.md)，修改了 `app/main.py` 和 `app/main_refactored.py`。迁移下载工具时必须同时检查：

- 后端是否返回 `Content-Disposition`；
- 反向代理是否保留该响应头；
- CORS 是否暴露该响应头；
- Axios/fetch 适配器是否以 Blob 方式读取响应。

如果任一环节缺失，解析器会稳定地回退到默认名，但用户会误以为服务端文件名配置没有生效；这应作为可观测的集成问题处理，而不是在页面静默复制另一套解析逻辑。

## 8. 跨项目迁移步骤

1. **确认响应契约**：统一导出接口的 Blob 响应、`Content-Disposition` 格式和 fallback 文件名；优先规范化后端输出 `filename*=`，同时保留 `filename=` 兼容旧客户端。
2. **复制纯解析器**：迁移 `getFilenameFromContentDisposition` 与 `sanitizeFilename`，保留 `filename*` 优先、`filename` 回退和解码失败回退顺序。
3. **集中下载副作用**：迁移 `downloadBlob`，禁止页面重复创建 Object URL；如需新窗口预览，单独设计并标注 URL 延迟释放策略。
4. **改造服务层返回值**：导出/附件/模板服务统一返回 `{ blob, filename }`，每个服务提供业务合理的 fallback，不要让 util 写死业务名称。
5. **接入页面**：页面只负责权限、请求参数和用户提示，接收服务返回的 filename 后调用统一下载函数。
6. **打通跨域链路**：检查 CORS、代理和浏览器实际响应头；在跨域集成测试中断言能读到 `Content-Disposition`。
7. **最后清理重复实现**：搜索 `filename=`、`createObjectURL`、`a.download` 和旧 `parseFilename`，逐个迁移并删除第二事实源。

## 9. 复用风险与边界

- **解析器不是授权边界**：导出权限仍由后端 API 和前端既有权限控制负责，文件名工具不应决定是否允许下载。
- **不可信响应头**：文件名来自服务端/代理，应始终经过统一清理；不要直接把未清理值赋给 `link.download`。
- **编码兼容性**：实现只接受空/UTF-8 charset；其他 charset 会回退到普通 `filename=` 或 fallback，不要假设浏览器会自动转码。
- **正则限制**：当前解析以分号作为参数边界，复杂 RFC 参数或异常引号需在目标项目增加测试后再扩展。
- **URL 生命周期**：`downloadBlob` 立即释放 URL 适用于触发下载；如果改为新窗口/异步读取，必须延后释放。
- **文件名策略**：当前清理未覆盖所有 OS 保留字符、超长名称和 Unicode 规范化，目标项目需按部署平台补充。
- **测试缺口**：`b33e4960` 没有新增测试；CodeGraph 当前也未找到 `getFilenameFromContentDisposition` 的直接覆盖测试，只有多个 `downloadBlob` 调用方的组件测试。迁移时应先补纯函数测试。
