## 4. 提交时的 `isReadPermissionButton` 契约

提交 `c7543cf1` 中的实现等价于：

```typescript
export const isReadPermissionButton = (
  btn: Pick<FeatureTreeNode, 'FeatureName' | 'FeatureKey'>
): boolean => {
  const name = String(btn.FeatureName || '').toLowerCase()
  const key = String(btn.FeatureKey || '').toLowerCase()

  return (
    name.includes('查询') ||
    name.includes('列表') ||
    name.includes('详情') ||
    key.includes('read') ||
    key.includes('list') ||
    key.includes('detail')
  )
}
```

### 4.1 输入边界

函数只依赖两个字段：

| 字段 | 作用 | 约束 |
| --- | --- | --- |
| `FeatureName` | 中文显示名称启发式 | 空值按空字符串处理；大小写转换对中文无影响 |
| `FeatureKey` | 英文权限键启发式 | 空值按空字符串处理；先转小写，再做子串匹配 |

使用 `Pick` 而不是完整节点类型，使它可以处理来自 API、测试夹具或其他树组件的最小对象。函数不读取 `FeatureID`、`FeatureType` 或 `children`，也不修改输入对象。

### 4.2 提交基线的分类表

| 示例 | 提交基线结果 | 原因 |
| --- | --- | --- |
| `查询` / `xxx` | `true` | 名称含“查询” |
| `列表` / `xxx` | `true` | 名称含“列表” |
| `详情` / `xxx` | `true` | 名称含“详情” |
| `其他` / `module:read:list` | `true` | key 同时包含 `read`、`list` |
| `其他` / `pms:read:detail` | `true` | key 含 `detail` |
| `新建` / `pms:write:create` | `false` | 不满足任一读取条件 |
| `查看` / `customer:view` | `false`（提交当时） | 当时没有“查看”或 `view` 规则 |
| `导出列表` / `pms:read:export_list` | `true`（提交当时） | `read`/`list` 子串会命中，导出例外尚未处理 |

这里的 `includes` 是子串匹配，不是按 `:` 或 `_` 分段匹配。它能兼容旧权限键，但也可能把复合动作、导出动作或包含 `read` 片段的非读取键误判为读取按钮。迁移时应明确这是 UI 启发式，而不是授权判定。

## 5. `JsePermissionTreeEl` 中的行为闭环

该提交只替换判断来源，原有交互流程保持不变：

1. 组件保留原始树数据并建立 `nodeMap`、`parentMap`；展示树会把按钮子节点平铺到菜单行右侧。
2. `isReadButton(btn)` 现在只是 `isReadPermissionButton(btn)` 的薄包装，所有按钮状态判断走同一规则。
3. 菜单未选中时，`isButtonDisabled()` 禁用该菜单下全部按钮。
4. 菜单选中时，识别为读取按钮的按钮自动纳入选中集合并保持禁用；非读取按钮允许手工勾选。
5. `handleCheck()` 处理 Element Plus `el-tree` 的 `@check` 事件：
   - 读取完全选中的非按钮节点；
   - 菜单选中时遍历原始 `children`，把读取按钮加入 `finalChecked`；
   - 仅在父菜单仍选中的情况下保留已手工勾选的非读取按钮；
   - 通过 `update:modelValue` 输出完整 FeatureID 列表。
6. `handleButtonCheck()` 处理按钮行的 `el-checkbox`：读取按钮取消操作直接返回，非读取按钮执行增删并立即回写。

因此，按钮从展示树中隐藏并不等于从权限集合中删除：按钮 ID 仍保存在 `checkedKeys`，保存角色时仍会提交完整 `feature_ids`。迁移时必须同时保留“原始树用于判定”和“展示树用于渲染”这两份视图。

## 6. 与 RBAC 页面及服务的边界

### 6.1 角色编辑流程

`RoleDialog.vue` 的既有流程为：

```text
打开编辑角色
  -> rbacService.getRolePermissions(roleId)
  -> selectedFeatures = response.feature_ids
  -> rbacService.getFeatureTree()
  -> JsePermissionTreeEl v-model="selectedFeatures"
  -> assignRolePermissions(roleId, { feature_ids: selectedFeatures })
```

树组件只负责编辑 FeatureID 集合，不负责创建角色、调用 HTTP 或决定后端允许哪些权限。目标项目如果使用其他 RBAC 服务，只需保持“树节点 ID ↔ 保存接口 ID 列表”的契约，不要把中文按钮判断塞进服务层。

### 6.2 业务范围配置流程

`FeatureScopeDialog.vue` 也复用 `JsePermissionTreeEl`，但它会先过滤 `button`/`api` 节点，并把选中的 Feature 映射到业务范围配置。因此，迁移读取按钮规则时要确认该场景是否还存在按钮节点；不能因业务范围页面隐藏按钮，就删掉权限树对原始按钮数据的支持。

### 6.3 后端仍是安全边界

`isReadPermissionButton` 只影响默认勾选、禁用和用户体验：

- 后端必须校验角色、FeatureID、FeatureType、启用/删除状态及当前操作者权限；
- 前端隐藏或禁用按钮不能替代接口鉴权；
- 如果后端会向上补全模块/菜单权限，初始化树时仍应使用既有的最小勾选集合算法，避免级联树误勾选；
- 保存接口应以服务端返回的合法权限集合为准，不能信任前端的“读取按钮”分类。

## 8. 跨项目迁移建议

1. **先统一节点契约**：至少提供稳定的 `FeatureID`、`FeatureName`、`FeatureKey`、`FeatureType` 和 `children`；确认 ID 唯一且父子关系无环。
2. **把分类策略配置化**：优先让后端返回 `is_read_action`、`is_export_action`、`is_scope_action` 等能力字段，前端只消费能力；只有兼容旧数据时才使用名称/key 启发式。
3. **集中一个纯函数**：若仍需启发式，将规则放在共享 util，所有权限树、按钮列表和测试统一调用，避免每个组件维护不同判断。
4. **选择匹配算法**：新项目优先按权限键分段匹配（如 `resource:read:list`），并为分隔符、大小写、旧格式建立归一化边界；不要直接复制历史 `includes` 规则而不评估误判。
5. **保留完整权限集合**：展示层可以平铺/隐藏按钮，但保存状态必须保留合法按钮 ID；读取按钮是否自动授权要由后端产品契约确认。
6. **处理级联时序**：Element Plus 需要在 `nextTick` 后读取/写入勾选状态；换树组件时把“初始化勾选”和“用户变更回写”分开实现，不要直接依赖其他组件的内部 store。
7. **补测试再接页面**：先测试纯函数，再测组件的菜单选中、父菜单取消、读取按钮不可取消、非读取按钮可切换、外部 `modelValue` 同步和导出/view_all 例外。

## 9. 迁移验收清单

- [ ] `FeatureName`/`FeatureKey` 为空、大小写混合或旧格式时结果可预期。
- [ ] 查询、列表、详情、查看等读取动作与写入动作分类符合后端契约。
- [ ] 导出、下载、预览、审核、数据范围（如 `view_all`）不会被错误自动授权。
- [ ] 菜单未选中时按钮禁用；菜单选中后读取按钮自动选中且不可手动取消。
- [ ] 非读取按钮只能在父菜单选中时手工选择，取消父菜单后不会残留。
- [ ] 初始化不会因后端父级补全而误勾选未授权子菜单。
- [ ] 展示树隐藏按钮时，原始树仍可用于父级、按钮和保存集合计算。
- [ ] 组件通过 `update:modelValue` 输出完整 FeatureID，保存接口不依赖前端名称判断。
- [ ] 后端对每次实际操作执行独立鉴权，前端禁用状态不被当作安全控制。
- [ ] 纯函数和权限树组件均有回归测试；规则变更时同步更新测试样例和权限键文档。
