## 3. CodeGraph 调用链

```text
列表行点击
  -> openRouteInTab()/openDetailById(processId)
  -> getProcessDetail(processId)
  -> getWorkflowDetail(workflowId)
  -> timelineByLevel + visualStages
  -> 节点状态/审批意见/弃审信息渲染

详情操作
  -> currentDetailRow 保存列表权限上下文
  -> confirmProcess / interruptProcess / resubmitProcess
  -> 成功后关闭抽屉并刷新列表
```

CodeGraph 显示 `MyProcesses`、`PendingApprovals` 和 `ProcessMonitoring` 都将 `ProcessDetailResponse` 与 `WorkflowDetailResponse` 组装为 `visualStages`；因此节点状态映射、数值 `NodeLevel` 排序和审批意见展示必须保持一致。深链打开时没有列表行，`MyProcesses`/监控页会尝试补拉列表项，以恢复 `CanConfirm`、`CanCancel` 等操作权限上下文。

## 4. 可复用前端契约

### 4.1 可视化节点模型

将后端时间线与工作流配置合并为 UI 专用模型，不直接在模板中拼接原始响应：

```ts
type VisualWorkflowNode = {
  NodeID: string
  NodeLevel: string
  NodeName: string
  RoleName: string
  ApproverName?: string | null
  ApproveStatus: number
  ApproveComment?: string | null
  StatusText: string
  StatusBadgeClass: string
  Timestamp?: string
  isDone: boolean
  isCurrent: boolean
}
```

- `ApproveStatus=1/2/3/4/5` 分别表示待处理、同意、否决、退回、失效。
- 审批意见仅在同意、否决、退回等已处理状态展示，保留换行并避免把空意见渲染成空卡片。
- 工作流节点按 `stage.order` 数值排序；不能按字符串排序。
- `ParallelPolicy=1/2/3` 在阶段标题显示串行、AND、OR 语义，但最终推进规则仍由后端决定。

### 4.2 弃审详情

当 `ProcessStatus=7` 时，详情响应可带：

- `AbandonOperatorName`
- `AbandonTime`
- `AbandonReason`

字段缺失时显示 `—`/`-`，不能因为历史流程没有操作日志而阻断整个详情页。弃审状态来自后端权限和状态机，前端只负责条件展示。

### 4.3 详情操作与路由

- 列表页把确认发起、取消、中止等操作集中放在详情抽屉底部，避免表格操作列过载。
- 详情打开后保存 `currentDetailRow`；只依赖详情接口不足以恢复 `Can*` 操作字段。
- 确认发起前弹出二次确认；成功后关闭过期抽屉并刷新列表。
- 删除旧独立详情路由后，使用 `openRouteInTab` 或现有页面的 `processId` 深链；关闭抽屉时同步清理 query，避免返回页面重新打开旧详情。

## 5. 测试与迁移验收

`VisualWorkflowApproveComment.spec.ts` 用 Vue Test Utils + Vitest mock 服务，分别验证：

1. 流程监控详情显示已同意意见；
2. 我的流程详情显示已否决意见；
3. 待审批详情显示已退回意见。

迁移到其他项目时建议补充：

- `ProcessStatus=7` 的弃审人/时间/原因显示与空值兼容；
- 并行 AND/OR 节点的阶段分组和排序；
- 深链无列表行时的详情打开与操作按钮隐藏策略；
- 权限不足时确认/取消/中止按钮不可执行，而不是只隐藏图标；
- 路由切换后抽屉 query 清理和刷新行为。

## 6. 复用风险

- `visualStages` 在多个页面各有一份实现，迁移时应抽成纯函数或共享组件，避免状态文案漂移。
- 列表接口的 `CanConfirm/CanCancel/CanStop` 是服务层计算结果，不能由前端根据状态号自行推断。
- 移除旧路由前要检查外部链接、通知模板和浏览器书签；必要时保留重定向而不是直接 404。
- 详情页可见不等于业务数据可编辑；继续沿用后端资源授权和业务状态校验。
