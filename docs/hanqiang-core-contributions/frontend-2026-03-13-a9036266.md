## 3. 登录错误提示契约

### 3.1 提交前后的行为

提交前，`el-form` 使用 `loginRules`：

```ts
const loginRules: FormRules = {
  UserCode: [
    { required: true, message: '请输入用户编号', trigger: 'blur' },
    { pattern: /^\d{4}$/, message: '用户编号为4位数字', trigger: 'blur' }
  ],
  password: [
    { required: true, message: '请输入密码', trigger: 'blur' },
    { min: 6, message: '密码至少 6 个字符', trigger: 'blur' }
  ]
}
```

`handleSubmit()` 先调用 `loginFormRef.value.validate`，仅在 `valid=true` 时调用 `handleLogin(UserCode, password)`。因此本提交没有改变认证服务、token 保存或权限加载，只改变错误信息的布局。

### 3.2 样式修复

提交给 `el-form` 增加 `login-form` 类，并添加：

```css
.login-form .el-form-item__error {
  position: static;
  padding-top: 0.375rem;
}
```

这会让 Element Plus 的校验信息占据正常高度，输入框、错误文本和下一个表单项依次排列。迁移到其他项目时：

- 不要用固定 `top` 或绝对定位把错误信息压在输入框上。
- 若表单使用自定义布局，保留错误信息的可见、可读和键盘顺序；可用 `min-height` 防止校验前后页面跳动，但不要裁剪提示。
- `position: static` 是针对当前 Element Plus DOM 结构的覆盖；升级 Element Plus 后应检查 `.el-form-item__error` 的默认定位和 CSS 优先级。
- 错误提示文本属于产品校验契约，语言、字段名和服务端错误提示应保持一致；本提交未处理后端登录失败消息。

## 4. PMS 日期时间控件契约

### 4.1 原生控件替换

`WorkOrderForm.vue` 将两个原生输入：

```html
<input type="datetime-local" v-model="formState.planned_acceptance_time" />
<input type="datetime-local" v-model="formState.planned_date" />
```

替换为：

```vue
<el-date-picker
  v-model="formState.planned_acceptance_time"
  type="datetime"
  value-format="YYYY-MM-DD HH:mm:ss"
  format="YYYY-MM-DD HH:mm:ss"
  placeholder="请选择计划验收时间"
  class="work-order-datetime-picker planned-acceptance-picker w-full"
/>

<el-date-picker
  v-model="formState.planned_date"
  type="datetime"
  value-format="YYYY-MM-DD HH:mm:ss"
  format="YYYY-MM-DD HH:mm:ss"
  placeholder="请选择计划时间"
  class="work-order-datetime-picker w-full"
/>
```

这里有三个独立契约：

| 配置 | 作用 | 跨项目要求 |
| --- | --- | --- |
| `type="datetime"` | 使用 Element Plus 日期+时间选择器 | 确保目标项目已注册 Element Plus；不能只复制 CSS |
| `value-format="YYYY-MM-DD HH:mm:ss"` | `v-model` 直接得到稳定字符串 | 与 API schema、提交转换和时区约定一致 |
| `format="YYYY-MM-DD HH:mm:ss"` | 输入框与面板显示格式 | 不要把显示格式误当作实际 payload 格式 |

本提交的值仍写回 `PmsWorkOrderFormModel` 的 `planned_acceptance_time`/`planned_date`，父级状态同步和 API payload 归一化由既有 `useWorkOrderForm.ts`、`workOrderPayload.ts` 负责。迁移时不要在组件内再维护第二套日期状态。

### 4.2 日期和时区边界

- `value-format` 不带时区偏移，表示“本地业务时间字符串”；后端若使用 UTC，应在 API 边界显式转换，不能依赖浏览器隐式 `Date` 解析。
- 不要把 `YYYY-MM-DD HH:mm:ss` 直接交给 `new Date(string)` 并假设所有浏览器一致；需要时间计算时使用项目已有的 dayjs/解析工具。
- 清空值应保持 `''` 或 `null` 的既有模型约定，并在提交层统一转换；不要让日期控件随机产生 `Invalid Date`。
- 日期范围控件和只选日期控件也会命中全局 `.el-date-editor` 规则；若某个控件允许键盘编辑或需要可选文本，必须增加更具体的局部覆盖。

## 5. 日期控件全局样式

### 5.1 点击区域

`src/assets/common-page-styles.css` 新增：

```css
.el-date-editor,
.el-date-editor .el-input__wrapper,
.el-date-editor .el-range__icon,
.el-date-editor .el-range__close-icon,
.el-date-editor .el-input__prefix,
.el-date-editor .el-input__suffix {
  cursor: pointer;
}

.el-date-editor .el-input__inner[readonly],
.el-date-editor .el-range-input[readonly],
.el-date-editor .el-range-separator,
.el-date-editor .el-input__prefix-inner,
.el-date-editor .el-input__suffix-inner {
  cursor: pointer;
  pointer-events: none;
}
```

Element Plus 的日期输入通常是只读文本框，点击会由外层 wrapper 打开面板。将只读 inner、范围分隔符和图标内部设为 `pointer-events: none`，可避免点击落在不可交互子元素上，统一让整块 editor 响应点击。

### 5.2 全局副作用

该 CSS 通过 `src/bootstrap.ts` 全局导入，因此会影响 `DataViewTab.vue`、`ReportTaskFormDrawer.vue`、`EmailRecipientDialog.vue`、APQP 等其他日期控件。复用时要注意：

- 这是全局规则，不要在某个页面假设只有 PMS 工单会命中。
- `pointer-events: none` 只应用于只读输入、图标和范围分隔符；不要扩大到可编辑文本输入，否则会破坏键盘输入和无障碍操作。
- 自定义日期组件（如 `JseDatePicker.vue`）若有更高优先级或不同 DOM，应单独验证，不要仅凭类名推断生效。
- 全局样式应尽量只声明交互语义（光标、点击穿透）；尺寸、边框和颜色放到组件类，避免污染其他表单。

## 6. PMS 工单局部样式

`WorkOrderForm.vue` 使用 `.work-order-datetime-picker` 对 Element Plus wrapper 做视觉对齐：

- 外层和 wrapper 宽度 `100%`。
- 高度固定为 `32px`，输入内容高度/行高为 `30px`。
- 圆角 `0.375rem`，边框使用 `var(--color-form-border, #d9e0e7)`。
- 默认取消 Element Plus 阴影；hover 使用蓝色边框，focus 使用 2px 浅蓝 focus ring。
- 输入字体为 `0.875rem`，前缀/后缀图标使用 slate 色。

这些规则是“与本表单原生 text/select 输入对齐”的局部视觉契约，不应无条件复制为全局 Element Plus 主题。迁移时优先复用项目的 design token（边框色、主色、圆角、控件高度），只有缺少 token 时才使用提交中的 fallback 值。

## 9. 跨项目最小迁移方案

1. **确认组件库版本**：Element Plus 的 DOM 类名和日期格式 token 必须与目标版本一致。
2. **先定义时间契约**：明确表单内部、API payload、数据库和时区各自的格式；统一采用一个转换边界。
3. **迁移登录错误布局**：给目标登录表单加局部类，覆盖错误元素为正常文档流，检查长文本和移动端换行。
4. **替换日期控件**：用 `el-date-picker` 的 `datetime` 类型，显式设置 `value-format` 和 `format`，保留原字段名和父级 `v-model` 链路。
5. **加入全局点击规则**：只对只读日期输入及图标使用 `pointer-events: none`，确认不会影响可编辑日期输入。
6. **加入局部视觉规则**：只在需要对齐的表单上设置高度、边框和 focus ring，不把 PMS 专用类复制到全局。
7. **运行结构与交互测试**：先跑提交中的 Vitest 契约测试，再用浏览器验证真实 Element Plus 弹层和键盘行为。
