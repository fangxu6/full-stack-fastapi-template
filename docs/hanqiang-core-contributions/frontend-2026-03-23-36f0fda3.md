这是一次“共享筛选组件 + 批量页面迁移”的前端提交，核心复用价值集中在：

1. `QuickTagFilterGroup.vue` 将“全部/多个状态标签/数量”统一为受控组件。
2. `quickFilters.ts` 将选择归一化、全选判断、单值后端映射和客户端匹配集中为纯函数。
3. 旧页面的单选状态标签、启用/停用标签、树形状态筛选、训练状态筛选和 PMS 工单状态分组统一迁移。
4. 为多选状态补充了服务端单值查询、客户端过滤和服务端分页兼容策略。

提交还包含几项与筛选迁移同批落地的兼容性改动：训练列表查询参数、培训报告完成状态参数、PMS 工单状态大小写归一化、设备已有工单提示，以及 Vite ESM 路径写法。这些改动不是 `QuickTagFilterGroup` 的必要依赖，跨项目迁移时应按接口契约单独选择。

## 3. 核心组件：`QuickTagFilterGroup.vue`

文件：`frontend/JSE_UI_AI/src/components/QuickTagFilterGroup.vue`

### 3.1 输入输出契约

| 项目 | 类型/默认值 | 说明 |
| --- | --- | --- |
| `modelValue` | `QuickFilterValue[]`，必填 | 当前选中的值集合；空数组表示“全部” |
| `options` | `QuickTagFilterOption[]`，必填 | `{ label, value, count?, disabled? }` |
| `allLabel` | `string`，默认 `全部` | “全部”按钮文案 |
| `allCount` | `number \| string`，可选 | “全部”按钮数量；未传则不显示 |
| `update:modelValue` | `QuickFilterValue[]` | 始终输出按 `options` 顺序归一化后的值 |

`QuickFilterValue` 只允许 `string | number | boolean`。组件通过 `Set`、`includes` 和严格相等比较值，不支持对象、数组或需要自定义比较器的值。

### 3.2 交互状态

| `modelValue` | 视觉状态 | 点击选项后的输出 |
| --- | --- | --- |
| `[]` | “全部”和所有未禁用选项均高亮 | 点击某项 -> `[该项]` |
| 包含所有可用值 | 与 `[]` 相同，视为全选 | 点击某项 -> `[该项]` |
| 部分值 | 仅选中值高亮 | 点击未选项 -> 加入；点击已选项 -> 移除 |
| 归一化后为空 | 视为全选 | 继续点击“全部”仍输出 `[]` |

实现要点：

- `optionValues` 只收集 `disabled !== true` 的选项；禁用按钮仍渲染，但不参与全选、归一化和切换。
- `toggleAll()` 始终发出空数组，而不是发出完整选项数组；父级必须把空数组解释为“不过滤”。
- 从全选状态点击某个选项会直接切换到单选，避免用户先清空再选一项。
- 部分选择每次输出都按 `options` 原顺序排列，去除重复值和未知值。
- 组件只负责按钮和选择状态，不负责请求、分页、计数来源、权限判断或路由跳转。
- 样式依赖项目已有的 `jse-btn` 与 `jse-btn--primary` 类；迁移到其他设计系统时只需替换模板类名。

### 3.3 可直接复用的最小用法

```vue
<script setup lang="ts">
import { computed, ref } from 'vue'
import QuickTagFilterGroup from '@/components/QuickTagFilterGroup.vue'
import { resolveSingleQuickFilterValue } from '@/utils/quickFilters'

const statusValues = ['pending', 'success', 'failed'] as const
const selectedStatuses = ref<Array<(typeof statusValues)[number]>>([...statusValues])
const rows = ref<Array<{ status: (typeof statusValues)[number] }>>([])

const statusOptions = computed(() => statusValues.map((value) => ({
  value,
  label: value,
  count: rows.value.filter((row) => row.status === value).length
})))

function handleStatusChange(values: Array<string | number | boolean>) {
  selectedStatuses.value = values as Array<(typeof statusValues)[number]>
  const serverStatus = resolveSingleQuickFilterValue(selectedStatuses.value, statusValues)
  // serverStatus === null 表示全部或多选；按项目 API 约定决定服务端/客户端路径
  void serverStatus
}
</script>

<template>
  <QuickTagFilterGroup
    v-model="selectedStatuses"
    :options="statusOptions"
    :all-count="rows.length"
    @update:model-value="handleStatusChange"
  />
</template>
```

如果父组件使用 `v-model`，不需要再手动赋值；如果还要同步旧的标量筛选字段，则使用显式 handler，避免两个状态源互相覆盖。

## 4. 共享工具：`utils/quickFilters.ts`

文件：`frontend/JSE_UI_AI/src/utils/quickFilters.ts`

| 函数 | 契约 | 典型用途 |
| --- | --- | --- |
| `normalizeQuickFilterSelection(selected, options)` | 按 `options` 顺序保留合法值、去重 | 处理组件事件和外部恢复值 |
| `isAllQuickFiltersSelected(selected, options)` | 无可用选项返回 `false`；空选择或包含全部可用值返回 `true` | “全部”按钮高亮 |
| `resolveSingleQuickFilterValue(selected, options)` | 归一化后恰好一个值才返回该值，否则返回 `null` | 旧 API 只有单状态参数时 |
| `toQuickFilterSelection(selectedValue, options)` | 标量为空/未知 -> 全部值；合法标量 -> 单元素数组 | 高级筛选下拉框同步标签 |
| `hasPartialQuickFilterSelection(selected, options)` | 归一化后数量大于 0 且小于选项总数 | 需要显示“部分选中”状态时 |
| `matchesQuickFilterSelection(current, selected, options)` | 空选择、全选或归一化为空 -> `true`；否则判断当前值是否被选中 | 客户端数组/树过滤 |

### 4.1 复用边界

- `resolveSingleQuickFilterValue()` 把“多选”折叠成 `null`，它不代表后端支持多值查询；多选时必须选择客户端过滤、重复请求或后端新增 `IN` 参数。
- `matchesQuickFilterSelection()` 对未知 `currentValue` 在全选/空选择时会返回 `true`；若未知状态不应展示，先做域值校验。
- 业务值可能是 `0` 或 `false`，不要写 `if (!resolvedValue)` 判断是否为空，应使用 `resolvedValue === null`。本提交中的页面值大多为字符串，跨项目扩展到数字/布尔值时必须保留这一点。
- `options` 为空时组件不会把“全部”高亮；父级应在加载选项前决定是否渲染组件或显示空状态。
- 工具函数不触发请求，也不修改输入数组；请求副作用应保留在页面/组合式函数中。

## 5. 三种页面接入模式

### 5.1 服务端单值筛选（最省请求）

适用于后端只接受 `status`、`is_enabled` 等单值参数的列表页。提交中的审批、启停状态、备课/备考页面主要采用此模式：

```ts
const statusValues = [true, false] as const
type StatusValue = (typeof statusValues)[number]
const selected = ref<StatusValue[]>([...statusValues])

const serverStatus = computed(() =>
  resolveSingleQuickFilterValue(selected.value, statusValues)
)

async function loadList() {
  await service.list({
    is_enabled: serverStatus.value === null ? undefined : serverStatus.value
  })
}

function handleQuickFilterChange(next: Array<string | number | boolean>) {
  selected.value = normalizeQuickFilterSelection(next as StatusValue[], statusValues)
  page.value = 1
  void loadList()
}
```

语义是：单选继续使用服务端过滤；全选或多选传 `undefined`，表示服务端返回全部。若用户确实需要“启用 + 停用”之外的多选组合，不能假设服务端会自动理解数组。

高级下拉框与标签并存时，使用 `toQuickFilterSelection()` 同步：

```ts
function handleStatusSelectChange() {
  selected.value = toQuickFilterSelection(query.value.status, statusValues)
  page.value = 1
  void loadList()
}
```

### 5.2 客户端多选筛选

适用于已经加载完整集合、或后端没有多值参数但数据量可控的页面：

```ts
const filteredRows = computed(() => rows.value.filter((row) =>
  matchesQuickFilterSelection(row.status, selected.value, statusValues)
))
```

`ReportReviewPage.vue` 先按报告状态 `2/3/4` 全量拉取并合并，再按选择结果本地分页；`Department.vue` 在递归树中过滤节点，并保留“自身命中或子节点命中”的父节点。树形过滤不能只对根数组做 `filter`，否则会丢失可见路径。

### 5.3 服务端单值 + 客户端多选混合

`ImportRecords.vue`、`FileMonitor/TaskManagement.vue`、`EmailReceiveHistory.vue` 采用同一策略：

1. 恰好选中一个值：把该值作为服务端参数，使用正常分页。
2. 选中多个但不是全选：以批量大小（提交中通常为 `100`）循环拉取全部数据。
3. 把未过滤的批量结果保存到 `statusSummaryRows`，用于稳定统计数量。
4. 使用 `matchesQuickFilterSelection()` 做客户端过滤，再按当前页切片。
5. 全选：不传状态参数，直接使用服务端分页；空选择也必须按全选解释。

该模式保留了旧 API 的单值兼容性，但全量拉取的成本与数据规模成正比。可复用时应优先让后端支持 `statuses[]=...` 或逗号分隔的 `IN` 查询；在后端能力未具备前，必须设置最大批量、取消请求和超大数据量提示，避免页面在大表上长时间占用浏览器内存。

### 5.4 业务语义分组

`WorkOrderBoard.vue` 没有把每个原始状态都做成标签，而是定义：

```ts
type WorkOrderQuickGroup = 'waiting' | 'executing' | 'closed'

function resolveQuickGroup(row: WorkOrder): WorkOrderQuickGroup {
  if (row.status === '待接单') return 'waiting'
  if (String(row.status || '').trim().toLowerCase() === 'closed') return 'closed'
  return 'executing'
}
```

“执行中”在该提交中是兜底组，会吸收除“待接单”和 `closed` 外的状态（包括已接单、待审批、已完成、驳回、取消等）。这只是该页面的产品分组，不是通用状态机。迁移到其他 PMS/工单系统时应改成显式状态映射或由后端返回 `quick_group`，不要复制兜底规则。

## 7. 训练与 PMS 的附带契约

### 7.1 训练列表与报告

- `CoursePrepareManagement.vue`、`ExamPrepareManagement.vue` 将快捷状态映射到 `/training/course-prepare/v1/list` 和 `/training/exam-prepare/v1/list` 的 `course_prepare_status`/`exam_status` 参数。单选传 `0/1`，全选或多选传 `undefined`。
- 两个服务的 `getListV1()` 继续兼容 `records/items/data` 外壳，并把 `CoursePrepareStatus`/`ExamPrepareStatus` 从 `IsFinished`、`is_finished` 回填，避免页面直接依赖后端历史字段名。
- `EmployeeTrainingReportPage.vue` 的完成状态为 `0..4`：未开始、进行中/已培训、已完成、请假、旷培。全选不传 `completion_statuses`，部分选择按逗号连接，例如 `1,2,3`；查询和导出共用同一 `buildQueryParams()`。
- `trainingEmployeeReport.service.ts` 使用自定义 `paramsSerializer`：数组参数重复追加同名键，空值不发送；`completion_statuses` 本身是逗号字符串。
- `ReportReviewPage.vue` 针对状态 `2/3/4` 并行请求并按 `submit_time` 倒序合并，再用共享工具本地过滤和分页。该方案适合状态集合固定且待批改数据量可控的页面。
- `StudentLearningPage.vue` 保留旧 API 的标量语义：同时选中 `2`、`3` 映射为 `0`（全部），只选一个则传对应状态；空选择也回到 `0`。这是兼容适配，不是通用多值协议。

### 7.2 PMS 状态与设备提示

- `WorkOrderBoard.vue` 对 `closed`、`completed` 等终态做大小写不敏感处理，避免后端返回 `Closed`/`closed` 导致徽章、完成时间和动作不一致。
- `workOrderActions.ts` 对终态和执行中/待审批判断统一 `trim().toLowerCase()`；后端仍必须返回稳定状态枚举，前端归一化只是兼容层。
- `Equipment` 类型新增 `open_work_order_type`、`open_work_order_code`；`WorkOrderCreate.vue` 在设备选项描述中显示“已存在维修/保养/验收/调试工单”。提交中的 UI 实际使用 `open_work_order_type`，`open_work_order_code` 仅作为 API 类型信息保留。
- 设备是否可选仍由 `status === 'Idle'` 决定；“已有开放工单”提示不应替代后端创建接口的并发/重复校验。

## 8. 跨项目迁移步骤

1. **确认组件宿主样式**：复制组件和工具后，确认目标项目存在 `jse-btn`、弹性布局类和 Vue 3 `v-model` 事件约定；没有则只替换样式类，不改选择算法。
2. **定义稳定值域**：为每个页面声明 `const statusValues = [...] as const`，让选项值、查询参数和过滤函数共享同一类型；不要用显示文案作为隐式状态协议。
3. **先选筛选策略**：后端支持单值时用 5.1；可控全量集合用 5.2；必须兼容旧单值 API 且允许多选时用 5.3；业务分组按 5.4 自定义映射。
4. **迁移模板**：把旧的“全部 + 多个 button”替换为一个 `<QuickTagFilterGroup>`，保留高级筛选、表格、权限按钮和分页结构。
5. **迁移状态处理**：删除旧的 `activeTab`/`setStatusFilter`，增加 `selectedStatusFilters`、`statusQuickFilterOptions` 和统一 handler；重置动作必须恢复完整值数组（或明确使用空数组语义）。
6. **同步高级筛选**：下拉框改变时调用 `toQuickFilterSelection()`；标签改变时回写旧标量字段，避免刷新后标签高亮与实际查询条件不一致。
7. **修正统计来源**：服务端单选统计可使用当前响应；客户端多选统计必须基于未过滤集合，否则切换标签后计数会自我缩小。
8. **处理分页与并发**：本地过滤后重新计算总数和页切片；批量拉取应支持加载状态、错误中断和最大记录数。长期方案优先把多值筛选下沉到后端。
9. **补可访问性**：本提交组件未输出 `aria-pressed`、键盘 roving tabindex 或部分选中指示；目标项目若有无障碍要求，应在组件层补齐，而不是在每个页面重复实现。
10. **保留后端安全边界**：筛选组件只影响列表展示和请求参数，不能替代接口鉴权、数据权限、重复工单校验或导出权限。
