## 路由与权限

```text
/scheduled-tasks (module:scheduled_task)
  ├─ /tasks (menu:scheduled_task, scheduled_task:read:list)
  └─ /logs  (menu:scheduled_task_log, scheduled_task_log:read:list)
```

按钮权限与后端保持同名：
`scheduled_task:read:detail`、`scheduled_task:write:create`、`scheduled_task:write:update`、`scheduled_task:write:toggle`、`scheduled_task:write:run`、`scheduled_task:delete:remove`、`scheduled_task_log:read:detail`。

页面使用 `usePermission().hasPermission()` 同时控制按钮 `disabled` 和 `data-permission-key`，但真正授权仍由后端依赖完成。

## 任务管理交互

1. 页面加载调用 `listTasks({page, page_size, keyword, is_enabled})`。
2. “新建”打开 `ScheduledTaskFormDialog`；“编辑”先调用 `getTask(id)`，避免列表项缺少设备/邮件变量。
3. 运行调用 `runTask(id)`，成功后若有日志详情权限立即打开 `ExecutionLogDrawer`。
4. 复制、启停、删除完成后重新加载列表；删除前使用 `ElMessageBox` 二次确认。
5. “查看日志”跳转到 `/scheduled-tasks/logs?task_id=<id>`，日志页监听 query 并自动筛选。

表单提交的 `ScheduledTaskSavePayload`：

```ts
{
  task_name, delivery_method: 'email', expression_cron,
  delivery_config: { email_config_id, email_template_id, email_address_id, variables },
  effective_date, expiry_date, is_enabled,
  advance_remind_days, equipment_ids
}
```

表单通过既有 `emailConfigService`、`emailTemplateService`、`emailRecipientService`、PMS 设备服务加载选项；设备选择器仅回传 ID，不在组件内写业务数据。

## 执行日志交互

- `listExecutions` 支持任务 ID、状态、时间范围和分页。
- 表格显示任务快照、触发来源、状态、入队/开始/结束时间、耗时和明细计数。
- `ExecutionLogDrawer` 打开时按 execution ID 请求 `getExecutionDetail`，展示执行摘要、失败摘要和明细状态/顺序/耗时。
- 状态标签映射：`pending` 待执行、`executing` 执行中、`success` 成功、`failed` 失败、`timeout` 超时；明细为 pending/success/failed/skipped。

## 类型与 API 服务契约

`src/types/scheduled-task.ts` 是前端唯一事实源：

- `ScheduledTaskType = 'pms_maintenance'`，`ScheduledTaskDeliveryMethod = 'email'`；
- 主执行状态和明细状态使用联合字面量，避免任意字符串进入 UI；
- `ScheduledTaskExecutionSummary` 与后端执行主表字段一一对应；
- `ScheduledTaskExecutionDetailResponse = { execution, details }`。

service 方法与路径：

| 方法 | HTTP |
| --- | --- |
| `listTasks/getTask` | GET `/scheduled-tasks/tasks[/{id}]` |
| `createPmsTask/updateTask` | POST `/scheduled-tasks/tasks/pms`、PUT `/scheduled-tasks/tasks/{id}` |
| `toggleTask/deleteTask/duplicateTask/runTask` | PATCH/DELETE/POST 对应任务动作 |
| `listExecutions/getExecutionDetail` | GET `/scheduled-tasks/executions[/{executionId}]` |

所有方法直接返回 `data`，错误交给 `resolveApiErrorMessage` 显示；列表组件不复制 Axios 响应解包逻辑。

## 跨项目复用步骤

1. 先复制 `types` 和 `services`，根据目标 API 调整字段命名与响应包装；类型应先于组件。
2. 把表单拆为“通用配置 + 业务范围”两段，邮件/设备选项通过 props 或 service 注入，避免写死接口。
3. 在路由、侧边栏、页面按钮同时声明权限键，并确认后端权限配置存在。
4. 列表页只负责分页和动作编排；详情抽屉只负责读取/展示，不在模板内修改执行状态。
5. 对 URL query（如 `task_id`）做字符串/数组归一化；刷新、返回和深链都应保持筛选状态。
6. 用组件测试覆盖表单 payload、错误提示、权限禁用、空列表和详情加载；再做一次手动执行到日志抽屉的 E2E。
