## 交互与数据流

```text
TaskManagement
  -> scheduledTaskService.listTasks / create/update / toggle / duplicate / run / delete
  -> FormDialog（按 task_type 生成联合 payload）
  -> 任务详情/执行抽屉

ExecutionLogManagement
  -> listExecutions 或 listExecutionTraces
  -> Trace 行展开 steps
  -> ExecutionLogDrawer(detailData 可直传，或 getExecutionDetail)
  -> retryExecution（POST，关闭网络自动重试）
```

### 表单分支

`ScheduledTaskFormDialog` 把通用字段（名称、Cron、有效期、启用、邮件配置）与 PMS 专属字段分开：

- `pms_maintenance`：`all_devices/specified_devices`、制造类型和设备选择；指定设备无 ID 时禁止提交。
- `ScheduledTaskType` 在本提交仍只有 `pms_maintenance`；Tooling、B2B_SGM、报表校验分支来自更晚提交，不应回写到本提交的复用范围。

模板详情加载后将系统变量（如 `mtplan`、`overdue_plan_count`、`upcoming_plan_count`、`${NOW_*}`）作为只读提示；用户变量通过 `variables` 字典提交。编辑时若后端返回 `specified_devices` 但没有有效设备 ID，前端回填为 `all_devices`，避免提交不可执行配置。

## 执行日志与 Trace 视图

- 日志页支持“执行记录/执行链路”切换；Trace 视图按 `task_trace_id` 聚合 steps 和状态计数。
- `ExecutionLogDrawer` 支持 `detailData` 直传，打开示例或已缓存详情时不重复请求；无 detailData 才调用 `getExecutionDetail`。
- 抽屉展示 ExecutionID、TaskID、TraceID、MessageID、触发源、耗时、聚合 JSON、错误摘要和逐条明细，并提供复制按钮。
- 失败/超时执行显示“重试”，请求完成后刷新列表；错误消息统一走 `resolveApiErrorMessage`。

## 网络与重复派发边界

```ts
const scheduledTaskDispatchRequestConfig = { disableRetry: true }
```

`runTask` 和 `retryExecution` 都会创建新的执行记录；Axios 层若对 POST 自动重试，网络超时后可能产生重复执行。因此只对这两个请求关闭自动重试，并在 UI 用 loading/确认框避免双击。其它只读 GET 可继续使用全局重试策略。

## 类型与 API 增量

- `ScheduledTaskType` 仍为 `pms_maintenance`，`ScheduledTaskSavePayload` 增加设备范围和制造类型字段。
- `ScheduledTaskExecutionSummary` 增加 `task_trace_id`；新增 `ScheduledTaskExecutionTraceItem`（steps、overall_status、计数）。
- `ScheduledTaskExecutionListParams.status` 支持单值、数组或逗号分隔字符串；增加 `trace_id`。
- service 新增 `listExecutionTraces()` 与 `retryExecution()`；列表选项 API 对 `tooling_ids` 序列化为逗号分隔查询参数。

## 跨项目复用步骤

1. 先复制类型和 service，并与后端状态/任务类型保持同一枚举；组件不要自行拼接未知字段。
2. 将 `ScheduledTaskFormDialog` 的任务专属区拆为可插拔分支，但保留一个统一提交入口和后端校验。
3. 复用 `ScheduledTaskEquipmentSelector` 的“筛选结果全选 + 已选项回显”模式，列表数据必须支持分页。
4. 日志页先实现 execution 视图，再按后端 Trace 契约增加聚合；抽屉接收 `detailData` 以减少重复网络请求。
5. 为写请求显式设置 `disableRetry`；重试按钮只对 failed/timeout 可见，并在成功后重新加载。
6. 将 `QuickTagFilterGroup`、`JseDrawerShell`、`resolveApiErrorMessage` 作为宿主 UI 基础设施依赖，不要在定时任务组件内复制。
