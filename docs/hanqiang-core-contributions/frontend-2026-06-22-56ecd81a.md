## 3. `copyToClipboard` API 契约

```ts
export async function copyToClipboard(text: string): Promise<boolean>
```

行为顺序：

1. 将输入转换为字符串；空字符串直接返回 `false`。
2. 如果存在 `navigator.clipboard.writeText`，先调用它；成功返回 `true`。
3. Clipboard API 不存在或 reject 时，且 `document.body` 可用，创建临时 readonly textarea。
4. textarea 固定定位到屏幕外、聚焦、全选并执行 `document.execCommand('copy')`。
5. 无论成功、失败还是异常，都在 `finally` 删除临时 textarea；返回命令结果，异常返回 `false`。
6. 在 SSR、Web Worker 或没有 DOM body 的环境中返回 `false`，不抛出浏览器引用异常。

该函数只负责复制，不负责 toast、权限提示、埋点或业务文案；调用方根据 `true/false` 决定“已复制”或“复制失败，请手动复制”。

## 5. 浏览器与安全上下文边界

### 5.1 Clipboard API

`navigator.clipboard` 通常要求 HTTPS、localhost 或浏览器允许的安全上下文，并可能受 Permissions Policy、用户手势和浏览器权限拒绝。工具捕获 reject 后再走兼容路径，不能把 API reject 当作“文本未复制”的唯一事实，最终仍以 fallback 返回值为准。

### 5.2 textarea 降级

降级 textarea 设置 `readonly`、屏幕外固定定位、透明度为 0，并在 finally 中移除。它避免把内容长期留在 DOM，但复制内容仍可能包含日志、URL、业务数据或个人信息；调用方必须只复制用户明确选择的文本，不要把 Token、Secret、Authorization 或未脱敏响应放入复制按钮。

`document.execCommand('copy')` 已被现代浏览器标记为过时能力，适合作为短期兼容层；新项目应监控 fallback 使用率，并在目标浏览器矩阵允许时逐步移除，而不是依赖它实现复杂剪贴板格式。

## 7. 测试契约

新增 `src/utils/__tests__/clipboard.spec.ts`：

```ts
it('uses Clipboard API when browser allows direct write', ...)
it('falls back to textarea copy when Clipboard API is unavailable', ...)
it('falls back to textarea copy when Clipboard API rejects', ...)
```

测试验证：

- Clipboard API 成功时只调用 `writeText`；
- API 缺失时调用 `execCommand('copy')`；
- API reject 时仍执行 fallback；
- fallback 完成后临时 textarea 已从 DOM 移除。

跨项目还应补充空字符串、`document.body` 缺失、`execCommand` 抛异常、超长文本、emoji/换行、Safari/移动端用户手势和 SSR 构建测试。不要在测试中写入真实凭证或生产日志内容。

## 8. 跨项目迁移步骤

1. 在 `utils/clipboard` 建立唯一 `Promise<boolean>` 入口，先定义空输入、API reject 和 DOM 不可用的结果。
2. 全仓搜索 `navigator.clipboard.writeText`、`document.execCommand('copy')` 和重复 textarea 实现，替换为统一工具。
3. 保持业务调用方自己的空值检查、loading/禁用和成功/失败文案；不要把 UI 依赖放进底层工具。
4. 为 Clipboard API 成功、不可用、reject 和 fallback 清理增加单元测试，并在真实浏览器矩阵验证安全上下文行为。
5. 对复制内容做数据分级；敏感字段只显示脱敏值，禁止提供 Token/Secret 一键复制。
6. 统计 fallback 触发率和失败率，确认目标浏览器支持后再评估删除 `execCommand`。

## 9. 不能原样复制的历史行为

- fallback 依赖 `document.execCommand`，不是长期现代 API；需要富文本、图片或多格式剪贴板时应单独设计 ClipboardItem 权限和降级策略。
- 工具把任意输入转换为字符串，调用方若传入对象会得到 `[object Object]`；需要 JSON 时应先 `JSON.stringify` 并明确脱敏。
- `void`/忽略 reject 只适用于工具内部已经返回布尔值的实现；业务调用方不能再无视返回值后显示成功。
- 临时 textarea 选区操作依赖用户代理；移动端或无用户手势场景可能失败，必须保留手动复制提示。
- 复制函数不做权限校验。页面、路由守卫和后端 API 仍是日志/配置数据的访问控制边界。
