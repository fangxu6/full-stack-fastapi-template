## 可复用契约

- 端点生命周期为 `registered -> verified -> retired`；只有 `verified` 才能启用通信。
- 记录定位始终使用 `owner_service_code + direction + event_id`，不能只用 `event_id`；完整载荷单独读取。
- service 层统一处理响应 `{data: ...}` 和裸响应，所有路径参数使用 `encodeURIComponent`。
- 列表页只编排查询、权限和动作；详情抽屉只读取/展示并发出 `retry/archive/restore` 事件。
- 端点表单在提交边界校验 HTTP(S) 基础地址和受控 CIDR；保存/验证后用返回的新版本替换行，避免旧列表请求覆盖新状态。

## 跨项目复用步骤

1. 先复制 `types/serviceCommunication.ts` 和 service，再按目标项目的响应包装调整 `unwrapResponse`；不要在每个页面重复解包。
2. 复用 `ServiceEndpointManagement` 的 `expected_version`、原因必填和 CIDR 校验；后端仍是最终校验者。
3. 把列表页、详情抽屉和状态映射作为独立组件接入目标路由；按钮权限同时写入 `usePermission` 与 `data-permission-key`。
4. 若目标项目没有 `/internal` 代理，显式返回 404，不能把内部事件入口暴露给浏览器。
