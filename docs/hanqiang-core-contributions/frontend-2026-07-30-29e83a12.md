## 请求与状态行为

### 列表页

提交前，角色页和工作流页会为“总数/启用/停用”并发发起三次小分页列表请求；提交后每次进入页面或筛选只调用一次 `listRoles`/`listWorkflows`，直接读取后端 `res.statistics`。状态切换成功后调用完整 `fetchRoles()`/`fetchWorkflows()`，让当前行、分页总数和启用/停用统计来自同一份服务端快照。

列表接口约定：

```ts
interface ApprovalListStatistics {
  total: number
  enabled: number
  disabled: number
}
```

该类型同时挂载到 `ApproveRoleListResponse` 和 `WorkflowListResponse`。顶层 `total` 仍是当前筛选结果的分页总数，统计对象用于全局状态卡片；页面不再用当前页数据估算统计。

### 工作流弹窗选项

- 首次进入 `WorkflowConfig` 只加载工作流列表。
- 打开新建或编辑弹窗时，`loadWorkflowDialogOptions()` 才加载功能模块和启用的流程管理员角色，并用 loading 标志避免重复请求。
- 功能模块接口的分页大小从 500 调整为 100，循环分页直到返回数量小于页大小；迁移时应按目标 API 的上限调整，而不是一次性拉取未知规模数据。

## 跨项目复用步骤

1. 先在共享类型文件定义 `ApprovalListStatistics`，将列表响应的统计字段设为必填。
2. 页面只保留一个列表请求；成功响应同时更新 `items`、顶层 `total` 和 `statistics`。
3. 状态更新、删除或保存后重新请求列表，不要只修改当前行再单独刷新统计。
4. 把低频的下拉选项放进弹窗打开处理器；用 `loading` 和“已有数据”条件防止重复加载。
5. 分页请求遵守后端上限（本提交为 100），并在测试中固定 query 参数和统计展示。
6. 若目标项目没有 TypeScript，可保留同名 JSON 契约；不要把统计查询复制回浏览器端。
