## 系统用户展示契约

共享工具将系统自动操作的身份规则集中为一个事实源：

```ts
SYSTEM_USER_ID = '00000000-0000-0000-0000-000000000000'
SYSTEM_USER_LABEL = '系统'
isSystemUserId(value) // trim + lowercase 后精确匹配
```

- 只有全零 UUID 被识别为系统用户；`00000000-0000-0000-0000-000000000001` 等相似值仍按普通未知 ID 处理。
- `isSystemUserId` 接受 `null`、`undefined` 和带首尾空白的输入；比较前统一转字符串、去空白并转小写。
- `resolvePmsUserDisplayName` 先判断系统用户，再按 `displayName → userName → userCode → userId → fallback` 回退；系统用户即使带有错误的姓名/工号映射，也始终显示“系统”。
- `SYSTEM_USER_IDS` 使用 `ReadonlySet` 保存规则，便于目标项目增加明确的系统账号 ID；不要在页面中复制 UUID 判断。
- `PMS_SYSTEM_OPERATOR_ID`、`PMS_SYSTEM_OPERATOR_LABEL` 和 `isPmsSystemOperatorId` 继续指向通用规则，已有 PMS 调用方无需改接口。

页面的本地格式化函数（`Department.formatUserDisplayById`、`Roles.getUserCode`、`TemplateList.formatUserDisplayById`）都先调用 `isSystemUserId`，再查用户选项映射。普通用户仍保留原有展示或 ID 回退，不因本次修复隐藏未知数据。

## CodeGraph 调用链证据

```text
Department.mapDepartmentsToNodes
  -> formatUserDisplayById
     -> isSystemUserId / SYSTEM_USER_LABEL

Roles.loadRoles
  -> getUserCode(CreatorID / UpdaterID)
     -> isSystemUserId / SYSTEM_USER_LABEL

APQP TemplateList
  -> formatUserDisplayById(CreateUserID / UpdateUserID)
     -> isSystemUserId / SYSTEM_USER_LABEL

PMS progress / tooling / 其它用户展示入口
  -> resolvePmsUserDisplayName
     -> isSystemUserId
```

CodeGraph 当前调用图还显示 `ConfigManagement` 等页面直接复用 `isSystemUserId`/`SYSTEM_USER_LABEL`，说明该工具适合作为跨模块公共依赖；迁移时应让所有用户展示入口依赖共享工具，而不是各页维护自己的系统 ID 常量。

## 测试覆盖

- 工具测试验证全零 UUID（含空白）识别为系统、相似但非全零 UUID 不识别、空值处理，以及系统用户优先级和普通用户回退顺序。
- Department、Roles、TemplateList 页面测试均注入错误的系统用户映射，断言最终仍显示“系统”，且页面文本不泄漏全零 UUID。
- 页面测试同时验证历史/未知用户 ID 原样回退，避免把“系统用户修复”扩大成静默隐藏数据。

## 跨项目复用步骤

1. 在共享前端工具中定义系统用户 ID、展示标签和规范化比较函数；业务页面只调用 `isSystemUserId` 或 `resolvePmsUserDisplayName`。
2. 先在所有创建人、修改人、审批操作者和进度记录展示入口接入系统用户判断，再保留原有普通用户映射与未知 ID 回退。
3. 若已有 PMS 专用常量，改为通用常量的别名，避免同时维护两套系统身份规则。
4. 使用 `ReadonlySet` 管理明确允许的系统 ID；新增 ID 必须有业务依据和单元测试，不要把任意空值或 UUID 前缀当作系统用户。
5. 测试至少覆盖：全零 UUID、首尾空白/大小写、相似非全零 UUID、错误映射优先级、普通未知 ID 回退和页面文本不泄漏内部 ID。

## 历史边界

- 本提交只改变前端身份展示和共享工具兼容层，不改变后端用户数据、权限判断、审批状态机或 API 字段。
- “系统”是展示标签，不代表新增用户记录；系统用户 ID 仍按后端既有约定传输和审计。
- `SYSTEM_USER_IDS` 当前只包含全零 UUID；扩展集合可能改变展示结果，必须同步产品约定和测试。
- 页面本地格式化函数仍各自存在；复用时可先保持薄适配，只有展示入口足够多且签名稳定时再进一步统一调用。
