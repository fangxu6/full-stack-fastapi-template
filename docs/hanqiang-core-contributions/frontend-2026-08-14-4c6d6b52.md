## 功能与数据流

```text
路由 /approve/external-integrations
  -> ExternalIntegrationCenter (权限 external_integration:manage)
  -> useExternalIntegrationRecords
     -> configs / callbacks / logs / attempts / auth-reject-statistics
  -> externalIntegrationService
     -> /api/system/config/external-integrations/*
```

- 页面首次加载并发读取五类数据；筛选重置日志和网络尝试分页后重新加载相关集合。
- 配置/回调保存、Key 轮换、退休和连接测试均经过统一 service；错误由页面统一转换，服务层不弹全局业务错误。
- 日志和网络尝试支持分页、按配置/回调/TraceID/错误分类筛选；认证拒绝统计独立按时间窗口查询。
- API 返回 `{ code, data }` envelope，service 只向页面暴露 `data`，避免组件感知传输层包装。
- 设备管理页只保留其设备快照和集成相关字段；外部集成中心不直接耦合设备页面状态。

## 复用边界

外部集成中心应拆为四个可替换边界：

1. `externalIntegrationService`：替换 API 前缀和请求客户端即可迁移；保留 `disableRetry` 语义。
2. `externalIntegrationUi`/组件：替换 UI 库，保持表单状态、筛选字段和动作事件不变。
3. `useExternalIntegrationRecords`：替换分页与错误提示适配，保留并发加载和状态集中所有权。
4. 路由/权限：将 `external_integration:manage` 映射到目标项目权限系统，不在页面硬编码管理员身份。

不要复制设备管理页的业务查询到集成中心；设备 ID、编码和快照只作为 API 预览/测试上下文传入。

## 跨项目复用步骤

1. 先复制类型和 service 契约，再接入页面；所有 API 调用通过同一 service，统一解包 `{ code, data }`。
2. 将配置、回调、日志、尝试和统计分别建成可分页的响应模型；筛选状态只由 composable 持有。
3. 用一项权限控制管理中心入口和所有写操作；后端仍必须重复鉴权。
4. 弹窗采用受控 `v-model`，保存成功后只刷新相关集合，避免整页状态被局部组件覆盖。
5. 测试至少固定请求次数、URL、查询参数、错误分支和路由入口；设备上下文通过参数适配而非复制设备模块。
