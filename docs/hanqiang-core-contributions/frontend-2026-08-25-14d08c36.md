## 事件路由契约（本提交时）

| 场景 | `scenario_code` | `contract_code` | 事件映射字段 |
| --- | --- | --- | --- |
| FT 非 FT-Tester 状态变更 | `ft_equipment_status_non_tester` | `pms.equipment-status.changed.v1` | 制造类型、设备 ID/编码/名称、类型、资产编码、序列号、旧/新主状态、旧/新明细状态、旧/新状态桶、更新来源及 ID |
| FT-Tester 状态变更 | `ft_equipment_status_tester` | `pms.equipment-status.changed.v1` | 同状态变更 contract；字段语义由 Tester 设备事实决定 |
| FT 设备绑定关系变更 | `ft_equipment_binding_changed` | `pms.equipment-binding.changed.v1` | 制造类型、变更类型、绑定 ID、来源类型及 ID |

- 回调类型固定为 `outbound_event`，制造类型由 UI 设为 `FT` 且不可编辑。
- 场景下拉选项是 contract 的唯一来源；场景切换会清除 `eventMappings`/`event_mappings`，避免旧 contract 的字段泄漏。
- 事件 Profile 的响应结果映射可为空；出站查询仍要求 `equipment_code` 和 `mes_state`。
- Header 值除 JSON 字符串外，还可保留以 `{% ... %}` 包围的原始模板表达式；该表达式不会被 JSON 二次解析。
- 保存时只写规范键 `eventMappings`，同时删除旧别名 `event_mappings`；预览和审计展示不应回显敏感绑定。

## 可迁移的组件契约

### 回调表单

`ExternalIntegrationCallbackEditorForm` 仍是受控表单，页面通过暴露的 `buildExecutionTemplate()` 完成保存前校验。类型切换规则应保持：

| 类型 | contract/场景 | Profile |
| --- | --- | --- |
| `outbound_event` | 由场景选项决定，制造类型固定 `FT` | 必填 URL/HTTP 配置；结果映射可选；可维护事件映射 |
| `outbound_query` | `pms.equipment-status.query.v1` + `query` | 必填 URL/HTTP 配置和查询结果映射；清除事件映射 |
| `inbound_query` / `inbound_write` | 固定入站 contract + `query` | 显式空对象 `{}`，不进入 Profile 编辑器 |

关闭或切换类型时必须清空仅属于事件的映射；编辑已有事件回调时不能因为打开 Profile 而清掉 `match_condition`。

### 审计投影

事件日志与网络尝试详情同时保留三类事实：原始事件报文（映射前）、映射命中/未命中摘要、投递租期。入站日志仍显示处理租期。这样排查“PMS 原始值、外部目标值、是否过期”时不会把不同事实合成一个字段。

## 从查询路由迁移的最小步骤

1. 在类型定义中增加 `outbound_event` 和事件审计字段，先不改变已有查询/入站载荷。
2. 建立场景到 contract 的白名单；场景切换时清除旧映射，并在保存前重新校验字段属于当前 contract。
3. 将事件映射放入 Profile 的受控行编辑器，写回单一 `eventMappings` 键；不要把映射逻辑散落到页面或请求 service。
4. 对事件 Profile 放宽结果映射必填规则，对查询 Profile 保持原规则；两种 Profile 共用 URL、Header、Body、状态码和脱敏校验。
5. 将事件上下文加入只读审计/尝试详情；原始报文与映射摘要分栏展示，租期标签按日志类型区分。
6. 为创建、编辑、场景切换、类型切换和事件/查询 Profile 分别写最小组件/页面测试。
