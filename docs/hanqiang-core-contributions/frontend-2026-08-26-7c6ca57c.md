## 场景变量目录（本提交时）

三种场景都提供事件信封基础变量：

`EventID`、`EventTime`、`EventType`、`EventVersion`、`EventPayload`、`EventData`、`LogID`、`TraceID`、`IdempotencyKey`。

| 场景 | 额外变量 | 复用注意 |
| --- | --- | --- |
| `ft_equipment_status_non_tester` | `ManufactureTypeCode`、`EquipmentID`、`EquipmentCode`、`EquipmentName`、`EquipmentTypeCode`、`EquipmentTypeName`、`OldMainStatus`、`NewMainStatus`、`OldDetailStatus`、`NewDetailStatus`、`StatusChangedFields`、`UpdateSourceType`、`UpdateSourceID` | 状态变更前后值允许为 `null`；更新来源只来自受控业务来源 |
| `ft_equipment_status_tester` | 与非 Tester 状态场景同名的变量集合 | 设备事实为 FT-Tester，类型名称和值由 Tester 设备决定 |
| `ft_equipment_binding_changed` | `FTBindingID`、`ChangeType`、`SourceType`、`SourceID`、`TesterStatus`；`$.EventData.AfterBinding.*` 与 `$.EventData.BeforeBinding.*` 下的主设备/子设备编码和型号 | `ChangeType` 取绑定、换绑、解绑语义；路径变量用于直接取绑定前后快照 |

变量帮助只是编辑提示，真正可用变量仍由后端 Profile 白名单校验。`EventPayload` 是完整信封对象，`EventData` 是业务数据对象；不要在目标系统只需要业务字段时误传整个信封。

## Profile 行为契约

- `ExternalIntegrationHttpProfileEditor` 接收 `eventScenario`，composable 通过 computed 返回目录；切换场景会立即刷新帮助表，不复制第二份状态。
- 事件 Profile 隐藏通用查询的默认 Body 示例折叠区，避免把 `TXN_ID`、`REPLY_SUBJECT` 等查询示例误用于事件回调。
- 绑定事件的映射字段目录同时包含 `TesterStatus`；状态事件不会显示绑定字段。
- 事件 Profile 的响应结果映射仍是可选项；本提交不改变 URL、Header、Body、脱敏或敏感绑定保护规则。

## 跨项目迁移步骤

1. 把变量说明定义为纯数据表，键使用稳定的场景码，不在组件模板中硬编码占位符。
2. 从页面把 `scenario_code` 透传到 Profile 编辑器，再由 composable 通过 computed 选择目录。
3. 为每个场景同时定义“事件信封变量”和“业务变量”；缺失场景回退到通用查询目录或显式空目录，不能把上一场景的列表留在 UI。
4. 把变量目录与后端允许集合做一次契约校对；前端帮助不能扩大后端白名单。
5. 对只读帮助、默认 Body 和映射字段分别写场景测试，至少验证正向变量存在、相邻场景变量不存在。
