# prod：配置、密钥、Redis 与分布式锁

## 目标与非目标

统一配置来源、密钥加载、Redis 连接和跨进程协调。非目标是把 Redis 变成所有业务事实的数据库，或提供没有消费者的通用锁平台。

## 启动条件、所有权与边界

配置由应用设置层拥有，业务模块只消费已验证的设置；Redis 由缓存、限流、一次性令牌、锁和 Broker 按用途使用。密钥来自 Secret manager 或环境注入，配置文件只保存非敏感示例。

## 契约与安全

启动时 fail fast 校验数据库 URL、JWT/Fernet 密钥和生产必填配置；日志只记录来源与版本，不记录正文。Redis URL、TLS、ACL、超时和 key prefix 必须显式配置，环境隔离。锁键含应用、环境、资源和版本，锁必须有 TTL，持有者丢失可恢复。

## 状态与权限边界

配置状态以环境发布版本为准，密钥轮换保留旧版本兼容窗口；只有受控运维身份可读取或切换 Secret 引用，业务请求和普通管理员不得读取密钥正文或修改 Redis 连接参数。

## 幂等、并发与失败恢复

Token 刷新、缓存预热和初始化使用明确锁边界；获得锁失败不能静默执行竞争写入。缓存失效可回源时回源，否则按安全策略拒绝。锁不是数据库事务替代品，最终事实仍写 PostgreSQL；锁过期后的旧 Worker 必须用条件更新拒绝覆盖新结果。

## 观测、迁移与发布

记录配置校验结果、Redis 连接失败、锁竞争和过期次数，按 key 类型聚合而不输出敏感 key。密钥轮换先支持新旧版本读取，再重加密/切换，确认无旧密文后移除旧版本。发布先在隔离 namespace 验证，回滚保留兼容密钥和旧 URL 解析。

## 测试验收

覆盖环境/YAML/Secret 优先级、缺失密钥启动失败、TLS、Redis 不可用、锁超时、重复刷新、旧持有者和 key prefix 隔离。验收不得把框架默认优先级当作契约。
