# prod：Durable 异步投递

## 目标与非目标

把可恢复副作用从请求事务中解耦，并区分“已入队”“执行中”和“业务完成”。非目标是以 Celery/Broker 回执替代 PostgreSQL 业务事实，或把所有任务都抽成万能执行器。

## 所有权与状态

业务模块保存任务/Outbox 事实；Worker 只消费 ID 或 JSON 上下文并重新读取数据库。最小投递状态由具体能力定义，至少区分 pending、leased/running、retry_wait、delivered/succeeded、failed；状态迁移只能由拥有者执行。

## 幂等、租约与恢复

写入事实和发布动作采用 Outbox 或等价事务边界；发布成功不等于执行成功。Worker 用租约、条件更新和幂等键防止重复副作用；租约过期可回收，固定参数错误进入终态，瞬时错误指数退避，超过上限进入人工恢复/死信。

## 安全与配置

任务载荷不放密钥、完整文件或不可序列化对象；Broker、结果后端、并发、预取和超时均配置化。外部发送经过白名单 Adapter，重试需防止重复邮件、通知或文件写入。

## 观测、测试、发布与回滚

记录 task ID、业务 ID、attempt、状态和错误类别，关联 Request ID/Trace；告警区分堆积、租约过期、失败率和死信。验收覆盖发布失败、Worker 崩溃、重复消息、超时、重试、回收和最终一致性。发布先兼容旧载荷，回滚保留可消费的旧状态和任务版本。

## 来源与禁止复制

来源：[`5b298070`](../backend-2025-12-02-5b298070.md)、[`9158d8fe`](../backend-2025-12-03-9158d8fe.md)、[`eb990317`](../backend-2025-12-03-eb990317.md)、[`080c5f54`](../backend-2025-12-10-080c5f54.md)。当前模板优先复用 `EmailOutbox`、Celery 和既有任务约束。

禁止把 `send_task()` 成功写成业务成功、让任务携带 ORM/session、用进程内全局 event loop 跨任务复用，或为没有消费者的任务类型预建注册表。
