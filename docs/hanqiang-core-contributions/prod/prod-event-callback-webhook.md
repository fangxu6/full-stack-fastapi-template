# prod：事件回调与最小 Webhook

## 决策与启动门槛

`candidate`，但只有至少一个真实领域事件和一个明确消费者时启动。第一版只支持一个版本化事件信封和一个经服务端验证的出站 Webhook Adapter；复杂编排、任意脚本和可视化规则编辑器不在首版。

## 目标与非目标

目标是提供提交后、可审计、可重试的事件投递接缝。非目标是任意 Python 执行、通用脚本平台、完整规则语言、级联编排或把外部 HTTP 成功当作业务事实。

## 所有权与事件契约

业务模块拥有事件语义、资源 ID 和最小快照；平台事件模块拥有事件记录、订阅、投递尝试和重放。事件信封必须有 event_id、event_type、occurred_at、producer、resource、schema_version、trace/request ID 和 idempotency key；payload 遵循最小化和脱敏原则。

## 状态、幂等与并发

业务写入和事件登记在同一事务，提交失败不投递。投递记录通过唯一键/条件更新和租约防重；`pending -> leased -> delivered|retry_wait|failed` 由平台管理。Subscriber 以 event_id/键去重，旧 Worker 不得覆盖新租约结果，重放创建新 attempt 而非篡改审计历史。

## Webhook 安全

URL/HTTP Profile 只允许管理员配置，验证协议、解析 IP、端口、重定向、DNS 重绑定、超时、响应大小、出口策略和签名。请求签名/时间窗防重放，Secret 只从密钥管理引用；日志只保留脱敏 headers、摘要和状态码。入站 Webhook 另立任务，需固定路由、认证、限流和请求幂等。

## 观测、发布、回滚与验收

记录事件、订阅、endpoint profile、attempt、延迟、状态和错误类别，并对积压、失败率、重试耗尽和 SSRF 拒绝告警。测试覆盖事务回滚、重复消息、租约过期、超时、5xx、签名、SSRF、敏感脱敏和订阅停用。发布先单事件/单消费者并可关闭订阅；回滚停投递但保留事件和审计。

## 下一任务拆分与运维检查

立项任务至少拆为事件信封/Outbox、单一订阅、受控 Webhook Adapter、投递尝试与人工重放、管理查询和生成 client；运维检查积压、租约过期、重试耗尽、签名失败和 SSRF 拒绝。没有真实事件与消费者时只维护本入口，不创建占位事件表或 Webhook UI。

## 迁移与兼容

先增加事件/投递记录和只读审计，再启用单一订阅；事件信封和 schema 版本向后兼容，停用订阅不删除历史事件。回滚只关闭新投递，保留可审计的事件和 attempt 记录。
