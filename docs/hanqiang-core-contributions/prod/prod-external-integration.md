# prod：外部集成中心

## 决策与启动门槛

`defer`。依赖稳定的事件日志、至少一个固定外部契约和已验证的密钥治理。它不是“任意 HTTP 配置器”；没有消费者时只维护本入口，不增加代码或 UI。

## 目标与非目标

管理版本化入站/出站集成 Profile、事件路由、条件和投递审计。非目标是复制 FT 设备、区域等业务字段，或允许用户配置任意函数、表达式、URL 和 Header。

## 契约、所有权与安全

集成中心拥有 Profile、版本、启停和 endpoint 绑定；领域模块拥有事件定义。服务端发布固定 schema、字段目录和条件运算符，前端编辑器只消费白名单元数据。凭据不可回显，URL 进行 SSRF、协议、端口、重定向、大小和超时限制。

## 状态、幂等与失败恢复

入站使用认证、幂等键和处理租约；出站依赖事件/Outbox，投递记录区分 pending、attempt、delivered、retry_wait、failed/dead-letter。版本更新不改变运行中投递的快照，重复事件不重复非幂等副作用，人工重放产生可追踪的新 attempt。

## 观测、迁移、测试与发布

审计 Profile 变更、事件、条件版本、endpoint、attempt 和结果；指标覆盖匹配/跳过、延迟、失败、重试和安全拒绝。测试覆盖严格 JSON、未知字段/运算符、版本冲突、入站重复、出站超时、SSRF、签名和脱敏。灰度单一场景，回滚停用新版本并保留旧契约和历史记录。

## 启动门槛、后续拆分与运维检查

只有稳定事件内核、固定外部契约、密钥 owner 和首个场景确认后才建独立任务；任务至少拆为契约/schema、Profile 版本、入站幂等、出站投递、条件白名单和管理查询。运维检查匹配/跳过、积压、重试耗尽、版本冲突和安全拒绝；此前禁止创建任意 HTTP 配置器或占位集成菜单。
