# prod：IAM 与权限导航

## 目标与非目标

提供服务端唯一授权事实源，并让前端路由、菜单和按钮使用同一权限键。非目标是复制历史数据库表名、业务人事模型或让前端承担授权。

## 启动条件、所有权与边界

模板已有 `backend/app/models/iam.py`、`backend/app/modules/iam/`、审计模块和前端集中式路由/导航边界；新能力默认复用它们。IAM 拥有用户、角色、权限和授权判断，业务模块只声明权限并保护自己的端点。

## 数据与状态契约

权限编码必须稳定、唯一、可审计；角色启停、用户角色绑定和权限变更不能绕过服务层。删除采用明确的软删除或撤销策略，系统角色不可被普通管理员破坏。权限匹配默认精确，层级/通配继承必须是显式产品决策。

## API、前端与权限契约

后端端点通过现有依赖执行认证和权限检查；前端继续使用生成客户端、集中 guards、navigation config 和纯权限 predicate。路由保护与菜单可见性必须对齐，但按钮可拥有比页面更窄的动作权限。返回 401 表示未认证，403 表示已认证但无权。

## 安全、幂等与恢复

授权失败不得泄露资源存在性；权限缓存必须有明确失效边界，权限变更后不能长期使用旧授权。初始化数据以版本化、幂等迁移完成，重复导入不重复创建权限。缓存或权限服务异常时按安全策略 fail closed，不能用前端标记放行。

## 审计与运维

记录角色、权限、绑定和管理员操作，关联操作者与 Request ID；监控授权失败、权限缓存命中率和初始化版本。告警不得包含令牌或敏感用户资料。

## 配置与环境

权限键、系统角色、缓存 TTL 和兼容别名按版本化配置/迁移管理；环境差异不得通过前端常量放宽授权，初始化配置不包含密码、令牌或个人敏感资料。

## 迁移、测试、发布与回滚

先迁移权限键和服务端端点，再迁移菜单/路由，最后删除兼容别名。验收覆盖匿名、无权、授权、角色停用、缓存失效、重复初始化和前后端菜单一致性。发布采用向后兼容权限键窗口；回滚保留旧键映射，禁止回滚后开放越权路径。
