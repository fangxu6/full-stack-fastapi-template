# prod：后端模块分层与依赖边界

## 决策与适用条件

`reuse-existing`。这是代码治理能力，不是新的业务运行时。适用于新模块、跨层重构和需要异步/外部依赖的功能；当前模板按 `core`、`infra`、`modules`、`services` 和路由边界承载它。

## 目标与非目标

目标是让路由负责 HTTP 契约，服务负责用例编排，仓储/CRUD 负责持久化访问，Adapter 负责外部依赖，任务只负责调度和恢复。非目标是为了目录整齐拆出单一实现的工厂、Mixin 或空壳接口。

## 所有权与事务契约

每个领域模块拥有自己的模型、状态和事务边界；服务可以组合仓储，但不得绕过授权和仓储直接散落 SQL。事务提交由用例边界决定，嵌套服务不得隐式提交；外部副作用必须在提交后经 Outbox/任务执行。依赖注入集中在 dependencies，生产代码不依赖全局可变 session。

## 幂等、并发与失败恢复

写用例使用数据库唯一约束、条件更新或领域锁定义幂等边界；跨模块调用只传稳定 ID/DTO，失败按错误类别返回并由上层决定重试。重构期间保留旧入口或兼容适配，避免同一事实由两个模块重复写入。

## 安全、失败与观测

模块边界不能绕过 IAM、租户过滤、输入校验、错误映射或审计。外部调用设置超时和错误分类，任务载荷只传 ID/JSON。记录用例、资源、耗时、异常类别和 trace，禁止把拆分后的内部对象或密钥写入响应/日志。

## 测试、发布与回滚

测试覆盖路由到服务到仓储的调用链、事务回滚、依赖替换、外部 Adapter 失败和任务重试；重构先保留行为测试，再移动依赖，最后删除旧入口。发布按模块灰度，回滚恢复旧 import/调用入口，不在重构中混入业务字段或数据库变更。

## 迁移与运维检查

代码迁移先保持 API 和数据行为兼容，再切换依赖入口；若涉及 schema，单独执行可回滚迁移和兼容窗口。运维检查跨层错误映射、事务耗时、外部依赖失败、重复写入和旧入口调用量，确认稳定后再删除兼容层。
