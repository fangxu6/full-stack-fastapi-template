# prod：通用枚举与参考数据

## 目标与非目标

为跨页面使用的稳定代码/标签提供受控查询、管理、缓存和审计。非目标是把业务实体、可变配置或租户策略全部塞进一张万能枚举表。

## 启动条件、所有权与数据契约

只有至少两个消费者、稳定机器键和清晰作用域时才立项。参考数据拥有者定义 code、label、排序、启停、父子关系、作用域和系统项规则；数据库约束保证业务键、层级和外键完整性，软删除复用策略必须明确。

## 状态与权限边界

参考项状态至少区分启用、停用和已被引用的历史项；读权限、管理写权限和系统项保护分离，租户/作用域由服务端过滤。停用不等于物理删除，已落库的业务快照不能因标签改名而改变历史含义。

## API、权限与缓存

业务下拉使用范围受限的列表接口，管理页使用全量/树接口；读权限和管理写权限分离，系统项保护必须比普通更新更窄。缓存键包含应用、环境、租户/作用域和版本；失效失败可回源时不得影响正确性。

## 并发、安全与审计

写前校验不能替代数据库唯一约束；父节点更新、禁用和删除采用事务及条件更新，拒绝孤儿和陈旧覆盖。记录创建、改名、启停、排序和系统属性变化，查询不得跨租户泄露。

## 迁移、测试与回滚

先建表和基础数据，再上线只读 API，最后启用管理写入；迁移必须可重复且不在启动时隐式写生产数据。测试覆盖权限分层、重复键、并发写、树完整性、缓存回源、租户过滤和旧客户端字段兼容。回滚保留旧查询契约，不把已引用 code 静默删除。

## 下一任务拆分与运维检查

立项任务至少拆为模型/迁移、只读 API、管理写入、缓存失效和前端生成 client 五步；上线后检查唯一键冲突、禁用项引用、缓存回源和跨租户查询告警。若只有一个消费者，继续由业务模块维护，不创建通用枚举中心。

## 发布与回滚

按“表和数据、只读 API、管理写入、前端消费”顺序灰度发布；回滚关闭管理写入或新客户端，不删除仍被业务引用的 code 和历史审计。
