# prod：服务通信

## 决策与启动门槛

`defer`。只有出现第二个独立服务和真实跨服务调用需求才创建任务。前置是服务身份、网络边界、调用方责任、超时预算、版本兼容和跨服务审计方案。

## 目标与非目标

登记受控服务端点、执行固定动作调用并查询调用链。非目标是为单体内部调用增加管理后台、允许任意 URL/方法/脚本，或用链路图替代领域监控。

## 契约与安全

每个端点有稳定 service_id、环境、协议、版本、健康策略和 owner；动作有固定输入/输出 schema、认证方式、超时和重试策略。端点、证书和 Secret 由服务端治理；前端只展示脱敏元数据。出站 URL 经过 allowlist/SSRF 策略，跨租户查询严格隔离。

## 配置与凭据

端点地址、超时预算、证书和 Secret 引用按环境配置，凭据不得进入前端、任务载荷或日志；配置变更需要 owner 审批、版本记录和可回滚的兼容窗口。

## 幂等、失败与观测

写操作必须由调用方提供幂等键或服务端声明不可重试；仅对明确瞬时错误退避，避免级联重试。记录调用、attempt、状态码/错误类别、耗时和 trace，不记录凭据与完整业务载荷。告警覆盖超时、失败率、熔断、证书即将过期和链路积压。

## 迁移、测试、发布与回滚

先以一个固定动作和测试端点验证契约，再扩大端点管理；版本通过兼容窗口和 contract test 演进。验收覆盖认证失败、权限、超时、重试、重复写、服务不可用、租户隔离和脱敏。回滚禁用新端点/动作并保留调用记录，不回滚已发生的远端副作用。

## 启动门槛、后续拆分与运维检查

只有第二个独立服务、owner、身份认证和固定动作契约确认后才建独立任务；任务至少拆为端点注册、身份/凭据、固定动作 Adapter、调用尝试和链路查询。运维检查超时、失败率、熔断、证书期限和 Trace 断链；单体阶段禁止创建服务通信后台或任意 URL 调用。
