# 前端开发规范

## 1. 目的与适用范围

本规范用于指导当前仓库 `frontend/` 的后续开发、评审与 AI 协作。

- 适用范围：`frontend/src/**` 下的业务代码、路由、页面、hooks、共享组件与测试。
- 不适用范围：生成代码与受上游工具管理的文件。
- 如果是常规 CRUD 页面，除本文外还应同时参照 [前端CRUD开发模板](D:/Workspace/full-stack-fastapi-template/docs/rules/前端CRUD开发模板.md)。
- 本文是当前仓库 React 开发、评审与 AI 协作的主规范；`docs/skills/**` 中的前端说明不得覆盖本文的项目化约束。

本文基于当前真实代码结构，核心前提是：前端已经进入 `app / platform / features / shared` 的边界演进阶段，新增代码必须顺着这个方向生长。

## 2. 技术栈基线

当前前端以如下组合为准：

- React 19 + TypeScript strict
- Vite 7
- TanStack Router（文件路由）
- TanStack Query（服务端状态）
- Tailwind CSS v4
- shadcn/ui + Radix UI
- React Hook Form + Zod
- Playwright
- Biome
- Bun

现有约定：

- 当前项目是前后端分离的 Vite SPA，不采用 Next.js、RSC 或 Server Components 作为默认开发模型。
- 构建和开发入口来自 `frontend/package.json`。
- 使用 `@/*` 指向 `frontend/src/*`。
- 使用文件路由与自动生成的 `routeTree.gen.ts`。

增强要求：

- 除特殊说明外，前端新增功能不得引入第二套路由、状态管理或 UI 基础框架。
- 对外 API 调用默认复用生成客户端与现有 query/mutation 模式。
- 常规 Vite SPA React 任务，优先参考 `react-best-practices`；`vercel-react-best-practices` 只作为补充参考。

## 3. 基础约束

### 3.1 禁改目录

以下目录或文件禁止手动修改：

- `frontend/src/client/**`
- `frontend/src/routeTree.gen.ts`
- `frontend/src/components/ui/**`

如果后端 OpenAPI 发生变化，应执行仓库根目录命令重新生成客户端：

```bash
bash ./scripts/generate-client.sh
```

### 3.2 开发命令

```bash
cd frontend
bun install
bun run dev
bun run build
bun run lint
bunx playwright test
```

增强要求：

- 提交前至少运行 `bun run lint`。
- 修改了路由结构、边界迁移、关键页面渲染逻辑、Query 行为或关键 CRUD 主路径时，应执行 `bun run build`。
- 影响路由、鉴权或关键 CRUD 路径时，应补充或回归 Playwright 测试。

## 4. 当前目录职责

### 4.1 顶层分层

当前前端目录按以下职责理解：

- `src/app/`
  - 应用壳、全局导航、头尾布局、路由守卫
- `src/platform/`
  - 跨业务平台能力，如 `auth`、`system`、`docs`
- `src/features/`
  - 具体业务功能，如 `items`
- `src/shared/`
  - 真正共享的跨域组件、hooks、permissions、utils
- `src/routes/`
  - 薄路由文件，只做路由注册、guard、metadata、页面接线
- `src/hooks/`
  - 现有应用级 hooks，例如 `useAuth`
- `src/client/`
  - OpenAPI 生成客户端

### 4.2 强约束

- 不再把 `src/routes/` 当成完整页面实现目录。
- 不再把 `src/components/` 当成默认业务承载层。
- 不再新增 `components/Common/*` 式平铺共享目录。
- 新页面、新业务组件优先落到 `platform/*` 或 `features/*`，共享后再上升到 `shared/*`。

## 5. 路由、页面与鉴权

现有约定：

- 使用 TanStack 文件路由。
- 页面标题通过 `head()` 定义。
- 鉴权守卫放在路由的 `beforeLoad` 中。
- 受保护布局由 `routes/_layout.tsx` 接到 `app/layout/AppLayout.tsx`。

增强要求：

- 路由文件应保持薄封装，只负责：
  - 定义 `Route`
  - 配置 `head()`
  - 接入 `beforeLoad`
  - 引用真实页面模块
- 新增需要登录态的页面，优先挂载在已有受保护布局下；不要在组件内部临时做登录跳转。
- 页面实现优先进入：
  - `platform/*/pages`
  - `features/*/pages`
- 应用壳与全局框架能力进入：
  - `app/layout/*`
  - `app/navigation/*`
  - `app/router/*`

当前真实示例：

- `routes/login.tsx` -> `platform/auth/pages/LoginPage.tsx`
- `routes/_layout.tsx` -> `app/layout/AppLayout.tsx`
- `routes/_layout/admin.tsx` -> `platform/system/pages/AdminUsersPage.tsx`
- `routes/_layout/items.tsx` -> `features/items/pages/ItemsPage.tsx`

## 6. 组件分层与导入规则

### 6.1 组件应放在哪里

- `components/ui/*`
  - 设计系统基础原件，只能消费，不能随意改
- `platform/*/components/*`
  - 平台域内部组件
- `features/*/components/*`
  - 业务域内部组件
- `shared/components/*`
  - 真正跨域复用的共享 UI

### 6.2 共享组件规则

共享组件优先按分组目录导入，例如：

- `@/shared/components/branding`
- `@/shared/components/feedback`
- `@/shared/components/layout`
- `@/shared/components/table`
- `@/shared/components/theme`

不要：

- 新增 `components/Common/*`
- 继续深度依赖旧的平铺公共目录
- 把业务专属 UI 直接塞进 `shared/components/*`

### 6.3 权限与导航规则

- 侧边栏与菜单装配集中在 `app/navigation/*`
- 路由守卫集中在 `app/router/guards.ts`
- 菜单权限判断集中在 `shared/permissions/*`

不要在页面组件里散落长期权限逻辑。

## 7. 命名、导入与 Bundle 约束

现有约定：

- 组件文件使用 `PascalCase`
- hooks 使用 `useXxx.ts`
- 路由文件遵循 TanStack Router 约定
- 字符串使用双引号，分号遵从 Biome

增强要求：

- `src` 内跨目录导入默认使用 `@/` 别名。
- 类型导入优先使用 `import { type Foo } from "..."`。
- hooks 名称必须以 `use` 开头。
- 组件名称必须与导出语义一致，避免缩写和含糊命名。
- 对重型依赖、重型页面区块或大弹窗内容，优先做延后加载或代码分割。
- 不要为了图省事重新引入跨大目录的“万能 barrel”依赖方式，尤其不要用它取代现有分组 shared barrel。

## 8. TypeScript 与 React 编码约定

现有约定：

- `tsconfig.json` 开启 `strict`、`noUnusedLocals`、`noUnusedParameters`
- 项目全部使用函数组件和 Hooks
- Provider 与全局能力在 `main.tsx` 统一注入

增强要求：

- 新代码优先使用显式类型和推导结合的方式。
- 衍生状态优先通过表达式、查询结果或表单状态直接计算，不额外创建冗余 state。
- 纯数据推导不要放进 `useEffect`。
- 对 expensive initial value 使用 `useState(() => initialValue)`。
- 不要为了普通事件处理器滥用 `useCallback`。
- 当回调主要被 effect 内的订阅、计时器或监听器消费时，优先使用 React 19 的 `useEffectEvent`。
- 对频繁但非紧急的更新，可使用 `startTransition` 保持交互响应。
- 仅在存在可测量收益时使用 `useMemo` / `useCallback`。

## 9. 数据获取、Query 与 Waterfall 控制

现有约定：

- API 调用通过 `src/client/**` 生成客户端完成。
- 服务端状态使用 TanStack Query。
- 页面或 hooks 中使用 `useQuery`、`useSuspenseQuery`、`useMutation`。
- query key 使用数组形式，例如 `["items"]`、`["currentUser"]`。

增强要求：

- 新增接口调用不得绕过生成客户端直接拼接 URL，除非生成客户端无法表达。
- 服务端数据默认交给 TanStack Query 管理，不使用 `useEffect + fetch + useState` 重新手搓请求生命周期。
- 查询参数与 mutation 函数尽量靠近业务域，可复用时提取为页面或域内 helper。
- mutation 成功后应根据影响范围精确失效相关 query。
- 互相独立的异步操作必须并行启动，优先使用 `Promise.all()`。
- 配置、字典、当前用户等共享数据优先复用已有 query key 和缓存。
- 页面 JSX 中不要直接编写请求细节。

## 10. 表单规范

现有约定：

- 表单统一采用 `react-hook-form + zod + zodResolver`
- 默认值通过 `defaultValues` 声明
- 表单字段优先复用 `components/ui/form`、`input`、`password-input`、`loading-button`

增强要求：

- 新表单默认必须定义 Zod schema，类型从 schema 推导。
- 提交事件必须处理重复提交。
- 表单成功后要明确后续动作：关闭弹窗、重置、跳转或刷新。
- 必填项、校验错误与提交中状态必须有可见反馈。
- 搜索、筛选或本地过滤等非紧急联动，可考虑 `startTransition`。

## 11. UI、样式与渲染性能

现有约定：

- 基础 UI 组件来自 `components/ui/**`
- 样式以 Tailwind 原子类为主
- 全局主题 token 与亮暗色变量定义在 `src/index.css`

增强要求：

- 新增业务界面优先复用现有 `components/ui` 与 `shared/components/*`，不要平行造一套按钮、表单、表格或弹窗。
- 表格、错误页、空态、页脚、主题切换等跨域 UI，优先复用 `shared/components/*` 分组入口。
- 样式优先通过现有 token、语义色和 Tailwind 类组合表达。
- 不要机械禁止所有 arbitrary values，但应避免无明确理由的零散视觉补丁。
- 复杂视觉结构优先抽成小展示组件。
- 非关键第三方 UI 能力应在用户触发后再加载。

## 12. 加载态、空态、错误态

现有约定：

- 根路由已经接入共享 `ErrorState` 与 `NotFoundState`
- 列表页面使用 `Suspense + Pending...` 组件承接加载态

增强要求：

- 新增页面必须至少覆盖：
  - 加载态
  - 空态
  - 错误态
- 空态优先给出下一步动作，例如“新增”“返回”或“刷新”。
- 错误提示面向用户描述结果，不直接暴露原始异常对象。
- 当页面包含多个独立数据区块时，加载态应尽量局部化。

## 13. Hooks、状态边界与 Effect 使用

现有约定：

- 鉴权、toast、复制等横切逻辑已抽为 hooks
- 本地交互状态使用组件内 `useState`

增强要求：

- 单组件临时 UI 状态放本地 state。
- 跨页面共享且来自服务端的数据优先交给 Query 管理。
- 可复用副作用流程优先抽为 hook。
- effect 内如果只是为了调用 render 变化函数，不要通过层层 `useCallback` 强行维持稳定引用；优先考虑 `useEffectEvent`。
- 不要在 effect 中重复做可在 render 阶段完成的排序、过滤、拼接或派生布尔值计算。

## 14. 测试、构建与联调规范

现有约定：

- 当前前端自动化测试以 Playwright 为主
- `bun run build` 会先做 TypeScript 构建检查再执行 Vite build
- `bun run lint` 由 Biome 执行检查与格式修复

增强要求：

- 新增关键流程至少考虑以下覆盖点：
  - 登录/退出或鉴权跳转
  - 列表加载、空态、错误态
  - 创建/编辑/删除主路径反馈
  - 表单校验与禁止重复提交
- 如本次改动影响 OpenAPI schema，必须重新生成 client 并验证构建通过。
- 后端接口字段、必填项或错误结构变化时，前端改动应以重新生成后的 client 类型为准。
- 对接口变更敏感页面，至少执行一次本地联调或构建校验。

## 15. 开发自检清单

提交前至少检查以下内容：

- 是否误改了生成文件或 `components/ui`
- 是否仍按 `app / platform / features / shared` 边界放置代码
- 是否把完整页面实现错误地放回 `routes/*`
- 是否引入了新的 `components/Common/*` 式平铺公共目录
- 是否通过 query/mutation 调用生成客户端，而不是手写请求
- 是否为新增页面补齐加载态、空态、错误态
- 是否运行了 `bun run lint`
- 涉及关键路径或边界迁移时，是否执行了 `bun run build`
