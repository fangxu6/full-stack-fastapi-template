# 数据库设计规范

## 表命名规范
- 表名格式：主模块_次级模块_业务名称_后缀
- 主从结构主表后缀：Master
- 主从结构从表后缀：Detail
- 类型关联表后缀：Relation
- 主从表写入同一文件时，文件名使用后缀：MasterDetail

## 字段规范
- 字段命名遵循Pascal命名法
- 独立"ID"使用大写形式（如UserID、RoleID）
- 禁止使用数据库保留字作为字段名
- 主键ID不使用默认值
- 自引用结构统一使用ParentID作为上级节点字段名

## 枚举型数据规则
### 简单枚举量
- 适用于通用的、简单的枚举值
- 字段类型使用TINYINT
- 注释中标明来源：`来源：字典表`

### 业务枚举值
- 适用于复杂业务值
- 统一使用通用枚举表（Common_Enum）
- 注释中标明来源：`来源：通用枚举表[分类编码]`

## 字段类型规范
### UUID字段
- 统一使用BINARY(16)存储
- 应用程序层负责格式转换

### 布尔类型字段
- 数据库存储使用BIT(1)类型
- 命名以Is或Has开头（如IsDeleted、HasPermission）
- 必须明确设置默认值

### 启用字段规范
- 所有系统表的启用状态字段统一使用 **IsEnabled** 作为字段名
- 字段类型：BIT(1)
- 默认值：1（启用）
- 含义：1表示启用，0表示禁用
- 禁止使用其他相似字段名如IsActive、IsValid、IsOpen等，避免字段命名混乱

### 单据类表固定字段
- 主表必须包含：主业务名ID(主键)、CreateTime、CreatorID、UpdateTime、UpdaterID、IsDeleted
- 从表必须包含：从表业务名ID(主键)、主业务名ID、IsDeleted

## 关系设计说明
- 禁止使用外键约束，数据完整性与关联关系由后端逻辑保证

## 建表SQL规范
- 使用CREATE TABLE IF NOT EXISTS语法
- 明确指定引擎：ENGINE=InnoDB DEFAULT CHARSET=utf8mb4
- 包含完整字段注释和表注释
- 通常不包含外键约束定义


## 数据字典格式规范

### 表基本信息
- 中文表名：数据表的中文名称
- 表名：数据表的物理名称
- 描述：表的详细业务描述
- 主键：表的主键字段名
- 关联字段：用于关联其他表的字段名

### 表结构
使用表格形式展示：
- 表名、存储引擎、字符集、备注

### 字段明细
使用表格形式详细描述每个字段：
- 字段名、字段类型、长度、可空、默认值、键、示例值、描述、备注

### 索引
使用表格形式描述所有索引：
- 索引名、索引类型、索引字段、描述

### 索引命名规范
- 所有索引名称必须以"Index"结尾
- 示例：IX_Sys_FTP_Config_HostIndex

### 建表SQL
提供完整的建表SQL语句，包含：
- 字段定义（名称、类型、长度、约束、注释）
- 主键约束
- 索引定义
- 表注释
- 存储引擎和字符集设置

### 枚举字段注释规范
- 简单枚举量：`字段描述(1:枚举1,2:枚举2) | 来源：字典表`
- 业务枚举值：`字段描述(1:枚举1,2:枚举2) | 来源：通用枚举表[分类编码]`
