# Backend Refactor Context (2026-03-05)

## 背景
- `backend/` 在重构前存在模块边界不清的问题：路由层承担了部分业务编排职责，依赖注入集中在单文件，模型与接口 DTO 边界不够明确。
- 随着用户、鉴权、条目等功能增长，继续在现有结构上迭代会增加维护成本与认知负担。

## 目标问题
- 建立稳定的分层边界：`Route -> Service -> CRUD -> Model`。
- 降低“改一个接口牵一片文件”的耦合风险。
- 让目录结构和开发规范一致，便于新人快速定位代码。

- 本文档是对 2026-03-05 已完成 backend 重构的追补 spec。
- 重点记录“已完成的设计意图、改动范围、验证策略”，用于后续演进和回归对照。
