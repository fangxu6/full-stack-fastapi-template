## 环境与工具

- 后端依赖使用 `uv` 管理，目录为 `backend/`。
- 前端依赖使用 `bun`（或 Node.js），目录为 `frontend/`。
- 本地全栈推荐 `docker compose watch`。

## 目录约定

- 后端入口：`backend/app/main.py`。
- 后端路由：`backend/app/api/routes/`。
- 模型定义：`backend/app/models.py`。
- CRUD 逻辑：`backend/app/crud.py`。
- 前端入口：`frontend/src/main.tsx`。
- 前端路由：`frontend/src/routes/`。

### 平台分层约定

- 后端横切治理能力放 `backend/app/core/*`
- 后端基础设施放 `backend/app/infra/*`
- 后端业务边界入口优先放 `backend/app/modules/*`
- 前端应用壳放 `frontend/src/app/*`
- 前端平台能力放 `frontend/src/platform/*`
- 前端业务功能放 `frontend/src/features/*`
- 前端共享能力放 `frontend/src/shared/*`

## 配置与安全

- 所有运行时配置统一从顶层 `.env` 读取。
- 禁止提交真实密钥，`changethis` 仅用于本地占位。
- 生产环境需设置 `SECRET_KEY`、`POSTGRES_PASSWORD`、`FIRST_SUPERUSER_PASSWORD`。

### 异常与可观测性

- 后端业务失败优先抛 `app.core.exceptions.AppError` 子类。
- 统一错误响应必须包含 `detail` 与 `request_id`。
- `401/404/422/500` 也应遵守统一错误结构。
- 未处理异常必须保留服务端 traceback，不能只返回通用 `500`。

## 数据库与迁移

- 使用 Alembic 生成迁移：`alembic revision --autogenerate -m "..."`。
- 应用迁移：`alembic upgrade head`。
- 初始化数据通过 `backend/app/initial_data.py` 创建首个超级用户。

## 前后端联动

- 后端 OpenAPI 变更后需重新生成客户端：`bash ./scripts/generate-client.sh`。
- 前端调用 API 时使用 `VITE_API_URL` 指向后端。

### 前端边界

- `routes/*` 保持轻量，优先只做路由声明和页面导入。
- 页面实现放 `platform/*/pages` 或 `features/*/pages`。
- 页面私有组件留在对应域的 `components/*`。
- 真正共享的组件再进入 `shared/components/*`。
- 共享组件优先按分组 barrel 导入，不再回到 `components/Common/*` 式平铺目录。

### 权限与导航

- 路由保护逻辑集中在 `app/router/guards.ts`。
- 导航结构集中在 `app/navigation/*`。
- 菜单权限判断入口集中在 `shared/permissions/*`。

## 测试与质量

- 后端测试：`bash ./scripts/test.sh`。
- 前端 E2E：`bunx playwright test`。
- 提交前可运行 `uv run prek run --all-files`。
- 预提交钩子会校验类型（mypy）并自动生成前端 SDK（如已配置）。

### 最低回归要求

- 后端新增异常分支时，至少补一条测试验证统一错误结构。
- 鉴权与参数校验相关改动，要覆盖 `401/403/422` 的返回契约。
- 前端新增页面或边界迁移时，要验证路由、权限、错误态或空态没有退化。
