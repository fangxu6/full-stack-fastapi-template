## 常见问题

### 1. 后端启动失败或一直等待数据库

- 确保数据库服务已启动：`docker compose watch`。
- 查看日志：`docker compose logs backend`。

### 2. 登录后仍然 401/403

- Token 可能过期或被清除，重新登录。
- 用户必须 `is_active=true`。
- 当前项目的错误响应应包含 `request_id`；如果没有，优先检查是否绕过了统一异常处理。

### 2.1 返回了 500，但日志里找不到堆栈

- 这是不符合当前平台基线的。
- 未处理异常应该同时：
  - 给前端返回 `request_id`
  - 在服务端日志里记录 traceback
- 先检查是否走到了 `backend/app/core/exceptions.py` 的统一异常处理。

### 3. 无法发送邮件

- 需要配置 `SMTP_HOST`、`SMTP_USER`、`SMTP_PASSWORD`、`EMAILS_FROM_EMAIL`。
- 本地开发默认使用 Mailcatcher，访问 `http://localhost:1080` 查看邮件。

### 4. 密码找回没有邮件

- 邮件能力未启用时不会发送。
- 该接口始终返回相同消息以防枚举邮箱。

### 5. 前端请求 API 失败或跨域

- 设置 `VITE_API_URL` 指向正确后端地址。
- 更新 `BACKEND_CORS_ORIGINS` 和 `FRONTEND_HOST`。

### 5.1 前端新增页面后结构越来越乱

- 检查是否把完整页面实现直接写进了 `routes/*.tsx`。
- 当前推荐做法：
  - 应用壳与导航放 `app/*`
  - 平台能力放 `platform/*`
  - 业务功能放 `features/*`
  - 共享能力放 `shared/*`

### 6. 私有接口 404

- `/private` 仅在 `ENVIRONMENT=local` 时启用。

### 7. 迁移未生效或表结构不一致

- 先生成迁移，再执行 `alembic upgrade head`。
- 若跳过迁移，需在 `backend/app/core/db.py` 中启用 `SQLModel.metadata.create_all`（不推荐）。

### 8. 前端类型/接口不匹配

- 后端 OpenAPI 变更后重新生成客户端：`bash ./scripts/generate-client.sh`。

### 9. 新增后端模块时不知道该放哪

- 横切治理能力放 `core/*`
- 基础设施放 `infra/*`
- 模块边界入口放 `modules/*`
- HTTP 路由放 `api/*`
- 具体业务逻辑当前优先落在 `services/*`

### 10. 为什么错误响应里一定要有 `request_id`

- 这是当前仓库排障基线。
- 前端报错、接口日志、后端 traceback 需要通过同一个 `request_id` 串起来。
- 没有这个字段，线上问题会明显更难排查。
