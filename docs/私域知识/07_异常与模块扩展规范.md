## 异常与模块扩展规范

### 适用范围

- 后端：`backend/app/**`
- 前端：`frontend/src/app/**`、`frontend/src/platform/**`、`frontend/src/features/**`、`frontend/src/shared/**`

## 一、后端异常基线

### 1. 统一错误响应结构

所有错误响应必须收口到统一 JSON：

```json
{
  "detail": "xxx",
  "request_id": "uuid"
}
```

覆盖范围包括：

- 业务异常 `AppError`
- 鉴权/权限异常
- 框架抛出的 `401/404`
- 请求参数校验 `422`
- 未处理异常 `500`

### 2. 业务代码如何抛错

优先使用 `app.core.exceptions` 中的异常类型：

- `AuthenticationError`
- `PermissionDeniedError`
- `BadRequestError`
- `ConflictError`
- `UserNotFoundError`
- `ItemNotFoundError`
- `RuleDocumentNotFoundError`

如果现有异常不够，再新增明确语义的 `AppError` 子类。

不要在服务层长期混用：

- 裸 `Exception`
- ad-hoc 字符串错误
- 到处散落的 `HTTPException`

### 3. 500 错误必须保留服务端堆栈

统一错误响应不等于吞掉异常。

未处理异常必须：

- 返回通用 `500`
- 返回 `request_id`
- 在服务端记录 traceback
- 日志至少带上 `request_id` 和请求路径

否则只能得到一个无法回查的错误编号。

### 4. Request ID 规则

- 请求进入应用后立即生成或透传 `X-Request-ID`
- 响应头回写 `X-Request-ID`
- 错误响应体中的 `request_id` 与响应头保持一致

这条规则是排查线上问题的基础契约。

## 二、日志规则

### 1. 什么情况必须记录日志

- 未处理异常
- 外部系统调用失败且需要排障
- 重要状态切换或关键业务动作

### 2. 日志应该包含什么

- `request_id`
- 资源标识或业务 ID
- 路径或动作名
- 失败原因

### 3. 不要做什么

- 不要用 `print`
- 不要吞掉异常后什么都不记
- 不要只记 `"error happened"` 这类无上下文日志

## 三、后端新增业务模块规范

### 1. 当前推荐接入方式

仓库当前处于平台化批次 0 阶段，新增业务建议按这个顺序接入：

1. 在 `backend/app/modules/<module>/` 建立模块目录
2. 增加模块路由聚合入口或模块内路由
3. 业务实现优先复用 `services/*` 与 `api/dependencies/*`
4. 错误统一接 `core/exceptions.py`
5. 测试至少覆盖成功、权限失败、资源不存在、参数错误

### 2. 判断放在哪一层

- 横切能力：放 `core/*`
- 基础设施：放 `infra/*`
- 业务模块边界：放 `modules/*`
- HTTP 入口：放 `api/*`
- 具体业务逻辑：当前优先放 `services/*`

### 3. 当前不要做的事

- 不要把所有新能力继续塞回单个 `crud.py`
- 不要在路由函数里堆完整业务逻辑
- 不要绕过统一异常体系直接返回临时错误结构

## 四、前端边界规则

### 1. 四层职责

- `app/*`：应用壳、导航、路由守卫
- `platform/*`：认证、系统管理、文档等平台能力
- `features/*`：业务功能
- `shared/*`：共享 UI、工具、hooks、权限判断

### 2. 典型放置方式

- 登录页：`platform/auth/pages/*`
- 用户管理页：`platform/system/pages/*`
- 条目业务页：`features/items/pages/*`
- 全局侧边栏：`app/navigation/*`
- 菜单权限函数：`shared/permissions/*`

### 3. 导入约束

- `routes/*` 作为薄封装，优先直接导入页面模块
- 共享组件优先按分组目录导入，如：
  - `@/shared/components/feedback`
  - `@/shared/components/layout`
  - `@/shared/components/theme`

### 4. 何时才能放进 shared

满足以下条件再进入 `shared/*`：

- 被多个页面或多个业务域复用
- 不携带特定业务上下文
- 不绑定具体页面流程

否则应留在 `platform/*` 或 `features/*`。
