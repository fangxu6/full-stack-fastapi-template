## 业务逻辑公式手册

### 关键结论

- ✅ 规则明确，核心围绕鉴权、权限与数据归属。
- ⚠️ 业务计算较少，更多是校验与权限规则。

### 计算公式

- Access Token 过期时间：
  - `expire_at = now_utc + ACCESS_TOKEN_EXPIRE_MINUTES`
- 密码重置 Token 过期时间：
  - `expire_at = now_utc + EMAIL_RESET_TOKEN_EXPIRE_HOURS`
- CORS 允许来源：
  - `all_cors_origins = BACKEND_CORS_ORIGINS + FRONTEND_HOST`

### 校验规则

- 登录：用户必须存在且 `is_active=true`。
- 注册：邮箱必须唯一。
- 更新密码：新旧密码不可相同。
- 删除用户：超级管理员不可删除自己。
- 条目访问：普通用户仅能访问 `owner_id == 当前用户` 的条目。

### 业务规则映射（代码来源）

| 规则 | 代码位置 |
| --- | --- |
| 登录鉴权与 token 生成 | `backend/app/api/routes/login.py`、`backend/app/core/security.py` |
| 用户权限校验 | `backend/app/api/deps.py` |
| 用户唯一性校验 | `backend/app/api/routes/users.py` |
| 条目归属校验 | `backend/app/api/routes/items.py` |
| 密码找回与重置 | `backend/app/api/routes/login.py`、`backend/app/utils.py` |
| 默认密钥校验 | `backend/app/core/config.py` |

### 隐式决策点清单（if 条件）

- 用户不存在时仍执行密码校验（防计时攻击）。
- 密码找回始终返回统一消息（防邮箱枚举）。
- `ENVIRONMENT != local` 时强制密钥校验失败即抛错。

## 文档维护规范

### 增量更新规则

- 新规则：新增到“校验规则”或“业务规则映射”。
- 规则变更：更新公式/规则文本，并补充影响范围。
- 隐式规则：必须记录触发条件与风险。

### 统一格式

- 规则表：`| 规则 | 代码位置 |`
- 决策点：使用 `if/else` 条件描述并标注影响。
