## 开发规范与最佳实践

### 关键结论

- ✅ 分层清晰：API 路由、CRUD、模型、配置分离。
- ✅ 依赖注入明确：FastAPI `Depends` 统一处理认证与数据库会话。
- ⚠️ 业务扩展需先定义领域模型，避免 `Item` 演示实体滥用。

### 设计模式与结构

- 分层架构：`routes` → `crud` → `models/db`。
- 依赖注入：`api/deps.py` 统一认证与数据库会话。
- 配置集中：`core/config.py` 通过 `.env` 加载。
- 数据迁移：Alembic 作为唯一结构变更入口。

### 最佳实践

- 后端开发使用 `uv` 管理依赖并保持虚拟环境一致。
- 前端开发使用 `bun`，本地开发优先 `bun run dev`。
- OpenAPI 变更后，必须重新生成前端 SDK。
- 生产环境强制替换 `changethis` 类型的默认密钥。
- 提交前运行 `prek`，保证格式与类型一致。

### 常见陷阱

- 忘记设置 `VITE_API_URL` 导致前端请求失败。
- `ENVIRONMENT` 设为非 `local` 时未更新 `SECRET_KEY` 导致启动失败。
- 数据库迁移未执行导致模型与表不一致。

### 代码组织建议

- 新业务优先新增独立实体模型，再补充 CRUD 与 API。
- 权限规则集中在 `deps.py` 与路由层，避免散落。
- 邮件与外部服务逻辑集中在 `utils.py`。
