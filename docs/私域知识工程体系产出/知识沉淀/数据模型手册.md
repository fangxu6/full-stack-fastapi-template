## 数据模型使用手册

### 关键结论

- ✅ 模型结构清晰，用户与条目为核心实体。
- ⚠️ `Item` 为模板演示实体，业务含义待确认。

### 领域实体模型

#### User

- 用途：系统用户、权限主体。
- 关键属性：
  - `id`: UUID 主键。
  - `email`: 唯一邮箱。
  - `hashed_password`: 密码哈希。
  - `is_active`: 是否启用。
  - `is_superuser`: 超级管理员标记。
  - `full_name`: 可选姓名。
  - `created_at`: 创建时间（UTC）。
- 业务关系：一个用户拥有多个 `Item`。

#### Item

- 用途：通用条目实体（需结合业务定义）。
- 关键属性：
  - `id`: UUID 主键。
  - `title`: 标题（必填）。
  - `description`: 描述（可选）。
  - `owner_id`: 外键，关联 `User.id`。
  - `created_at`: 创建时间（UTC）。
- 业务关系：每个条目隶属一个 `User`。

### API 传输模型

#### 用户相关

- `UserCreate`: 创建用户（含密码）。
- `UserRegister`: 开放注册模型。
- `UserUpdate`: 管理员更新模型（字段可选）。
- `UserUpdateMe`: 用户自更新模型。
- `UserPublic`: 对外展示模型。
- `UsersPublic`: 列表 + 总数。
- `UpdatePassword`: 修改密码模型。

#### 条目相关

- `ItemCreate`: 创建条目。
- `ItemUpdate`: 更新条目。
- `ItemPublic`: 条目展示。
- `ItemsPublic`: 列表 + 总数。

#### 认证相关

- `Token`: JWT 访问令牌。
- `TokenPayload`: JWT 载荷。
- `NewPassword`: 重置密码模型。
- `Message`: 通用消息模型。

### 约束与校验

- 邮箱格式由 `EmailStr` 校验。
- 密码长度：8-128。
- `title` 最短长度为 1。
- `created_at` 统一 UTC。
